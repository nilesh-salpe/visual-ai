Training LLMs for tool use and agency

How models learn to call tools, recover from errors and finish long tasks: synthetic tool-use trajectories for fine-tuning, then reinforcement learning in environments with checkable rewards.

What is the problem?Multi-step tool use is rare in pretraining text. Untrained models call the wrong API (application programming interface), invent arguments, stop after one step or never recover from an error. Kimi K2's report: agentic capabilities such as multi-step reasoning, long-term planning and tool use "are rare in natural data and costly to scale".
Core ideaTwo stages. Supervised fine-tuning on tool-use trajectories, mostly synthesised: real and generated tool specs, generated tasks with rubrics, simulated or real environments, and a judge that filters the results. Then reinforcement learning with rewards you can check (tests pass, final state correct), plus rubric or self-critique rewards for open-ended tasks.

1 · Problem

Agency is missing from the training data

Wrong calls

Gorilla's starting point: even GPT-4 generated inaccurate API arguments and hallucinated API usage.

Short horizons

Chat data rewards one good reply, not a 50-step task that ends in the right state.

No recovery

Models rarely see examples of reading an error and changing course.

2 · Core idea

Synthesise trajectories, then reinforce outcomes

Self-labelled calls

Toolformer: the model inserts candidate API calls into text and keeps those that make the next tokens more likely.

Fine-tuning on APIs

Gorilla fine-tunes on API documentation with a retriever; ToolLLM builds ToolBench from 16,464 real REST (representational state transfer) APIs with ChatGPT-generated instructions and depth-first-search solution paths.

Pipelines at scale

Kimi K2: 3,000+ real MCP (Model Context Protocol) tools and 20,000+ synthetic tools, thousands of generated agents, tasks with explicit rubrics, simulated multi-turn trajectories filtered by an LLM (large language model) judge, plus real sandboxes for code.

RL on outcomes

SWE-RL (SWE = software engineering) rewards similarity to the real fix on GitHub history and reaches 41.0% on SWE-bench Verified with a 70B model; RL (reinforcement learning) also improved out-of-domain tasks where an SFT (supervised fine-tuning) baseline got worse.

5 · Trade-offs

Trade-offs

Choice Benefit Cost
Real APIs and sandboxes faithful feedback slow, flaky, expensive to scale and reset
Simulated tools and users cheap, unlimited, controllable simulation gap: the model learns the simulator
SFT only stable and simple imitates the generator's mistakes; weak at recovery
RL on outcomes learns recovery and long-horizon strategy needs environments, verifiers and lots of compute
Distil from a stronger agent fast way to a capable small model capped by the teacher; licence limits on outputs
6 · Failure modes

Failure modes

Failure Symptom Mitigation
Reward hacking model deletes failing tests or special-cases checks hidden tests, protected files, review of high-reward episodes
Overfitting to tool formats great on the benchmark's tools, poor on new ones held-out tools and APIs (ToolLLM tested unseen APIs and APIBench)
Credit assignment one reward for 50 steps learns slowly shorter tasks first, intermediate checks, curricula of moderate difficulty
Forgetting general skills chat and reasoning regress after agent tuning mixed data; RL rather than narrow SFT (SWE-RL's finding)
Unsafe habits learns to take destructive shortcuts safety tasks and penalties in the gym
7 · Challenges in production

In production

Environment infrastructure

Thousands of isolated sandboxes that start fast, reset cleanly and log everything.

Evaluation beyond the gym

Track agent benchmarks (SWE-bench Verified, τ-bench) and your own tasks, with pass^k for consistency.

Data provenance

Know which trajectories came from which generator and environment version.

Fine-tune or prompt?

For most applications, tool descriptions and examples beat training; fine-tune when volume justifies a smaller specialised model.

Further reading

Key papers

The primary sources behind this deck, each with what it contributed. Links go to the paper (arXiv or the conference page).

Toolformer: Language Models Can Teach Themselves to Use Tools
Schick et al. · NeurIPS 2023

A model trained self-supervised to decide which APIs to call, when, and with what arguments (calculator, search, QA, translation, calendar).

Gorilla: Large Language Model Connected with Massive APIs
Patil et al. · NeurIPS 2024

A LLaMA model fine-tuned to write API calls, trained with retrieved API documentation so it adapts to documentation changes at test time; APIBench evaluation.

ToolLLM: Facilitating Large Language Models to Master 16000+ Real-world APIs
Qin et al. · ICLR 2024

ToolBench: 16,464 real REST APIs in 49 categories, instructions and solution paths generated by ChatGPT with a depth-first decision-tree search; ToolLLaMA generalises to unseen APIs.

Kimi K2: Open Agentic Intelligence
Kimi Team · arXiv 2025

Agentic post-training: a synthesis pipeline (tool specs → agents and rubric-graded tasks → multi-turn trajectories filtered by a judge, plus real sandboxes for code) and joint RL with verifiable rewards and a self-critique rubric reward.

Remember: 3,000+ real MCP tools and 20,000+ synthetic tools; 65.8 on SWE-bench Verified, 66.1 on Tau2-Bench
SWE-RL: Advancing LLM Reasoning via Reinforcement Learning on Open Software Evolution
Wei et al. · arXiv 2025

RL on software-evolution data (issues, pull requests, code changes) with a rule-based reward (similarity to the real patch); RL improved out-of-domain skills where an SFT baseline degraded them.

Remember: Llama3-SWE-RL-70B solves 41.0% of SWE-bench Verified
DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning
DeepSeek-AI · arXiv 2025

R1-Zero: RL with rule-based accuracy and format rewards directly on a base model; R1 adds cold-start data and a multi-stage pipeline.

Remember: AIME (American Invitational Mathematics Examination) 2024 pass@1 15.6% → 77.9% (R1-Zero)
