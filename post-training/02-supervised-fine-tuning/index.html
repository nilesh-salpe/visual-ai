Post-training · 02

Supervised fine-tuning (SFT)

The first post-training step: chat templates, training only on the assistant's tokens, packing, and why a few thousand high-quality examples beat a million mediocre ones.

What is the problem?A base model has no notion of "user" and "assistant", doesn't know when an answer ends, and imitates whatever style its prompt resembles.
Core ideaFine-tune on demonstrations rendered with a chat template, using ordinary next-token loss but only on the assistant's tokens (including its end-of-turn token). Pack examples to avoid wasting compute on padding.
1 · Problem

One conversation, one token sequence

A chat model sees a single flat sequence. The template inserts role markers and end-of-turn tokens. Colour shows what the loss is computed on. Toggle to compare training on everything vs only the assistant's answers.

Illustrative template with generic role tokens. Real models define their own (each tokenizer's chat template), but the structure is the same.

2 · Limitation

What a base model gets wrong

No turn structure

It has never seen consistent role markers, so it may keep writing the user's next message, or invent a whole dialogue.

No stopping point

It doesn't know an answer is finished. Without a trained end-of-turn token it rambles until the length limit.

Style follows the prompt

Ask casually and you get forum-style text; ask formally and you get a paper. SFT (supervised fine-tuning) pins down one consistent assistant style.

3 · Your turn

Which tokens should be trained?

Pick an answer before moving on. Committing to a guess, even a wrong one, makes the real answer stick.

In a two-turn chat (system, user, assistant, user, assistant), where should the SFT loss be computed?

C. The model should learn to produce answers and to stop, not to predict what users type. Llama 2: "we zero-out the loss on tokens from the user prompt, so as a result, we backpropagate only on answer tokens." Earlier assistant turns are valid targets too.
4 · Core idea

SFT in one paragraph

Render

Messages → template → token ids, plus a mask marking the assistant's content and closing end-of-turn token as trainable.

Shift and mask

Inputs = tokens[:-1], labels = tokens[1:]. Set untrained labels to −100, the value standard cross-entropy implementations ignore.

Train

Average next-token loss over trained positions only. Small learning rate (Llama 2: 2×10⁻⁵), few epochs (Llama 2: 2), sequences up to 4,096 tokens.

Epochs and overfitting

InstructGPT found its SFT models "overfit on validation loss after 1 epoch", yet "training for more epochs helps both the RM (reward model) score and human preference ratings, despite this overfitting". Validation loss on demonstrations is not the goal; behaviour is. That is one reason labs judge SFT checkpoints with preference models and evals rather than perplexity.

At a glance

Ordinary next-token training, applied only to what the assistant should produce.

5 · How it works

Packing: stop paying for padding

20 examples of random length go into rows of 2,048 tokens. With one example per row, everything is padded to the longest example. Packing fills each row with whole examples, in order, and pads only the tail.

Packing needs a document mask

Llama 2: "we concatenate all the prompts and answers from the training set", with a special token separating segments. Without a document mask (or position resets), tokens in one example can attend to the previous, unrelated example in the same row. See Architecture deck 06.

5 · How it works

Quality beats quantity

Llama 2: "Quality Is All You Need"

Meta found third-party SFT data had "insufficient diversity and quality". They collected their own and stopped at 27,540 annotations: a small set of high-quality examples beat millions of mediocre ones.

InstructGPT: ~13k prompts

Written by a vetted team of labelers, covering generation, open QA, brainstorming, chat, rewriting, summarization and more.

What makes data good

Correct, consistent in format and style, diverse in task, and at the difficulty you want the model to reach. Errors in demonstrations are imitated faithfully.

Synthetic data

Modern recipes generate candidate answers with models and keep the best (rejection sampling, deck 07). Llama 3's SFT data combines human-collected prompts with rejection-sampled model responses, plus targeted synthetic data.

5 · How it works

Worked example: what fraction of a chat is trained on?

The 2-turn chat in notebook 01: system prompt, two user turns, two short assistant answers (toy word-level tokenizer).

Worked example

  1. Rendered sequence: 29 tokens (bos, role tokens, content, end-of-turn markers).
  2. Trained tokens: the two answers plus their end-of-turn tokens = 8 tokens (28%).
  3. Loss = mean of −log p over those 8 positions only; the other 21 are labels of −100.
  4. Packing 2,000 examples of 20–399 tokens: one example per row → 54% real tokens; packed into 2,048-token rows → 93%.
Most positions in a chat are context, not targets. Masking keeps the loss focused, and packing keeps the GPU (graphics processing unit) busy.
6 · Why it works

Why SFT comes first

It makes RL feasible

RL (reinforcement learning) and preference methods learn from the model's own samples. If the model can't produce a sensible answer at all, there is nothing to compare or reward. SFT puts it in the right region.

It defines the reference

The SFT model is the reference policy for the KL (Kullback-Leibler divergence) penalty (PPO (Proximal Policy Optimization)) and for DPO (Direct Preference Optimization)'s log-ratios. Later stages stay close to it.

Cheap and stable

Plain supervised learning: no sampling, no reward model, one model in memory, and with LoRA (Low-Rank Adaptation) it fits on modest hardware (deck 03).

But it only imitates

It can't exceed its demonstrations or learn from comparisons, and it gives no signal on which of two plausible answers is better.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Training on the whole conversation is just as good."

Then the model spends capacity predicting user messages, and the loss is diluted by tokens you never want it to generate. Standard practice (Llama 2) masks prompt tokens.

"More SFT data is always better."

Llama 2 got better results from 27,540 carefully collected examples than from millions of third-party ones. Bad examples are imitated too.

"Lowest validation loss is the best SFT checkpoint."

InstructGPT trained past the validation-loss minimum because reward-model scores and human preferences kept improving.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Train the end-of-turn token. Otherwise the model never learns to stop.
  • Average over trained tokens only. Averaging over all positions shrinks the effective learning rate.
  • Pack + document mask. Llama 2 concatenated prompts and answers to fill 4,096-token rows.

⚠ Traps

  • Training on user turns. Wastes capacity predicting what users type.
  • More data at any quality. Llama 2 preferred 27,540 high-quality examples to millions of third-party ones.
  • Picking checkpoints by validation loss. InstructGPT kept training past the minimum because preference scores improved.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

Which label value tells a standard cross-entropy loss to skip a position?

−100 (PyTorch's default ignore_index).

Why must the assistant's end-of-turn token be trained?

Otherwise the model never learns when to stop. It would keep generating past the end of the answer, often inventing the next user turn.

What does packing save, and what extra mechanism does it need?

It removes padding, so nearly every position is a real token. It needs a document mask (or position resets) so packed examples don't attend to each other.
9 · Key takeaway

Key takeaway

SFT is next-token training on demonstrations, rendered with a chat template and with the loss only on the assistant's tokens, using fewer but better examples.
Say it in 30 seconds

Supervised fine-tuning is the first post-training step. Each conversation is rendered with a chat template into one token sequence, and the model is trained with ordinary next-token loss, but only on the assistant's tokens and its end-of-turn token, so it learns to answer and to stop rather than to predict users. Examples are packed into full-length rows with a document mask to avoid wasted padding. Quality matters more than quantity: Llama 2 stopped at about 27,500 carefully collected examples. SFT teaches format and style and gives the later preference stages a sensible starting point and reference model.

Problem: base models don't follow turns, don't stop, and mimic the prompt's style.
Core idea: chat template + loss on assistant tokens only (+ end-of-turn).
Practice: pack with a document mask; a small, high-quality dataset; judge by behaviour, not validation loss.
