Post-training · 08

RL with verifiable rewards and GRPO

How reasoning models are trained: replace the learned reward model with a checker, replace the critic with a group of samples, and let RL (reinforcement learning) discover long chains of thought.

What is the problem?Learned reward models can be gamed and PPO (Proximal Policy Optimization)'s critic costs a whole extra model. For maths and code, correctness can often be checked exactly, so why approximate it?
Core ideaRLVR (reinforcement learning with verifiable rewards): reward = 1 if a checker accepts the answer (plus format rules). GRPO (Group Relative Policy Optimization): sample a group of G answers per prompt and use (r − mean)/std within the group as each answer's advantage, so no value model is needed.
1 · Problem

Some answers can simply be checked

Maths

The final answer, in a required format (for example inside a box), is compared with the reference solution. DeepSeek-R1 calls this an accuracy reward.

Code

Run the program against test cases; reward the pass rate or all-pass.

Format and constraints

Did the model put its reasoning between the required tags, answer in the requested language, follow length limits? R1's format reward checks the thinking tags.

Why this matters

A learned reward model is a proxy with blind spots (deck 06). A checker is exact for what it checks, so there is far less to exploit. Tülu 3 named the approach Reinforcement Learning with Verifiable Rewards (RLVR); DeepSeek-R1-Zero used rule-based rewards for maths, coding and logic and no neural reward model for them.

2 · Limitation

What PPO-style RLHF costs here

A critic as big as the policy

PPO's value model is usually the same size as the policy, with its own gradients and optimizer state.

Critics are hard for long outputs

Predicting the expected final reward at every token of a long chain of thought is a hard regression problem, and a bad critic gives bad advantages.

Reward models drift

A learned RM goes stale and can be hacked; maths answers don't have that problem.

3 · Your turn

Compute group advantages

Pick an answer before moving on. Committing to a guess, even a wrong one, makes the real answer stick.

GRPO samples a group of 4 answers to one maths question. Rewards are [1, 0, 0, 1]. What are the advantages?

C. mean = 0.5, std = 0.5, so Â = (r − 0.5)/0.5 = [1, −1, −1, 1]. Every token of a correct answer is pushed up, every token of a wrong one pushed down, relative to this group.
4 · Core idea

GRPO in one picture

Sample a group

For each question, sample G outputs {o₁ … o_G} from the old policy.

Normalize within the group

Âi = (ri − mean(r)) / std(r), applied to every token of oi. "GRPO foregoes the critic model, instead estimating the baseline from group scores."

PPO-style update

Clipped probability ratios as in PPO, plus a KL (Kullback-Leibler divergence) penalty to a reference model added to the loss (R1 used a KL coefficient of 0.001).

Why a group baseline works

A baseline only has to be "what reward would I expect for this prompt?". Several samples for the same prompt estimate that directly, with no network. The cost moves from memory (a critic) to compute (G samples per prompt), which also gives the reward signal more chances to be non-zero.

At a glance

The group is its own baseline; a checker replaces the reward model.

5 · How it works

When does a group teach anything?

If every answer in a group is right, or every answer is wrong, all advantages are 0 and the prompt contributes nothing. Probability of a "dead" group = pG + (1−p)G, where p is the chance of a correct answer. Pick p and G.

Practical consequence

Prompts the model always solves, or never solves, waste samples. RLVR datasets are therefore filtered towards problems of useful difficulty, and larger G helps on hard prompts. In notebook 08, a toy "base model" with 16% accuracy reaches 0.88 / 0.95 / 0.99 after 150 iterations with G = 2 / 4 / 16.

5 · How it works

What DeepSeek reported

R1-Zero: RL without SFT

RL with rule-based accuracy and format rewards directly on the base model. AIME (American Invitational Mathematics Examination) 2024 pass@1 went from 15.6% to 77.9%, and responses grew longer as the model learned to think longer. The paper shows an "aha moment" where an intermediate checkpoint learns to stop and re-examine its own solution.

R1: fixing R1-Zero's rough edges

R1-Zero had "poor readability and language mixing". R1 adds cold-start long chain-of-thought data, a language consistency reward during RL, and a multi-stage pipeline integrating rejection sampling, RL and SFT (supervised fine-tuning).

5 · How it works

Worked example: advantages and dead groups

GRPO with group size G = 4.

Worked example

  1. Rewards [1, 0, 0, 1]: mean 0.5, std 0.5 → advantages [+1, −1, −1, +1].
  2. Rewards [1, 0, 0, 0]: mean 0.25, std 0.433 → advantages [+1.73, −0.58, −0.58, −0.58]; a rare success gets a big push.
  3. A prompt the model solves 90% of the time: P(all 4 right or all 4 wrong) = 0.9⁴ + 0.1⁴ = 65.6% of groups give zero gradient.
  4. At 15% success and G = 8: 27.2% dead groups; at G = 32: 0.55%.
Filter prompts to useful difficulty and use larger groups on hard prompts so most samples carry signal.
6 · Why it works

Why RLVR + GRPO took off

Hard-to-hack rewards

A checker either accepts the answer or not. The model must actually get it right (or find a loophole in the checker, so checkers need care too).

Cheaper RL

No critic, no learned RM for these tasks: two models (policy and reference) instead of four.

Reasoning emerges

Rewarding only final correctness, R1-Zero developed longer reasoning, self-verification and reflection by itself, without demonstrations of how to reason.

Limits

Only for checkable tasks. Open-ended writing and helpfulness still need preference models, which is why R1 combines RLVR with other stages.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Every sampled answer produces a gradient in GRPO."

Groups where all answers get the same reward have zero advantages. With 0/1 rewards, too-easy and too-hard prompts teach nothing.

"GRPO doesn't need a reference model."

It drops the critic, not the reference. A KL penalty to a reference policy is still part of the objective (coefficient 0.001 in R1).

"RLVR replaces preference tuning."

Only where answers can be verified. General chat quality, tone and safety still rely on preference data or other reward models.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Â = (r − mean)/std within the group. Applied to every token of that sample.
  • Dead groups: p^G + (1 − p)^G. Too easy or too hard prompts waste compute.
  • Keep a small KL. DeepSeek-R1 used a KL coefficient of 0.001.

⚠ Traps

  • Assuming every sample teaches. Equal rewards in a group give zero advantage.
  • Dropping the reference model. GRPO drops the critic, not the KL reference.
  • Using RLVR for open-ended tasks. Writing quality and safety still need preference signals.

9 · Key takeaway

Key takeaway

RLVR rewards answers a checker accepts; GRPO uses the spread of rewards within a group of samples as the baseline, dropping the critic. Together they trained today's reasoning models.
Say it in 30 seconds

For maths, code and formats, correctness can be checked, so RL with verifiable rewards replaces the learned reward model with a rule: one if the answer is right, plus format checks. GRPO, from DeepSeekMath, removes PPO's value model too: sample a group of answers per prompt and use each answer's reward minus the group mean, divided by the group standard deviation, as its advantage, keeping PPO's clipping and a small KL penalty to a reference. Groups where every answer gets the same reward teach nothing, so prompt difficulty and group size matter. DeepSeek-R1-Zero used this with no SFT and went from 15.6 to 77.9 percent on AIME 2024, learning longer, self-checking reasoning along the way.
