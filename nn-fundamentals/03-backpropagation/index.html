Backpropagation

How frameworks like PyTorch compute every gradient automatically: record the operations, then apply each one's local derivative in reverse order. Built from scratch in notebook 01.

What is the problem?A network is millions of operations. Writing the derivative of the loss with respect to every weight by hand is impossible, and numerical estimates would cost one forward pass per weight.
Core ideaDuring the forward pass, record a graph of operations and their inputs. Then walk it in reverse topological order, each node passing grad × local derivative to its parents and accumulating (+=) where values are reused. That is reverse-mode automatic differentiation.

The expression L = (tanh(w·x + b) − y)² recorded as a list of operations. Step forward to fill in values, then backward to fill in gradients, one node at a time.

2 · Limitation

Why not differentiate some other way?

By hand

Every architecture change would need new derivative code; error-prone at any real size.

Numerically

Finite differences need one forward pass per parameter: billions per step.

Symbolically

Expanding the full formula duplicates shared sub-expressions and explodes in size.

4 · Core idea

Record, order, reverse

Record

Each operation returns a new node that stores its inputs and a small backward function.

Order

A depth-first search gives a topological order: each node appears after its inputs.

Reverse and accumulate

Set dL/dL = 1, then for each node in reverse order: parent.grad += node.grad × ∂node/∂parent.

At a glance

Each op only needs its own backward rule; the graph does the rest.

Backward rules you need for an LLM

PyTorch in one sentence

Every tensor operation records a node (grad_fn); loss.backward() runs exactly this reverse topological walk over tensors, and optimizer.zero_grad() resets the accumulated .grad fields.

5 · How it works

Worked example: one neuron and a squared loss

o = tanh(w₁x₁ + w₂x₂ + b) with x₁ = 2, x₂ = 0, w₁ = −3, w₂ = 1, b = 6.8814; loss = (o − 1)².

Worked example

  1. Forward: w₁x₁ + w₂x₂ + b = −6 + 0 + 6.8814 = 0.8814; o = tanh(0.8814) = 0.7071; loss = 0.0858.
  2. Backward: dloss/do = 2(o − 1) = -0.5858; tanh′ = 1 − o² = 0.5000, so dloss/dn = -0.2929.
  3. The sum passes that gradient unchanged to each term; the product w₁x₁ gives dloss/dw₁ = x₁ · that = -0.5857, and dloss/dw₂ = x₂ · that = 0.
  4. Notebook 01 builds exactly this graph with a Value class and checks dloss/dw₁ against a finite difference.
Each node used one local rule; the chain rule happened automatically by walking the graph backwards.
6 · Why it works

Why reverse mode is the right choice

One pass for all weights

One scalar loss, billions of parameters: reverse mode costs about one extra pass; forward mode would cost one pass per parameter.

Local and composable

New layers only need a forward and a local backward rule.

Exact

Uses analytic local derivatives, so results match finite differences to rounding error.

Costs memory

Forward values must be kept for the backward pass, the source of activation memory (Distributed deck 08).

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Backpropagation is how the network learns."

Backprop only computes gradients; the optimizer (SGD (stochastic gradient descent), Adam) uses them to change the weights.

"Autograd approximates derivatives."

It applies exact local derivatives; only floating-point rounding differs.

"Gradients overwrite each other when a value is reused."

They add: a value used in two places receives the sum of both contributions.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Zero the gradients each step. Because backward accumulates (+=).
  • A gradient has its tensor's shape. dW for a (d × k) weight is (d × k).
  • Backward ≈ 2× forward FLOPs (floating-point operations). Two matmuls per linear layer (dX and dW).

⚠ Traps

  • Forgetting to zero grads. Gradients from previous steps silently add up.
  • Detaching by accident. Converting to NumPy or using .item() cuts the graph.
  • Overwriting instead of accumulating. A value used twice must receive both contributions.

Why does backward use reverse topological order?

So every node's gradient is complete, with contributions from all its consumers, before it is propagated to its own inputs.

Why do you call zero_grad() every step in PyTorch?

backward() accumulates into .grad; without zeroing, gradients from earlier steps would add up.
9 · Key takeaway

Key takeaway

Backpropagation records the forward computation as a graph, then walks it in reverse topological order applying local derivative rules and accumulating gradients.
Say it in 30 seconds

Automatic differentiation makes training practical. During the forward pass every operation records its inputs and a small backward rule. Calling backward on the loss sets its gradient to one, sorts the graph so each node comes after its inputs, and walks it in reverse: each node multiplies its gradient by its local derivative and adds the result into each input's gradient. Adding matters because values can be reused. This is reverse-mode differentiation: one backward pass gives the gradient for every weight at about twice the forward cost, which is why frameworks like PyTorch can train any architecture you can write.
