Neural Networks · 09

Embeddings

How discrete tokens become vectors a network can compute with: a learned lookup table, why it beats one-hot vectors, and what geometry the vectors acquire.

What is the problem?Text arrives as integer token IDs (identifiers). Integers have no useful arithmetic (token 500 is not "close to" 501), and one-hot vectors are huge and say every pair of words is equally different.
Core ideaAn embedding table E (V × d) maps token i to row Eᵢ. That is exactly one-hot(i) × E, done as a lookup. The rows are learned by backpropagation, so tokens used in similar contexts end up with similar vectors.

2 · Limitation

Why not integers or one-hot vectors?

Integers

Token IDs have an arbitrary order; arithmetic on them is meaningless.

One-hot

A V-dimensional vector per token (V ≈ 50K–250K): huge and every pair is equally far apart.

Hand-made features

Nobody can write down useful features for every token in 100 languages.

4 · Core idea

A learned lookup table

Table

E has one row of d numbers per token: V × d parameters.

Lookup

Input token i → E[i]. Equivalent to one-hot × E, the first linear layer of the model.

Learned geometry

Backprop moves rows so tokens that predict similar contexts get similar vectors (Bengio et al., 2003; word2vec).

At a glance

The same idea embeds positions, images patches, users or products.

5 · How it works

Worked example: GPT-2 small's embedding table

GPT-2 has a vocabulary of 50,257 tokens; the small model uses d = 768.

Worked example

  1. Table size: 50,257 × 768 = 38.6M parameters, about a third of the 124M-parameter small model.
  2. A one-hot input would be a 50,257-dimensional vector with a single 1; multiplying it by E selects one row, so frameworks just index.
  3. Gradient: only the rows of tokens present in the batch receive gradient (sparse update).
  4. GPT-2 ties the output layer to the same matrix: logits = h · Eᵀ, saving another 38.6M parameters.
Embeddings are a big, sparse-updated lookup table whose geometry is learned from context.
6 · Why it works

Why learned embeddings work

Distributional signal

Words that appear in similar contexts receive similar gradients, so their vectors converge.

Generalisation

A model that learned about "cat" transfers some of it to "kitten" because their vectors are close.

Directions carry meaning

word2vec found offsets like man → woman are roughly consistent across pairs.

Reusable

Contextual embeddings from the middle of an LLM (large language model) power retrieval and classification.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Each embedding dimension means something specific."

Meaning is spread across directions; individual coordinates are rarely interpretable.

"Embeddings are fixed after pretraining."

They keep updating in fine-tuning, and contextual representations change every layer.

"The embedding layer is a small part of the model."

For small models with big vocabularies it can be a third or more of the parameters.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Lookup = one-hot × E. Same math, no multiply.
  • Tied embeddings. Reuse E for the output projection.
  • Cosine similarity for neighbours. Lengths vary with frequency.

⚠ Traps

  • Treating token IDs as numbers. Feeding the integer itself implies a meaningless order.
  • Rare tokens. Few updates, so their vectors stay close to initialisation.
  • Over-reading analogies. king − man + woman ≈ queen is a tendency, not a law.

9 · Key takeaway

Key takeaway

Embeddings are a learned V × d lookup table, equivalent to one-hot × E, whose rows acquire meaningful geometry because similar contexts give similar gradients.
Say it in 30 seconds

Neural networks need vectors, but text arrives as token IDs. An embedding table has one learned row of d numbers per token, and looking up row i is mathematically the same as multiplying a one-hot vector by the table, just much cheaper. Training moves the rows so that tokens used in similar contexts get similar vectors, which lets knowledge transfer between related words; word2vec famously found consistent directions such as man to woman. Tables are large: GPT-2 small's is 50,257 by 768, about 39 million parameters, and many models tie it to the output layer.

Problem: token IDs have no geometry.
Core idea: learned table E; lookup = one-hot × E.
Facts: V × d parameters; sparse gradients; weight tying.

Bengio et al. · JMLR 2003

The first neural language model: learned word embeddings plus a network that outputs a softmax over the next word, trained by maximum likelihood.
