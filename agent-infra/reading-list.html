Agent infrastructure: key papers

Every paper cited on the decks' Key papers slides, in the order the guide introduces them. Each entry links to the paper and to the decks that use it.

Router - load balancing, fallbacks and retries
LiteLLM documentation · docs.litellm.ai 2026 · cited in LLM gateway

An open-source gateway router: routing strategies (default simple-shuffle; latency-, cost-, usage-based, least-busy), num_retries with backoff on rate limits, fallbacks to other model groups, and cooldowns (allowed_fails 3, cooldown_time 5 s).

AI Gateway
Cloudflare documentation · developers.cloudflare.com 2026 · cited in LLM gateway

A managed gateway in front of model providers: analytics, logging, caching, rate limiting, request retry and model fallback.

Rate limits
Anthropic documentation · platform.claude.com 2026 · cited in LLM gateway

Limits in requests, input tokens and output tokens per minute (RPM, ITPM, OTPM) per model class, enforced with a token bucket; 429 errors with retry-after; for most models cached input tokens do not count toward ITPM.

Remember: 2M ITPM with an 80% cache hit rate ≈ 10M total input tokens per minute
OWASP Top 10 for LLM Applications 2025
OWASP GenAI Security Project · genai.owasp.org 2025 · cited in LLM gateway, Identity and access control

LLM06:2025 Excessive Agency: root causes are excessive functionality, excessive permissions and excessive autonomy; mitigations include minimising extensions and their permissions, executing in the user's context, user approval and complete mediation.

Building effective agents
Anthropic · Anthropic Engineering 2024 · cited in Model and agent routing

Workflows (predefined code paths) vs agents (LLMs directing their own process); patterns: prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer. Start with the simplest solution.

RouteLLM: Learning to Route LLMs with Preference Data
Ong et al. · ICLR 2025 · cited in Model and agent routing

Routers trained on human preference data (with augmentation) choose between a strong and a weak model per query; they transfer when the model pair changes.

Remember: costs cut by over 2× in some cases without lowering response quality
Hybrid LLM: Cost-Efficient and Quality-Aware Query Routing
Ding et al. · ICLR 2024 · cited in Model and agent routing

A router sends each query to a small or large model from its predicted difficulty; the quality level is tunable at test time.

Remember: up to 40% fewer calls to the large model with no drop in response quality
FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance
Chen, Zaharia & Zou · TMLR 2024 · cited in Model and agent routing

Three cost levers (prompt adaptation, LLM approximation, LLM cascade); FrugalGPT learns a cascade that queries cheaper models first and stops when a scorer accepts the answer.

Remember: matches GPT-4 with up to 98% lower cost, or +4% accuracy at the same cost
Role Based Access Control
NIST Computer Security Resource Center · csrc.nist.gov 2024 · cited in Identity and access control

RBAC was formalised by Ferraiolo and Kuhn in 1992; the NIST model became the ANSI/INCITS 359-2004 standard (revised 2012). Users get roles, roles carry permissions.

Guide to Attribute Based Access Control (ABAC) Definition and Considerations
Hu et al. (NIST) · NIST Special Publication 800-162 2014 · cited in Identity and access control

Access decisions computed from attributes of the subject, the object, the requested operation and the environment, evaluated against policy.

Zanzibar: Google's Consistent, Global Authorization System
Pang et al. · USENIX ATC 2019 · cited in Identity and access control

Relationship-based access control as a service; ACLs stored as relation tuples, checked consistently at global scale.

Remember: trillions of ACLs, millions of checks per second, p95 under 10 ms, over 99.999% availability for 3 years
Model Context Protocol: Authorization (revision 2026-07-28)
MCP specification · modelcontextprotocol.io 2026 · cited in Identity and access control

OAuth 2.1 for HTTP (Hypertext Transfer Protocol) transports: servers are resource servers publishing Protected Resource Metadata (RFC 9728); clients use PKCE (S256) and the resource parameter (RFC 8707); servers must validate the token audience and must not pass tokens through; 403 insufficient_scope triggers step-up authorization.

OAuth 2.0 Token Exchange (RFC 8693)
Jones et al. · IETF (Internet Engineering Task Force) 2020 · cited in Identity and access control

Exchange a subject token (and optional actor token) for a new token; distinguishes impersonation from delegation ("A is an agent for B") and records the acting party in the act claim.
