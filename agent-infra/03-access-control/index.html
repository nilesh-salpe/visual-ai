Identity and access control for agents

Making an agent act with the user's permissions and no more: role- and attribute-based policies enforced outside the model, delegated and audience-bound tokens, and permission-aware retrieval.

What is the problem?An agent with one broad service credential can do anything that credential can, for anyone who talks to it, including an attacker hiding instructions in a document. That is a confused deputy. Retrieval without permissions hands users documents they could never open.
Core ideaAuthorise every action as the user, with least privilege. A policy engine (role-based, attribute-based or relationship-based access control) decides outside the model, a gateway in front of tools enforces it, tokens are scoped and bound to one audience (OAuth 2.1, RFC (Request for Comments) 8707) and delegation is explicit (RFC 8693). Retrieval filters by the user's access lists before the model sees any text. The model never decides who may do what.

1 · Problem

Agents are perfect confused deputies

Confused deputy

A privileged program tricked into using its authority for someone who lacks it; the agent is the deputy, injected text the trickster.

Excessive agency

OWASP (Open Worldwide Application Security Project) LLM06:2025 names the root causes: excessive functionality, excessive permissions and excessive autonomy.

Leaky retrieval

An index built from every document answers any user; OWASP lists Vector and Embedding Weaknesses (LLM08:2025).

Untraceable actions

If every call uses the agent's own key, logs cannot say which user caused what.

2 · Core idea

Decide outside the model, act as the user

RBAC

Role-based access control: users get roles, roles carry permissions. Formalised by Ferraiolo and Kuhn in 1992; the NIST (National Institute of Standards and Technology) model became ANSI (American National Standards Institute)/INCITS (International Committee for Information Technology Standards) 359-2004.

ABAC

Attribute-based access control (NIST Special Publication 800-162): decide from attributes of subject, object, action and environment, e.g. "same department, business hours, document not restricted".

ReBAC

Relationship-based: "user is editor of folder that contains doc". Google's Zanzibar serves trillions of such access lists, millions of checks per second, p95 under 10 ms.

Delegation

RFC 8693 token exchange distinguishes impersonation (A is B) from delegation ("A is an agent for B"), recorded in the token's act claim.

The model proposes actions; deterministic code checks them. OWASP's mitigations say the same: minimise tools and their permissions, execute in the user's context, require approval for high-impact actions, and use complete mediation (check every request at the downstream system).

4 · Low-level design

Authorization in MCP (revision 2026-07-28)

Permission-aware retrieval

Store access lists with each chunk and filter inside the search (pre-filter), not after the model has read the text. Sync access changes into the index promptly.

Proxy servers

MCP (Model Context Protocol) proxy servers using a static client ID (identifier) MUST get user consent for each dynamically registered client before forwarding to a third-party authorization server, which closes a confused-deputy hole.

5 · Trade-offs

Trade-offs

Choice Benefit Cost
One service account for the agent simple every user gets the agent's full power; no per-user audit
Per-user delegated tokens (OAuth) actions limited to the user's rights; clear audit consent flows, token storage and refresh
RBAC (role-based access control) easy to reason about and review role explosion for fine-grained rules
ABAC (attribute-based access control) / ReBAC (relationship-based access control) fine-grained, contextual decisions policy complexity; a check service on the hot path
Pre-filter retrieval by access list no leaked text restrictive filters can hurt ANN (approximate nearest neighbour) recall
Human approval for risky actions stops injected or mistaken actions latency and approval fatigue
6 · Failure modes

Failure modes

Failure Symptom Mitigation
Token passthrough a token meant for one service works at another audience validation; separate upstream tokens (MCP: MUST NOT pass through)
Injected instruction uses a permitted tool data sent out with a valid token authorization does not stop this alone: egress limits, approval for sensitive actions
Over-broad scopes one token can read and write everything request minimal scopes; step-up when more are needed
Stale ACLs in the index revoked users still retrieve documents propagate permission changes; re-check at read time
Cross-user memory agent recalls one user's data for another partition memory and caches by user and tenant
Tokens in logs or prompts credentials leak through traces or the model keep tokens in the tool layer, never in the context window
7 · Challenges in production

In production

Short-lived tokens

Issue short-lived access tokens and rotate refresh tokens for public clients, as the MCP spec requires.

Policy as code

Version and test policies like software; review new tools for the permissions they need.

Tenant isolation

Separate indexes, caches and memory per tenant where the data demands it.

Kill switches

Be able to revoke an agent's or a user's tokens and disable a tool instantly.

OWASP Top 10 for LLM (large language model) Applications 2025
OWASP GenAI Security Project · genai.owasp.org 2025

LLM06:2025 Excessive Agency: root causes are excessive functionality, excessive permissions and excessive autonomy; mitigations include minimising extensions and their permissions, executing in the user's context, user approval and complete mediation.

Role Based Access Control
NIST Computer Security Resource Center · csrc.nist.gov 2024

RBAC was formalised by Ferraiolo and Kuhn in 1992; the NIST model became the ANSI/INCITS 359-2004 standard (revised 2012). Users get roles, roles carry permissions.

Guide to Attribute Based Access Control (ABAC) Definition and Considerations
Hu et al. (NIST) · NIST Special Publication 800-162 2014

Access decisions computed from attributes of the subject, the object, the requested operation and the environment, evaluated against policy.

Zanzibar: Google's Consistent, Global Authorization System
Pang et al. · USENIX ATC 2019

Relationship-based access control as a service; ACLs stored as relation tuples, checked consistently at global scale.

Remember: trillions of ACLs, millions of checks per second, p95 under 10 ms, over 99.999% availability for 3 years
Model Context Protocol: Authorization (revision 2026-07-28)
MCP specification · modelcontextprotocol.io 2026

OAuth 2.1 for HTTP (Hypertext Transfer Protocol) transports: servers are resource servers publishing Protected Resource Metadata (RFC 9728); clients use PKCE (S256) and the resource parameter (RFC 8707); servers must validate the token audience and must not pass tokens through; 403 insufficient_scope triggers step-up authorization.

OAuth 2.0 Token Exchange (RFC 8693)
Jones et al. · IETF (Internet Engineering Task Force) 2020

Exchange a subject token (and optional actor token) for a new token; distinguishes impersonation from delegation ("A is an agent for B") and records the acting party in the act claim.
