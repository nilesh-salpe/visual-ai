Prompting and in-context learning

How a model learns a task from its prompt alone: what in-context examples really teach, the biases that make few-shot prompts unstable, how to structure a prompt (role, documents, instructions, examples, query), many-shot prompting, and optimising prompts against an eval set.

What is the problem?The same model gives very different results depending on wording, the examples chosen and even their order. In an agent the system prompt, tool descriptions and examples are the program, yet they are often edited by hand and never tested.
Core ideaIn-context learning: the model infers the task from instructions and examples in the prompt, with no weight updates. Examples mostly teach the format, the label space and the input distribution, not new facts. Write prompts like a brief for a capable new colleague: role and reasons, long documents first, numbered instructions, 3 to 5 varied examples in tags, the query last, and a schema for the output. Then treat the prompt as code: version it, test it on an eval set, and optimise it.

1 · Problem

The same task, very different results

Unstable few-shot prompts

Zhao et al.: the prompt format, the choice of training examples and even their order moved GPT-3 from near chance to near state of the art.

Systematic biases

Models favour answers that are frequent among the examples (majority label bias), that appear last (recency bias), or are common in pretraining (common token bias).

Formatting alone

Sclar et al.: semantically equivalent formats (separators, casing, spacing) changed accuracy by up to 76 points for LLaMA-2-13B.

2 · Core idea

Examples teach the format; instructions teach the goal

In-context learning

GPT-3 showed that large models can perform a new task from a few input-output pairs in the prompt, with no gradient updates, and that larger models use those examples more efficiently.

What examples carry

Min et al.: replacing the gold labels in demonstrations with random labels cost only 0 to 5% absolute on classification and multiple choice. The label space, the input distribution and the format mattered far more.

Instructions with reasons

Explain why a rule exists ("read aloud by a text-to-speech engine, so never use ellipses") and say what to do rather than what not to do; the model generalises from the reason (Claude docs).

Many-shot

With long contexts, hundreds or thousands of examples can override pretraining biases and perform comparably to fine-tuning on some tasks (Agarwal et al. 2024); model-generated rationales can stand in for scarce human ones.

Calibration helps too: Zhao et al. estimate the model's bias from a content-free input such as "N/A" and correct for it, improving GPT-3 and GPT-2 accuracy by up to 30.0% absolute.

A prompt, written out

[system]
You triage Acme billing tickets.
Each goes to a human queue, and a
wrong queue delays refunds by days,
so answer "unsure" if no label fits.

[user]
<documents>
 <document index="1">
  <source>refunds.md</source>
  <document_content>
  ...
  </document_content>
 </document>
</documents>

<instructions>
1. Read the ticket.
2. Pick one label: refund,
   invoice, fraud or unsure.
3. Quote the sentence that
   decided it.
</instructions>

<examples>
 <example>
  <ticket>Charged twice in May.
  </ticket>
  <label>refund</label>
 </example>
 ... 3 to 5 varied examples,
 balanced across labels,
 in shuffled order ...
</examples>

<ticket>{ticket_text}</ticket>
Technique Use it for Evidence
XML (Extensible Markup Language) tags around documents, examples, inputs unambiguous structure Claude docs: tags help parse complex prompts

5 · Trade-offs

Trade-offs

Choice Benefit Cost
Zero-shot instructions short prompt; no examples to maintain the format and edge cases are left to the model
Few-shot (3 to 5 examples) reliable format, tone and label space example bias; extra tokens on every call
Many-shot (hundreds of examples) can rival fine-tuning, no training run long, costly prompts unless cached; curation effort
Fine-tuning instead short prompts; behaviour built in training pipeline; stale when the task changes (RAG (retrieval-augmented generation) vs fine-tuning deck)
Hand-written prompts fast to start, readable brittle; no evidence a change helped
Optimised prompts (DSPy, OPRO (Optimization by Prompting)) measured gains: DSPy beat standard few-shot by over 25% (GPT-3.5); OPRO up to 8% on GSM8K (Grade School Math 8K) needs an eval set and a metric; can overfit it
6 · Failure modes

Failure modes

Failure Symptom Mitigation
Example bias answers drift to the label most frequent or last in the examples balance labels; shuffle order; calibrate
Examples copied too literally outputs mimic an example's wording or length vary the examples; state that they are illustrations
Format sensitivity accuracy moves with a separator or casing change test several formats; report the spread, not the best one
Unexplained rules the model follows the letter and misses the intent give the reason for each rule
Model upgrade regressions a prompt tuned for one model misbehaves on the next pin model versions; rerun the eval set on every upgrade
Untrusted text in the prompt retrieved pages or tool results contain instructions separate data from instructions with tags; treat it as data (Safety and reliability deck)
7 · Challenges in production

In production

Prompts are code

Keep them in version control with tests; review changes; log the prompt version with every request.

Evals gate changes

A fixed set of real cases with graders; every prompt or model change runs against it (Evaluating agents deck).

Cache the stable prefix

System prompt, tools and documents rarely change; keep them first and byte-identical so prompt caching applies.

Re-tune per model

Guidance changes between model generations (for example, prefill removal); read the provider's current prompting guide when you upgrade.

Language Models are Few-Shot Learners (GPT-3)
Brown et al. · NeurIPS 2020

Besides in-context learning, a systematic contamination study: 13-gram overlap flags and clean vs dirty scores.

Remember: 13-gram overlap; a filtering bug left some overlap in
Rethinking the Role of Demonstrations: What Makes In-Context Learning Work?
Min et al. · EMNLP 2022

Ground-truth labels in demonstrations matter little; the label space, the distribution of input text and the format drive in-context learning.

Remember: random labels cost 0–5% absolute
Calibrate Before Use: Improving Few-Shot Performance of Language Models
Zhao, Wallace, Feng, Klein, Singh · ICML 2021

Few-shot accuracy swings with format, examples and order because of majority label, recency and common token biases; contextual calibration with a content-free input corrects them.

Remember: up to 30.0% absolute accuracy gain (GPT-3, GPT-2)
Fantastically Ordered Prompts and Where to Find Them: Overcoming Few-Shot Prompt Order Sensitivity
Lu et al. · ACL 2022

The order of the same few-shot examples can make the difference between near state-of-the-art and random-guess performance, across model sizes.

Remember: order alone: near state of the art to chance
Quantifying Language Models' Sensitivity to Spurious Features in Prompt Design
Sclar et al. · ICLR 2024

Shows equivalent prompt formats (separators, casing, spacing) change accuracy dramatically, and proposes reporting the spread (FormatSpread).

Remember: up to 76 accuracy points (LLaMA-2-13B)
Many-Shot In-Context Learning
Agarwal et al. · NeurIPS 2024

Hundreds or thousands of in-context examples give large gains over few-shot, can override pretraining biases and perform comparably to fine-tuning; Reinforced ICL uses model-generated rationales.

Remember: Gemini 1.5 Pro; gains across generative and discriminative tasks
DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines
Khattab et al. · arXiv 2023

Programs of declarative LM modules whose prompts and demonstrations are optimised (compiled) against a metric.

Remember: over 25% (GPT-3.5) and 65% (llama2-13b-chat) above standard few-shot prompting
Large Language Models as Optimizers (OPRO)
Yang et al. · ICLR 2024

An LLM proposes new instructions given previous ones and their scores; the best prompts beat human-designed ones.

Remember: up to 8% on GSM8K and up to 50% on Big-Bench Hard
Prompting best practices (Claude documentation)
Anthropic · Claude platform docs 2026

Be clear and direct, explain the reasons for rules, use 3–5 examples in example tags, structure with XML tags, put long documents first and the query last; prefilled responses are not supported from Claude 4.6 models (use structured outputs).

Remember: queries at the end: up to 30% better response quality on long, complex inputs
Effective context engineering for AI (artificial intelligence) agents
Anthropic · Anthropic Engineering 2025

Context as a finite "attention budget" (context rot); just-in-time retrieval; compaction, structured note-taking and sub-agents for long-horizon tasks.
