An enterprise RAG assistant

A question-answering assistant over a company's documents: indexing at scale, permission-aware retrieval, hybrid search and reranking, grounded answers with citations, freshness and evaluation.

What is the problem?Design an assistant that answers employees' questions from 10 million internal documents, never reveals a document a user cannot open, cites its sources and stays fresh as documents change.
Core ideaAn offline indexing pipeline (parse, chunk, add context, embed, BM25 (Okapi Best Matching 25 ranking function)) keyed by content hash, with access lists on every chunk; an online path that rewrites the query, runs hybrid search filtered by the user's groups, fuses with RRF (reciprocal rank fusion), reranks about 150 candidates to 20, and has the model answer with citations. Measure retrieval recall and groundedness continuously.

1 · Requirements

What the system must do

Functional

Answer questions from internal documents with citations; say "not found" when the documents do not answer; multi-turn follow-ups.

Hard requirement

Never show or use a document the asking user cannot open in the source system.

Scale (assumption)

10M documents averaging 2,000 tokens; 50,000 employees asking 10 questions a day; peak 3× average.

Freshness and latency (target)

Edits searchable within 15 minutes; permission revocations within 5; first answer token p95 under 3 s.

5 · Deep dive

Deep dive: permissions inside retrieval

Filter before ranking

Every chunk carries its document's access list; the search filters by the user's groups inside the index, so unauthorised text never reaches the reranker or the model.

Sync permissions fast

Permission changes come from the identity system and source connectors as events; revocations update chunk metadata within minutes, with a nightly reconciliation.

Re-check at read time

Before showing a citation, check the document's current permission with the source system: a stale index must not leak.

Restrictive filters

Very selective filters can starve approximate search of candidates: partition indexes by large groups, or fall back to exact search on small filtered sets.

6 · Scaling

What breaks at 10×

Bottleneck Symptom Response
Index memory HNSW (hierarchical navigable small world) over RAM (random-access memory) product quantization, DiskANN-style SSD (solid-state drive) graphs, sharding by source
Re-embedding a model upgrade means re-embedding billions of tokens versioned indexes, blue/green swap, scheduled backfills
Ingestion bursts freshness lags after bulk imports priority queues for edits and deletes, autoscaled workers
Reranker latency p99 grows with candidate count cap candidates, GPU (graphics processing unit) batching, time out to fused order
Long documents answer split across chunks structure-aware chunking, neighbouring-chunk expansion
7 · Failures and operations

Failures and operations

Leaked document

Treat as a security incident: audit logs of query, user, chunks and citations make it traceable.

Stale or deleted content

Deletes processed from the change feed; reconciliation catches missed events.

Retrieval regressions

A labelled query set (recall@20) and groundedness checks run on every index or model change.

Prompt injection in documents

Retrieved text is data: instructions inside documents are ignored, and the assistant has no write tools.

8 · Trade-offs

Trade-offs and alternatives

Decision Chosen Alternative Why
Retrieval hybrid BM25 + dense, RRF, rerank dense only exact identifiers and rare terms need lexical match
Chunks contextual chunks (LLM-written (LLM = large language model) context) plain chunks or late chunking Anthropic: failures −49% with BM25, −67% with reranking
Permissions pre-filter in the index + read-time check filter after retrieval post-filtering exposes text to the pipeline and returns fewer results
Index HNSW with quantization flat search flat is exact but too slow and memory-hungry at 50M chunks
Small corpora retrieval put everything in the prompt under ~200K tokens, skip retrieval and use prompt caching
9 · Summary

Summary

Quality is decided at indexing

Parse well, chunk with context, keep metadata and access lists.

Permissions inside retrieval

Filter in the index and re-check at read time; never after generation.

Hybrid, fused, reranked

BM25 + dense, RRF, rerank 150 → 20, answer with citations.

Further reading

Key papers

The primary sources behind this deck, each with what it contributed. Links go to the paper (arXiv or the conference page).

Introducing Contextual Retrieval
Anthropic · Anthropic News 2024

Prepend 50-100 tokens of chunk-specific context (written by an LLM from the whole document) before embedding and BM25 indexing; retrieve top 150, rerank, keep 20. Knowledge bases under 200,000 tokens can go straight into the prompt.

Remember: top-20 retrieval failures 5.7% → 3.7% (−35%), 2.9% with BM25 (−49%), 1.9% with reranking (−67%); $1.02 per million document tokens
Reciprocal Rank Fusion outperforms Condorcet and individual Rank Learning Methods
Cormack, Clarke & Büttcher · SIGIR 2009

Fuse several rankings by score(d) = Σ 1/(k + rank_r(d)) with k = 60; simple, training-free and better than the individual rankings.

Passage Re-ranking with BERT (Bidirectional Encoder Representations from Transformers)
Nogueira & Cho · arXiv 2019

A BERT cross-encoder reads query and passage together and outputs a relevance score; used to rerank BM25 candidates.

Remember: +27% relative MRR (mean reciprocal rank)@10 over the previous state of the art on MS MARCO
Efficient and robust approximate nearest neighbor search using Hierarchical Navigable Small World graphs
Malkov & Yashunin · IEEE TPAMI 2018

A multi-layer proximity graph: each element's top layer is drawn from an exponentially decaying distribution (mL = 1/ln M), search descends greedily from the top layer, and layer 0 keeps up to 2M links per element; logarithmic complexity scaling.

DiskANN: Fast Accurate Billion-point Nearest Neighbor Search on a Single Node
Subramanya et al. · NeurIPS 2019

A graph index (Vamana) stored on SSD with compressed vectors in RAM serves a billion-point index from one workstation.

Remember: 1B points, 64 GB RAM, >5,000 queries/s, <3 ms mean latency, 95%+ 1-recall@1 on 16 cores
OWASP (Open Worldwide Application Security Project) Top 10 for LLM Applications 2025
OWASP GenAI Security Project · genai.owasp.org 2025

LLM06:2025 Excessive Agency: root causes are excessive functionality, excessive permissions and excessive autonomy; mitigations include minimising extensions and their permissions, executing in the user's context, user approval and complete mediation.

BEIR: A Heterogenous Benchmark for Zero-shot Evaluation of Information Retrieval Models
Thakur et al. · NeurIPS Datasets and Benchmarks 2021

18 retrieval datasets for zero-shot evaluation; BM25 is a robust baseline, and re-ranking and late-interaction models score best on average at higher compute cost.
