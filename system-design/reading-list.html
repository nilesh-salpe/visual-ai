System design case studies: key papers

Every paper cited on the decks' Key papers slides, in the order the guide introduces them. Each entry links to the paper and to the decks that use it.

Efficient Memory Management for Large Language Model Serving with PagedAttention
Kwon et al. · SOSP 2023 · cited in Serving a chat assistant

Stores the KV cache in fixed-size blocks mapped by a block table, like virtual memory pages, giving near-zero fragmentation and sharing with copy-on-write. The basis of vLLM.

Remember: 2–4× throughput vs FasterTransformer and Orca at the same latency
Automatic Prefix Caching (design)
vLLM documentation · docs.vllm.ai 2026 · cited in Serving a chat assistant

Each KV block is hashed with its tokens and the prefix before it; blocks are reference-counted, freed blocks are evicted in LRU (least recently used) order, and cache hits skip prefill.

Orca: A Distributed Serving System for Transformer-Based Generative Models
Yu et al. · OSDI 2022 · cited in Serving a chat assistant

Iteration-level scheduling (requests join and leave the batch after every decode step) plus selective batching (batch the matmuls, run attention per request).

Remember: 36.9× throughput over FasterTransformer at the same latency (GPT-3 175B)
Taming Throughput-Latency Tradeoff in LLM Inference with Sarathi-Serve
Agrawal et al. · OSDI 2024 · cited in Serving a chat assistant

Chunked prefills plus stall-free scheduling: new requests are added without pausing ongoing decodes, so throughput rises without TPOT (time per output token) spikes.

Remember: 2.6× serving capacity (Mistral-7B, 1 A100) and up to 3.7× (Yi-34B, 2 A100s) vs vLLM; up to 5.6× with pipeline parallelism (Falcon-180B)
DistServe: Disaggregating Prefill and Decoding for Goodput-optimized Large Language Model Serving
Zhong et al. · OSDI 2024 · cited in Serving a chat assistant

Defines serving quality as goodput, the request rate served within both TTFT (time to first token) and TPOT targets, and runs prefill and decode on separate GPUs so they stop interfering.

Remember: 7.4× more requests or 12.6× tighter SLO than colocated systems
The Llama 3 Herd of Models
Llama Team, AI (artificial intelligence) @ Meta · arXiv 2024 · cited in Serving a chat assistant, Planning a pretraining run

Dense Transformer with GQA (8 KV heads), RoPE (rotary position embedding) base 500,000, a 128K vocabulary and a document mask; staged long-context pretraining to 128K; post-training with SFT (supervised fine-tuning), rejection sampling and DPO (Direct Preference Optimization) in six rounds.

Remember: 128K context after six stages over ~800B tokens
Rate limits
Anthropic documentation · platform.claude.com 2026 · cited in Serving a chat assistant

Limits in requests, input tokens and output tokens per minute (RPM (requests per minute), ITPM (input tokens per minute), OTPM) per model class, enforced with a token bucket; 429 errors with retry-after; for most models cached input tokens do not count toward ITPM.

Remember: 2M ITPM with an 80% cache hit rate ≈ 10M total input tokens per minute
Introducing Contextual Retrieval
Anthropic · Anthropic News 2024 · cited in Enterprise RAG assistant

Prepend 50-100 tokens of chunk-specific context (written by an LLM from the whole document) before embedding and BM25 indexing; retrieve top 150, rerank, keep 20. Knowledge bases under 200,000 tokens can go straight into the prompt.

Remember: top-20 retrieval failures 5.7% → 3.7% (−35%), 2.9% with BM25 (−49%), 1.9% with reranking (−67%); $1.02 per million document tokens
Reciprocal Rank Fusion outperforms Condorcet and individual Rank Learning Methods
Cormack, Clarke & Büttcher · SIGIR 2009 · cited in Enterprise RAG assistant

Fuse several rankings by score(d) = Σ 1/(k + rank_r(d)) with k = 60; simple, training-free and better than the individual rankings.

Passage Re-ranking with BERT (Bidirectional Encoder Representations from Transformers)
Nogueira & Cho · arXiv 2019 · cited in Enterprise RAG assistant

A BERT cross-encoder reads query and passage together and outputs a relevance score; used to rerank BM25 candidates.

Remember: +27% relative MRR (mean reciprocal rank)@10 over the previous state of the art on MS MARCO
Efficient and robust approximate nearest neighbor search using Hierarchical Navigable Small World graphs
Malkov & Yashunin · IEEE TPAMI 2018 · cited in Enterprise RAG assistant

A multi-layer proximity graph: each element's top layer is drawn from an exponentially decaying distribution (mL = 1/ln M), search descends greedily from the top layer, and layer 0 keeps up to 2M links per element; logarithmic complexity scaling.

DiskANN: Fast Accurate Billion-point Nearest Neighbor Search on a Single Node
Subramanya et al. · NeurIPS 2019 · cited in Enterprise RAG assistant

A graph index (Vamana) stored on SSD with compressed vectors in RAM serves a billion-point index from one workstation.

Remember: 1B points, 64 GB RAM, >5,000 queries/s, <3 ms mean latency, 95%+ 1-recall@1 on 16 cores
OWASP (Open Worldwide Application Security Project) Top 10 for LLM Applications 2025
OWASP GenAI Security Project · genai.owasp.org 2025 · cited in Enterprise RAG assistant

LLM06:2025 Excessive Agency: root causes are excessive functionality, excessive permissions and excessive autonomy; mitigations include minimising extensions and their permissions, executing in the user's context, user approval and complete mediation.

BEIR: A Heterogenous Benchmark for Zero-shot Evaluation of Information Retrieval Models
Thakur et al. · NeurIPS Datasets and Benchmarks 2021 · cited in Enterprise RAG assistant

18 retrieval datasets for zero-shot evaluation; BM25 is a robust baseline, and re-ranking and late-interaction models score best on average at higher compute cost.

Beyond permission prompts: making Claude Code more secure and autonomous
Anthropic · Anthropic Engineering 2025 · cited in Autonomous coding agent

Filesystem and network isolation built on Linux bubblewrap and macOS Seatbelt; egress through a proxy outside the sandbox with allowed domains; in the cloud version credentials stay outside the sandbox and a git proxy attaches the real token.

Remember: sandboxing cut permission prompts by 84% in internal use
Firecracker: Lightweight Virtualization for Serverless Applications
Agache et al. · NSDI 2020 · cited in Autonomous coding agent

A minimal KVM-based (KVM = Kernel-based Virtual Machine) virtual machine monitor for multi-tenant serverless workloads, used by AWS (Amazon Web Services) Lambda and Fargate.

Remember: < 125 ms boot, < 5 MiB overhead per microVM, up to 150 microVMs per second per host (firecracker-microvm.github.io)
Temporal Workflows
Temporal documentation · docs.temporal.io 2026 · cited in Autonomous coding agent

Workflow code is replayed against the recorded event history to rebuild state (no memory snapshots), so it must be deterministic; activities do the side effects and their results are recorded once and reused on replay.

Prompt caching
Anthropic documentation · platform.claude.com 2026 · cited in Autonomous coding agent

Reuse of cached prompt prefixes: 5-minute cache writes cost 1.25× base input, 1-hour writes 2×, and reads 0.1× on most models (lower on some newer ones).

SWE-bench (SWE = software engineering): Can Language Models Resolve Real-World GitHub Issues?
Jimenez et al. · ICLR 2024 · cited in Autonomous coding agent

Real GitHub issues: the model edits the repository and the project's own tests decide success.

Remember: 2,294 issues; Claude 2 solved 1.96% at release
τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains
Yao et al. · arXiv 2024 · cited in Autonomous coding agent

Simulated users, domain APIs (application programming interfaces) and policies; grades the final database state and introduces pass^k to measure consistency across trials.

Remember: gpt-4o < 50% success; pass^8 < 25% in retail
Building effective agents
Anthropic · Anthropic Engineering 2024 · cited in Autonomous coding agent

Workflows (predefined code paths) vs agents (LLMs (large language models) directing their own process); patterns: prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer. Start with the simplest solution.

Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism
Shoeybi et al. · arXiv 2019 · cited in Planning a pretraining run

Intra-layer (tensor) model parallelism that splits each attention and MLP (multilayer perceptron) block across GPUs with only a few all-reduce operations, implemented in plain PyTorch.

Remember: 2 all-reduces per transformer block in the forward pass; 76% scaling efficiency on 512 GPUs
ZeRO: Memory Optimizations Toward Training Trillion Parameter Models
Rajbhandari et al. · SC 2020 · cited in Planning a pretraining run

Partitions optimizer states, gradients and parameters across data-parallel workers instead of replicating them.

Remember: 100B+ parameters on 400 GPUs at 15 PFLOP (quadrillion floating-point operations)/s; 8× larger models than prior state of the art
PyTorch FSDP: Experiences on Scaling Fully Sharded Data Parallel
Zhao et al. · VLDB 2023 · cited in Planning a pretraining run

PyTorch's ZeRO-3-style fully sharded data parallelism, with flattened parameter units, prefetching and hybrid sharding.

Remember: comparable to DDP (distributed data parallel) speed while supporting much larger models
The FineWeb Datasets: Decanting the Web for the Finest Text Data at Scale
Penedo et al. · NeurIPS Datasets and Benchmarks 2024 · cited in Planning a pretraining run

15T tokens from 96 Common Crawl snapshots with fully ablated choices: WARC (Web ARChive format) + trafilatura over WET (plain text extracted from Web ARChive records), per-snapshot (not global) MinHash dedup, selected C4 filters; FineWeb-Edu uses an LLM-annotated educational-quality classifier.

Remember: 15T tokens; FineWeb-Edu 1.3T
DataDecide: How to Predict Best Pretraining Data with Small Experiments
Magnusson et al. · arXiv 2025 · cited in Planning a pretraining run

Controlled pretraining over 25 corpora, up to 100B tokens and 1B parameters, 3 seeds: rankings at a single small scale are a strong baseline; no scaling-law method among 8 baselines beats it for the same compute; continuous likelihood metrics make benchmarks highly predictable.

Remember: 150M rankings predict ~80% of 1B comparisons; >80% predictable with 0.01% of the compute
MegaScale: Scaling Large Language Model Training to More Than 10,000 GPUs
Jiang et al. · NSDI 2024 · cited in Planning a pretraining run

Production training system at ByteDance: algorithm-system co-design plus diagnosis tools for stragglers and failures at 10,000+ GPU scale.

Remember: 55.2% MFU on 12,288 GPUs (175B model), 1.34× Megatron-LM
