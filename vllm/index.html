vLLM internals and operation

How the vLLM serving engine works inside and how to run it: the process architecture, the paged KV (key-value) cache manager, the unified token-budget scheduler, automatic prefix caching, speculative decoding, parallelism and quantization, tuning with metrics, single- and multi-node deployment, and load balancing a fleet with the vLLM Router. Checked against the vLLM v0.31.0 source and documentation; the concepts are introduced in the LLM (large language model) Inference topic.

🛠 Build it: 6 Colab notebooks

Re-implement vLLM's block pool with ref counts and LRU (least recently used), chained-hash prefix caching, the token-budget scheduler with chunked prefill and preemption, a GPU (graphics processing unit) memory and concurrency planner, and n-gram speculative decoding, all as CPU (central processing unit) simulations.
