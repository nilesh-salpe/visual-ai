vLLM: key papers

Every paper cited on the decks' Key papers slides, in the order the guide introduces them. Each entry links to the paper and to the decks that use it.

Efficient Memory Management for Large Language Model Serving with PagedAttention
Kwon et al. · SOSP 2023 · cited in What vLLM is and a request's life, KV cache manager and PagedAttention

Stores the KV cache in fixed-size blocks mapped by a block table, like virtual memory pages, giving near-zero fragmentation and sharing with copy-on-write. The basis of vLLM.

Remember: 2–4× throughput vs FasterTransformer and Orca at the same latency
vLLM V1: A Major Upgrade to vLLM's Core Architecture
vLLM Team · vLLM blog 2025 · cited in What vLLM is and a request's life, Engine architecture, Automatic prefix caching

The V1 re-architecture: an isolated EngineCore busy loop (scheduler + executor) in its own process, a unified token-budget scheduler, zero-overhead prefix caching, torch.compile and piecewise CUDA graphs.

Remember: up to 1.7× higher throughput than V0
Architecture Overview
vLLM documentation · docs.vllm.ai 2026 · cited in What vLLM is and a request's life, Engine architecture

Entrypoints (LLM class, OpenAI-compatible server) and the process layout: API server, one engine-core process per data-parallel rank running a busy loop, one worker process per GPU.

vLLM v0.31.0 release
vLLM project · GitHub 2026 · cited in Engine architecture, KV cache manager and PagedAttention, The scheduler: continuous batching and chunked prefill, Speculative decoding in vLLM, Running and tuning vLLM

The release these decks were checked against (source at vllm/v1/core and vllm/config).

Automatic Prefix Caching (design)
vLLM documentation · docs.vllm.ai 2026 · cited in KV cache manager and PagedAttention, Automatic prefix caching

Each KV block is hashed with its tokens and the prefix before it; blocks are reference-counted, freed blocks are evicted in LRU order, and cache hits skip prefill.

Optimization and Tuning
vLLM documentation · docs.vllm.ai 2026 · cited in The scheduler: continuous batching and chunked prefill, Running and tuning vLLM

Preemption by recomputation when KV space runs out, chunked prefill and max_num_batched_tokens trade-offs, and when to use tensor, pipeline, expert and data parallelism.

Taming Throughput-Latency Tradeoff in LLM Inference with Sarathi-Serve
Agrawal et al. · OSDI 2024 · cited in The scheduler: continuous batching and chunked prefill

Chunked prefills plus stall-free scheduling: new requests are added without pausing ongoing decodes, so throughput rises without TPOT (time per output token) spikes.

Remember: 2.6× serving capacity (Mistral-7B, 1 A100) and up to 3.7× (Yi-34B, 2 A100s) vs vLLM; up to 5.6× with pipeline parallelism (Falcon-180B)
Orca: A Distributed Serving System for Transformer-Based Generative Models
Yu et al. · OSDI 2022 · cited in The scheduler: continuous batching and chunked prefill

Iteration-level scheduling (requests join and leave the batch after every decode step) plus selective batching (batch the matmuls, run attention per request).

Remember: 36.9× throughput over FasterTransformer at the same latency (GPT-3 175B)
SGLang: Efficient Execution of Structured Language Model Programs
Zheng et al. · NeurIPS 2024 · cited in Automatic prefix caching

A runtime and frontend for multi-call LLM (large language model) programs; RadixAttention keeps KV caches in a radix tree so shared prefixes are reused across requests automatically.

Remember: up to 6.4× higher throughput
Fast Inference from Transformers via Speculative Decoding
Leviathan et al. · ICML 2023 · cited in Speculative decoding in vLLM

A small model drafts tokens, the large model verifies them in parallel, and a modified rejection rule keeps the output distribution exactly unchanged.

Remember: 2–3× faster on T5-XXL with identical outputs
Speculative Decoding
vLLM documentation · docs.vllm.ai 2026 · cited in Speculative decoding in vLLM

Configuring speculative decoding with --speculative-config: n-gram (prompt lookup), draft models, EAGLE/EAGLE-3, MTP heads, Medusa and suffix decoding.

Parallelism and Scaling
vLLM documentation · docs.vllm.ai 2026 · cited in Parallelism and quantization

Single-node tensor parallelism, multi-node pipeline parallelism, data parallelism and expert parallelism for MoE models, and how to choose sizes.

Quantization
vLLM documentation · docs.vllm.ai 2026 · cited in Parallelism and quantization

Supported weight/activation quantization (FP8, AWQ, GPTQ, compressed-tensors, MXFP4 (microscaling 4-bit floating point), NVFP4 (NVIDIA's block-scaled 4-bit floating point) and more) and quantized KV caches, with hardware support tables.

Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism
Shoeybi et al. · arXiv 2019 · cited in Parallelism and quantization

Intra-layer (tensor) model parallelism that splits each attention and MLP (multilayer perceptron) block across GPUs with only a few all-reduce operations, implemented in plain PyTorch.

Remember: 2 all-reduces per transformer block in the forward pass; 76% scaling efficiency on 512 GPUs
AWQ: Activation-aware Weight Quantization for LLM (large language model) Compression and Acceleration
Lin et al. · MLSys 2024 · cited in Parallelism and quantization

Weight-only low-bit quantization that protects the most important weight channels, chosen by activation magnitude, by scaling them up before quantizing.

Remember: protecting 1% of salient weights greatly reduces error; >3× over Hugging Face FP16 (16-bit floating point) with its TinyChat kernels
GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers
Frantar et al. · ICLR 2023 · cited in Parallelism and quantization

One-shot weight quantization using approximate second-order information, quantizing one column at a time and compensating the error in the rest.

Remember: 175B model to 3–4 bits in about four GPU hours
FP8 Formats for Deep Learning
Micikevicius et al. · arXiv 2022 · cited in Parallelism and quantization

Defines the two FP8 encodings, E4M3 (more precision) and E5M2 (more range), and shows FP8 training and post-training quantization matching 16-bit results.

Remember: E4M3 max 448, E5M2 max 57,344
