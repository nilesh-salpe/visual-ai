Tokenization for LLMs · 01

Why tokenize?

A language model can only process numbers. Tokenization decides how text becomes a sequence of integer ids, and that choice affects vocabulary size, sequence length, cost, and what the model can "see".

What is the problem?Characters make sequences very long. Whole words leave rare and new words unknown.
Core ideaUse subwords: common words stay whole, rare words split into known pieces, so any text fits a fixed vocabulary.
1 · Problem

A model never sees text, only integer ids

Before an LLM (large language model) does anything, the input string is cut into tokens, and each token is replaced by its id in a fixed vocabulary. The model's first layer looks up one embedding row per id. Below is a real tokenization with cl100k_base (GPT-4's encoding).

"Tokenization turns text into numbers."

Hover a token for its id. · marks a space, which belongs to the token that follows it.

Next step inside the model: each id selects one row of the embedding matrix (vocabulary size V × model width d). The model's output layer then scores all V ids to predict the next token.
Everything the model learns, it learns over these ids. How text is split decides what each id means.
2 · Limitation

The two obvious units both break

Split by characters and the vocabulary is tiny, but sequences get long, and attention cost grows with the square of the length. Split by words and sequences are short, but any word outside the vocabulary becomes an unknown token. Pick a sentence.

Characters and words are split in the browser. The word row uses a toy vocabulary of about 100 common English words, and anything else becomes [UNK]. The subword row is the real cl100k_base output.

Sennrich et al. (2016) put the trade-off this way: an increase in text length "reduces efficiency and increases the distances over which neural models need to pass information", while large vocabularies cost time and space.

6 · Why it works

Why subwords work

Compression

tiktoken's README puts typical BPE (byte-pair encoding) compression at about 4 bytes per token. On this guide's 408-character English sample, cl100k_base uses 79 tokens, about 5.2 characters per token.

Fixed output layer

The model predicts one of V ids at every step. A fixed V (50K–200K) keeps that softmax bounded.

Open vocabulary

Rare words are spelled with smaller pieces, and byte-level tokenizers (deck 03) can encode any string at all.

Shorter sequences

Fewer tokens means less attention compute (it grows with n²) and more text in a fixed context window (deck 07).

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"A token is a word."

Often it is a piece of a word, and it usually includes the space before it: " strawberry" is one token in cl100k_base, but "strawberry" without the space is three (deck 10).

"Every model counts tokens the same way."

Each model has its own tokenizer. The sentence on the "Characters or words?" slide gets different token counts in gpt2, cl100k_base and o200k_base (deck 08).

"Tokenization throws information away."

Modern BPE tokenizers are reversible and lossless (tiktoken README): concatenating the tokens' bytes gives back the original text exactly.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Rule of thumb for English. A few characters per token; Llama 3 measured 3.94 characters per token.
  • Leading spaces matter. " hello" and "hello" are different tokens.
  • Everything is ids. The model sees integers; letters exist only inside the embedding.

⚠ Traps

  • Counting words as tokens. Token counts and word counts differ, by language and tokenizer.
  • Assuming one tokenizer per language. Each model family has its own; ids aren't portable.
  • Ignoring the tokenizer in evals. Some failures (spelling, arithmetic) start at tokenization.

Why not just use characters as tokens?

Sequences become several times longer, and attention cost grows with the square of the length, so compute rises and less text fits in the context window.

A subword tokenizer meets a word it has never seen. What happens?

It splits the word into known pieces, down to single characters or bytes if needed.
9 · Key takeaway

Key takeaway

Tokenization maps text to integer ids from a fixed vocabulary. Subwords keep common words whole and spell rare ones in pieces, balancing vocabulary size against sequence length.
Say it in 30 seconds

Models work on integers, so text is split into tokens and each token becomes an id from a fixed vocabulary. Characters give tiny vocabularies but long sequences, and words give short sequences but unknown words. Subword tokenizers keep frequent strings as single tokens and split rare words into known pieces. The pipeline is normalize, pre-tokenize, apply the subword model, then map to ids, and decoding reverses it losslessly.

Problem: characters make sequences long; words leave rare words unknown.
Core idea: subword tokens: a fixed vocabulary where any text is spelled with known pieces, about 4 bytes per token.
