Tokenization for LLMs · 07

Vocabulary size trade-offs

How many tokens should a vocabulary have? Bigger vocabularies make sequences shorter but add parameters, and the benefit depends heavily on the language.

What is the problem?The vocabulary size V sets sequence length, embedding and output-layer size, and how well each language is covered, all at once.
Core ideaChoose V to balance compression (characters per token) against parameters (V × d), and measure it on the languages you care about.
1 · Problem

One number, many consequences

Sequence length

Fewer, longer tokens mean shorter sequences: less attention compute and more text in the context window.

Parameters

The input embedding and the output layer each have V × d weights.

Coverage

Which languages, scripts and domains get compact tokens depends on what the vocabulary was trained on.

Training signal

Every token in the vocabulary needs enough training examples to learn a good embedding.

2 · Limitation

Both extremes hurt

Too small

Text is split into many short tokens: longer sequences, more compute per sentence, and less text per context window, especially for languages the vocabulary under-serves (deck 09).

Too large

Embedding and output matrices grow with V, and rare tokens get few training updates. Under-trained tokens that are nearly absent from training data can make models misbehave ("glitch tokens", Land & Bartolo 2024; deck 10).

3 · Your turn

What did Llama 3 gain?

Llama 3 moved from Llama 2's 32K-token vocabulary to 128K tokens. What benefit does the paper report?

B. On a sample of English data, characters per token rose from 3.17 to 3.94, which "enables the model to 'read' more text for the same amount of training compute". Adding 28K non-English tokens also improved compression and downstream performance in those languages (Llama 3 paper, §3.2).
4 · Core idea

Compression vs parameters

embedding params = V × d   (×2 if the output layer isn't tied to the input embedding)
tokens for a text ≈ characters ÷ (characters per token)
A larger V raises characters per token, but with diminishing returns once common words are already single tokens. Its cost in parameters grows linearly.

At a glance

Compression buys context and effective data; every entry costs 2·d parameters with untied embeddings.

5 · How it works

Worked example: the parameter bill vs the compression gain

Llama 3 moved from 32K to 128,256 tokens with d = 4,096 (8B model, untied input and output matrices).

Worked example

  1. Embedding + output head at 32,000: 2 × 32,000 × 4,096 = 0.26B.
  2. At 128,256: 2 × 128,256 × 4,096 = 1.05B (+0.79B).
  3. Compression on English: 3.17 → 3.94 characters per token = 24% more text per token.
  4. The same 8K context now holds ≈ 32,276 characters instead of 25,969.
For large models the extra embedding parameters are a small fraction, and the compression gain applies to every token of training and inference.
6 · Why it works

Why the trade-off resolves the way it does

Compression buys effective data and context

Llama 3: 3.17 → 3.94 characters per token on English lets the model "read" more text for the same compute.

Parameters are cheap at scale

V × d is a large share of a small model but a small share of a large one. That's why large models can afford 100K–200K vocabularies.

Where to spend tokens

Llama 3 added 28K tokens for non-English languages, which improved their compression with no effect on English tokenization.

Diminishing returns in English

On the guide's sample, going from 50K to 200K tokens barely changes English, while the Hindi sentence shrinks from 27 tokens to 5.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"A bigger vocabulary is free."

Each of the embedding and output matrices has V × d weights. At V = 128,000 and d = 4,096 that is about 524M parameters per matrix.

"Doubling the vocabulary halves the token count."

Returns diminish fast. On the English sample: 81 tokens (gpt2) → 79 (cl100k_base) → 79 (o200k_base). Most of the gain lands on under-served languages.

"Vocabulary size only matters for English text."

It matters most for other languages and scripts (Llama 3's +28K multilingual tokens; deck 09).
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Embedding params = V × d (× 2 if untied). GPT-2 small: 50,257 × 768 ≈ 38.6M.
  • Characters per token. The practical compression metric.
  • Pad V to a multiple of 64 or 128. Helps matmul efficiency.

⚠ Traps

  • Huge vocabularies in small models. The embedding can dominate the parameter budget.
  • Rare-token undertraining. Tokens seen rarely in training get poor embeddings.
  • Comparing perplexity across vocabularies. Per-token losses aren't comparable; use bits per byte or per character.

The window is measured in tokens. More characters per token means more text fits into the same number of tokens.
9 · Key takeaway

Key takeaway

Vocabulary size trades compression against parameters. Large models can afford 100K–200K tokens, and the extra tokens help non-English text far more than English.
Say it in 30 seconds

Vocabulary size V sets how many characters each token covers and how big the embedding and output layers are (V × d each, unless tied). Too small means long sequences, more compute and less text per context window. Too large adds parameters and rarely seen, under-trained tokens. Llama 3 went from 32K to 128K tokens (100K from tiktoken plus 28K multilingual) and improved English compression from 3.17 to 3.94 characters per token. In my measurements, larger vocabularies mostly help under-served languages.

Problem: V controls sequence length, parameter count and language coverage all at once.
Core idea: balance characters per token against V × d, and measure on your target languages.
