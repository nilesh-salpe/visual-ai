Tokenization for LLMs · 03

Byte-level BPE

How GPT-2 made BPE work on any string at all (emoji, every script, code) with a base vocabulary of only 256 symbols (Radford et al., 2019, §2.2).

What is the problem?A general language model should be able to give a probability to, and generate, any string. Character-level BPE either needs a huge base vocabulary or produces unknown tokens.
Core ideaRun BPE over the UTF-8 bytes of the text instead of Unicode characters. The base vocabulary is 256 bytes, so nothing is ever unknown.
1 · Problem

An LLM must handle any string

The GPT-2 paper sets the requirement: "A general language model (LM) should be able to compute the probability of (and also generate) any string." Real input includes accented letters, emoji, dozens of scripts, code, and stray control characters.

Lowercasing, word-level tokenization and unknown tokens all restrict which strings the model can represent (§2.2).
2 · Limitation

BPE over Unicode characters needs a huge base vocabulary

Reference BPE implementations of the time worked on Unicode code points. Covering every possible string that way would need "a base vocabulary of over 130,000 before any multi-symbol tokens are added", far larger than the 32,000–64,000-token vocabularies typically used with BPE.

GPT-2 paper §2.2. The alternative, an unknown token for rare characters, gives up the "any string" requirement.

4 · Core idea

BPE on bytes: 256 base symbols, then merges

Base = 256 bytes

Any text is first encoded as UTF-8, a sequence of bytes 0–255. That's the starting alphabet.

Merges on top

BPE merges frequent byte sequences into tokens. Common English words become single tokens, and rarer scripts use more, shorter tokens.

GPT-2's numbers

Vocabulary 50,257 = 256 bytes + 50,000 merges + 1 special token (<|endoftext|>), checked with tiktoken.

5 · How it works

Pre-tokenization: no merges across character categories

Applied naively, byte-level BPE wasted vocabulary on variants such as dog., dog! and dog?. GPT-2 therefore stops BPE from merging across character categories. A regular expression first splits text into chunks (letters, numbers, punctuation), with an exception that lets a space attach to the following word.

6 · Why it works

Why it works

Nothing is ever unknown

Every string is a byte sequence and all 256 bytes are in the vocabulary, so any input can be encoded.

Any string gets a probability

"Since our approach can assign a probability to any Unicode string," GPT-2 could be evaluated on any dataset "regardless of pre-processing, tokenization, or vocab size" (§2.2).

Word-level efficiency where it counts

Merges make frequent strings single tokens, combining "the empirical benefits of word-level LMs with the generality of byte-level approaches".

Vocabulary spent well

The category rule stops near-duplicate tokens like "dog." and "dog!" from using up vocabulary slots.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Byte-level means one token per byte."

Bytes are only the base. Merges build multi-byte tokens, so a common English word with its leading space is usually a single token.

"Every token decodes to valid text."

A token can hold a partial UTF-8 character: the 👋 emoji above is split across two tokens. Streaming output has to buffer bytes until a character is complete.

"The space between words is its own token."

In GPT-2-style pre-tokenization a single space attaches to the following word: " dog" is one token.

How big is the base vocabulary of byte-level BPE?

256, one symbol per byte value.

What makes up GPT-2's 50,257-token vocabulary?

256 + 50,000 + 1. The special token is <|endoftext|> (id 50256).

Why can a byte-level BPE tokenizer never output an unknown token?

Every possible input is a sequence of bytes, and every byte value is a base token, so the worst case is simply one token per byte.
9 · Key takeaway

Key takeaway

Byte-level BPE runs BPE over UTF-8 bytes: a 256-symbol base means any string can be encoded with no unknowns, while merges keep common text compact.
Say it in 30 seconds
