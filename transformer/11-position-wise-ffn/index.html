Position-wise feed-forward networks

After attention mixes information across tokens, a small two-layer network transforms each token's representation on its own.

What is the problem?Attention's output is a weighted average of value vectors. It moves information between tokens but does little non-linear processing of what each token now holds.
Core ideaApply FFN(x) = max(0, xW₁ + b₁)W₂ + b₂ (512 → 2048 → 512) to every position separately, with the same weights at every position and different weights in each layer.
1 · Problem

After gathering context, each token needs to compute new features

Attention gathers

It decides which tokens to take information from, and how much.

Then process it

Turning "it + context about the animal" into useful new features is a per-token computation.

Non-linearity

Rich features need non-linear transformations, layer after layer.

2 · Limitation

An attention output is always a blend of the values

The softmax weights are positive and sum to 1, so each output is a convex combination of the value vectors: it always lies inside the region they span. Attention routes information between tokens; on its own it doesn't add much new per-token computation. Change the weights below.

Something has to transform each token's gathered context into new features, non-linearly. That is the job of the FFN sub-layer.
3 · Your turn

What should process each token?

Pick an answer before moving on. Committing to a guess, even a wrong one, makes the real answer stick.

After attention has mixed context into each token, what should transform each token's vector?

B. A position-wise feed-forward network adds a ReLU (rectified linear unit) non-linearity and more capacity per token. Tokens don't interact at this step, so it stays fully parallel. Another attention layer (A) mixes tokens again, and an RNN (C) would bring back sequential computation.
4 · Core idea

The same small network, applied to every position independently

Each token's 512-dim vector goes through its own copy of one shared MLP (multilayer perceptron): expand to 2048, ReLU, and project back to 512. Tokens don't interact in this step (attention already did that), so all positions run in parallel.

Two equivalent views (§3.3): a fully connected network applied "to each position separately and identically", or "two convolutions with kernel size 1". The weights are shared across positions but differ from layer to layer.

5 · How it works

Inside one FFN: expand, ReLU, project back toy size 4 → 8 → 4

The inner layer is 4× wider (dff = 2048 = 4 × 512). ReLU switches hidden units off (to 0) depending on the input, which is where the non-linearity comes from. Slide between two token representations and watch different units turn on.

5 · How it works

Worked example: where the parameters are

Base model: d_model = 512, d_ff = 2,048, 6 encoder + 6 decoder layers.

Worked example

  1. One FFN: 2 × 512 × 2,048 weights + 2,560 biases = 2,099,712.
  2. Twelve FFNs (6 encoder + 6 decoder): 25.2M.
  3. Attention per block: 4 × 512² = 1,048,576; encoder 6 + decoder 12 attention blocks = 18.9M.
  4. So the FFNs hold ≈ 39% of the ~65M parameters; embeddings hold much of the rest (~37K × 512).
Attention moves information between positions; the FFN, with most of the layer weights, transforms each position.
5 · How it works from the paper · §3.3

The paper's wording

§3.3: "In addition to attention sub-layers, each of the layers in our encoder and decoder contains a fully connected feed-forward network, which is applied to each position separately and identically. This consists of two linear transformations with a ReLU activation in between."
FFN(x) = max(0, xW₁ + b₁)W₂ + b₂
"While the linear transformations are the same across different positions, they use different parameters from layer to layer. Another way of describing this is as two convolutions with kernel size 1. The dimensionality of input and output is dmodel = 512, and the inner-layer has dimensionality dff = 2048."

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"The FFN mixes information between tokens."

It is position-wise: each token is transformed on its own. Only the attention sub-layers move information between positions.

"Each position has its own FFN weights."

The weights are shared across positions within a layer, and differ from layer to layer (§3.3).

"The FFN is a small add-on next to attention."

It holds about two-thirds of each encoder layer's weights: 2 × 512 × 2048 vs 4 × 512² for attention.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • d_ff = 4·d_model. 2,048 for 512.
  • Per position, same weights. Like a 1 × 1 convolution.
  • FFN params = 2·d·d_ff. About twice the attention params per layer.

⚠ Traps

  • Thinking the FFN mixes positions. It never looks at other tokens.
  • Forgetting biases. The 2017 FFN has them (modern LLMs (large language models) usually drop them).
  • Assuming ReLU is still standard. Modern LLMs use gated SwiGLU (Swish-gated linear unit) FFNs.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

What is the FFN's inner dimension in the base model?

2048 (dff); 4096 in the big model.

Which activation does the paper's FFN use?

ReLU: FFN(x) = max(0, xW₁ + b₁)W₂ + b₂.

Why can the FFN be described as "two convolutions with kernel size 1"?

A kernel-size-1 convolution applies the same linear map at every position and looks at only that position, which is exactly a shared per-position linear layer.
9 · Key takeaway

Key takeaway

A shared 512 → 2048 → 512 ReLU network transforms each token separately: attention moves information between tokens, and the FFN processes it.
Say it in 30 seconds

Every encoder and decoder layer has a position-wise feed-forward network, FFN(x) = max(0, xW₁ + b₁)W₂ + b₂, with 512 → 2048 → 512 dimensions. The same weights apply at every position, which is equivalent to two kernel-size-1 convolutions, with different weights in each layer. It adds per-token non-linear processing after attention has mixed in context, and holds about two-thirds of each layer's parameters. A wider dff improved BLEU in Table 3.
