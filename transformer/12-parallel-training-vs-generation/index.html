Parallel training vs autoregressive generation

Why the Transformer trains on every target position at once, but still has to generate translations one token at a time.

What is the problem?An RNN is sequential in both training and inference. Fast training needs every position processed at once, but generated tokens only become known one by one.
Core ideaIn training, feed the whole reference target (shifted right) and use masking, so all m predictions come from one parallel pass. At inference, generate left to right, using beam search.
① What is the problem?

Count the sequential steps for one target sentence

For a target of m tokens: an RNN decoder needs m dependent steps even in training. A Transformer decoder needs one parallel pass in training, but m passes when generating, because token t+1 can't be computed until token t is chosen.

The Transformer makes training parallel. Generation stays sequential. The paper lists "making generation less sequential" as future work (§7).
② Core idea

Training: one forward pass gives m predictions and m loss terms

The decoder input is the reference translation shifted right by one (teacher forcing). Masked self-attention stops each position from seeing later tokens, so every position can be trained at the same time.

Loss: cross-entropy at each position against the next reference token, with label smoothing εls = 0.1 (§5.4). Batches hold about 25,000 source + 25,000 target tokens.

② Core idea

Generation: one token per decoder pass, fed back in

The encoder runs once on the source. Then the decoder runs repeatedly: each pass reads the tokens generated so far plus the encoder memory, and predicts the next token, which is appended to the input. Step through it.

② Core idea

Beam search: keep the 4 best partial translations toy probabilities

Instead of greedily keeping only the single best token at each step, the paper keeps a beam of 4 hypotheses, extends each, and keeps the 4 highest-scoring by total log-probability. Finished hypotheses are ranked with a length penalty (α = 0.6).

In the paper · §3, §6.1, §7

The paper's wording

§3: "At each step the model is auto-regressive, consuming the previously generated symbols as additional input when generating the next."
§6.1: "We used beam search with a beam size of 4 and length penalty α = 0.6 … We set the maximum output length during inference to input length + 50, but terminate early when possible." Base models average the last 5 checkpoints and big models the last 20.
§7: "Making generation less sequential is another research goals of ours."
Recap

Training vs generation in two lines

Problem: fast training needs parallelism, but generated tokens only become known one at a time.
Core idea: train on all m positions in one masked, teacher-forced pass; generate left to right with beam search (size 4, α = 0.6).
