Parallel training vs autoregressive generation

Why the Transformer trains on every target position at once, but still has to generate translations one token at a time.

What is the problem?An RNN is sequential in both training and inference. Fast training needs every position processed at once, but generated tokens only become known one by one.
Core ideaIn training, feed the whole reference target (shifted right) and use masking, so all m predictions come from one parallel pass. At inference, generate left to right, using beam search.
1 · Problem

Count the sequential steps for one target sentence

For a target of m tokens: an RNN decoder needs m dependent steps even in training. A Transformer decoder needs one parallel pass in training, but m passes when generating, because token t+1 can't be computed until token t is chosen.

The Transformer makes training parallel. Generation stays sequential. The paper lists "making generation less sequential" as future work (§7).
2 · Limitation

Two constraints pull in opposite directions

Generation is inherently sequential

Token t+1 depends on token t, which doesn't exist until it has been chosen.

RNNs copy that structure into training

An RNN decoder computes ht from ht−1, so even with the reference translation available, training takes m dependent steps.

Greedy decoding can't recover

Choosing only the single most likely token at each step locks in early mistakes.

4 · Core idea

Training: one forward pass gives m predictions and m loss terms

The decoder input is the reference translation shifted right by one (teacher forcing). Masked self-attention stops each position from seeing later tokens, so every position can be trained at the same time.

Loss: cross-entropy at each position against the next reference token, with label smoothing εls = 0.1 (§5.4). Batches hold about 25,000 source + 25,000 target tokens.

5 · How it works

Generation: one token per decoder pass, fed back in

The encoder runs once on the source. Then the decoder runs repeatedly: each pass reads the tokens generated so far plus the encoder memory, and predicts the next token, which is appended to the input. Step through it.

5 · How it works

Beam search: keep the 4 best partial translations toy probabilities

Instead of greedily keeping only the single best token at each step, the paper keeps a beam of 4 hypotheses, extends each, and keeps the 4 highest-scoring by total log-probability. Finished hypotheses are ranked with a length penalty (α = 0.6).

5 · How it works from the paper · §3, §6.1, §7

The paper's wording

§3: "At each step the model is auto-regressive, consuming the previously generated symbols as additional input when generating the next."
§6.1: "We used beam search with a beam size of 4 and length penalty α = 0.6 … We set the maximum output length during inference to input length + 50, but terminate early when possible." Base models average the last 5 checkpoints and big models the last 20.
§7: "Making generation less sequential is another research goals of ours."
6 · Why it works

Why it works

The same context in training and at inference

Masking plus shift-right means each position conditions only on earlier tokens, just as it will when generating.

m loss terms from one pass

Every target position contributes to the loss in a single parallel forward and backward pass, so GPUs stay busy.

Beam search hedges

Keeping 4 hypotheses lets the decoder recover from a locally attractive but globally poor token.

Length penalty

Summed log-probabilities favour shorter outputs; dividing by lp(Y) with α = 0.6 counters that bias.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Transformers generate all output tokens at once."

Only training is parallel across positions. Generation produces one token per decoder pass (§3: "auto-regressive").

"Teacher forcing lets the model see the token it is predicting."

It sees only the previous reference tokens. Shift-right plus the mask hide the current and future ones.

"Beam search finds the best possible translation."

It is an approximate search that keeps only the 4 best partial hypotheses at each step.

Input length + 50, terminating early when possible.

How many encoder passes and how many decoder passes does it take to generate a 20-token translation?

1 encoder pass (the source is fixed) and one decoder pass per generated token, about 20 (21 including the end token).
9 · Key takeaway

Key takeaway

Train with the reference shifted right and masked, so all positions train in one pass. Generate one token at a time, with beam search.
Say it in 30 seconds

In training the decoder receives the reference translation shifted right, and masked self-attention stops any position from seeing later tokens, so all m positions are predicted and trained in one parallel pass. At inference the model is auto-regressive: the encoder runs once, then the decoder runs once per output token, feeding each prediction back in. The paper decodes with beam size 4, length penalty α = 0.6, and a maximum length of input + 50.
