Attention Is All You Need · 09

Masked self-attention

How the decoder is stopped from seeing future target tokens, so a model trained on whole sentences can still generate one token at a time.

What is the problem?During training the decoder is given the whole target sentence. If position i could attend to position i+1, it would simply copy the answer.
Core ideaShift the target right by one, and set every score for a future position to −∞ before the softmax. Position i can then use only positions ≤ i.
1 · Problem

At inference the model must predict without seeing the future

Generation is left to right

When producing token i, tokens i+1, i+2, … don't exist yet.

Training should match inference

If the model learns to rely on future tokens in training, it fails at test time.

But training should be parallel

We want to train every target position at the same time (deck 12).

How can every position be trained at once while each one only uses what came before it?
2 · Limitation

If the decoder can see ahead, it learns to copy

The decoder input is the target shifted right (start token first), and position i must predict target token i. Unmasked self-attention lets position i read the input at position i+1, which is the token it is supposed to predict. Training would look perfect, and generation would fail because that future token doesn't exist yet.

4 · Core idea

Shift right + mask: position i sees only positions ≤ i

The mask is a lower-triangular pattern. Scores above the diagonal are replaced by −∞, so after the softmax their weights are exactly 0. Drag the position to see each row of the mask.

At a glance

Training sees the whole target but each position only sees its past.

5 · How it works

The masked softmax, computed live

The same scaled dot-product attention as deck 05, with one extra step between the scaling and the softmax. Step through it.

Because the mask is just −∞ entries in one matrix, all positions are still computed in parallel during training, and none of them can see the future (deck 12).
5 · How it works

Worked example: one masked row

Four target positions. Position 1 (second token) has raw scores [1.0, 2.0, 3.0, 0.5] against positions 0–3.

Worked example

  1. Mask positions 2 and 3 (future): [1.0, 2.0, −∞, −∞].
  2. softmax = [0.269, 0.731, 0, 0].
  3. Without the mask the row would be [0.085, 0.232, 0.631, 0.052]: most weight on a future token, which would let the model copy the answer.
  4. All 4 rows are computed in one pass; the mask makes that equivalent to 4 sequential steps.
Masking turns one parallel pass into m correct next-token predictions.
5 · How it works from the paper · §3.1, §3.2.3, Figure 2

The paper's wording

§3.1: "We also modify the self-attention sub-layer in the decoder stack to prevent positions from attending to subsequent positions. This masking, combined with fact that the output embeddings are offset by one position, ensures that the predictions for position i can depend only on the known outputs at positions less than i."
§3.2.3: "We need to prevent leftward information flow in the decoder to preserve the auto-regressive property. We implement this inside of scaled dot-product attention by masking out (setting to −∞) all values in the input of the softmax which correspond to illegal connections."

6 · Why it works

Why it works

Training sees what inference sees

With the mask and the shift-right input, position i depends only on positions < i in the target, exactly the information available when generating.

Still fully parallel

The mask is just −∞ entries in one n × n matrix, so all positions are still computed in one pass.

Exact zeros, proper distribution

e−∞ = 0, so masked positions get exactly 0 weight and each row still sums to 1 over visible positions.

Cheap

No extra parameters, and only one extra step (Figure 2's optional "Mask") before the softmax.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"The mask is applied to the attention weights after the softmax."

It is applied to the scores before the softmax, by setting illegal entries to −∞ (§3.2.3).

"Masking means the decoder can't see the source sentence."

Only the decoder's self-attention is masked. Encoder-decoder attention sees all source positions.

"The mask alone stops the model from cheating."

You also need the shift-right: without it, position i would still see its own target token. The paper combines both (§3.1).
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Mask = lower-triangular. Position i sees 0…i.
  • Shift right. Input at i is target i−1, so the prediction at i is target i.
  • Same mask at inference. There, future tokens simply don't exist yet.

⚠ Traps

  • Masking after softmax. Weights must be zeroed before normalization.
  • Masking the encoder. The encoder is bidirectional.
  • Off-by-one shifts. Without the shift the model sees the token it must predict.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

In masked self-attention, position 3 (0-indexed) can attend to which positions?

0–3: itself and everything before it.

What weight does a masked (−∞) score get after the softmax?

Exactly 0, since e−∞ = 0.

Why is the shift-right needed in addition to the mask?

Without it, decoder input position i would hold target token i, the very token it must predict. Shifting right by one (start token first) means position i holds token i−1.
9 · Key takeaway

Key takeaway

Shift the target right and put −∞ above the diagonal: every position trains in parallel, yet only ever sees the past.
Say it in 30 seconds

At inference the decoder generates left to right, so in training a position must not see later tokens. The paper shifts the decoder input right by one and, inside scaled dot-product attention, sets the scores for future positions to −∞ before the softmax, which gives them exactly zero weight. Position i then depends only on positions before i, while all positions are still trained in one parallel pass.

Problem: with the full target visible in training, an unmasked decoder could copy future tokens.
Core idea: output embeddings offset by one, plus −∞ on future scores, means position i depends only on positions < i in the target, while every position is still trained in parallel.
