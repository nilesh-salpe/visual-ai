Text extraction

Turning raw HTML (HyperText Markup Language) into the main text of a page: removing scripts, menus, buttons and cookie banners, and identifying the language, before any quality filtering.

What is the problem?A web page is mostly markup and boilerplate. Naive tag stripping keeps navigation, footers, share buttons and consent banners, repeated on every page of a site.
Core ideaRemove non-content markup (scripts, styles), split the page into blocks, and keep blocks that look like prose: low link density, enough words, no boilerplate phrases. Libraries such as trafilatura do this robustly. Then run language identification (for example fastText's 176-language model).

2 · Limitation

Why naive extraction fails

Leaked code

Script and style contents appear as text if not removed first.

Boilerplate repeated

Menus, footers and banners repeat on every page of a site: huge duplicate n-gram counts.

Lost structure

Tables, lists, code and math need special handling to stay readable.

4 · Core idea

Strip, split, score

Strip

Remove <script>, <style>, comments and hidden elements.

Split

Break into blocks at block-level tags; compute words, link density, position, punctuation.

Score and keep

Keep prose-like blocks; extractors like jusText and trafilatura combine many such cues with rules or models.

At a glance

FineWeb: extracting from WARC (Web ARChive format) with trafilatura beat Common Crawl's WET (plain text extracted from Web ARChive records) text.

5 · How it works

Worked example: one blog page

Notebook 03's page: a title, a navigation bar, two article paragraphs, share buttons, a cookie notice and a footer.

Worked example

  1. Raw HTML: 835 characters. Naive tag stripping: 488 characters, including the CSS (Cascading Style Sheets) rule, the script's string, "Home | Blog | About | Log in", "Tweet Share" and the cookie notice.
  2. Block view: the navigation bar has link density above 0.6 (most of its text is link text); the paragraphs have 0.
  3. Keeping blocks with link density < 0.3, ≥ 8 words and no boilerplate phrase leaves the headline and two paragraphs: 292 characters.
  4. At web scale, the same menu text would otherwise appear on every page of the site, creating massive duplication.
Good extraction removes most characters of a page and almost none of its content.
6 · Why it works

Why good extraction pays off

Cleaner tokens

Less boilerplate means more of the token budget goes to content.

Fewer duplicates

Site-wide menus and footers are the most repeated text on the web.

Measurable

FineWeb's ablations showed better downstream scores with trafilatura on WARC than with WET.

Enables later filters

Quality rules and classifiers work far better on clean main text.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Extraction is a solved preprocessing detail."

It changes downstream benchmark scores measurably and needs special cases for code, math and tables.

"WET files are good enough."

They are a fine start but keep much more boilerplate than modern extractors.

"Language ID (identifier) is trivial."

Short, mixed or boilerplate-heavy text is easily misidentified; run it on extracted text.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Link density. Characters inside <a> ÷ all characters; menus are near 1.
  • Prefer WARC + extractor. Over WET text (FineWeb ablation).
  • Language ID on extracted text. Boilerplate in another language confuses it.

⚠ Traps

  • Stripping tags with regex alone. Scripts and styles leak in as "text".
  • Dropping code and math blocks. Generic extractors can destroy them; Llama 3 built domain-specific extraction.
  • Over-aggressive removal. Short legitimate paragraphs (captions, lists) can be lost.

9 · Key takeaway

Key takeaway

Text extraction strips markup, splits pages into blocks and keeps prose-like ones (low link density, enough words), then identifies the language; better extraction measurably improves models.
Say it in 30 seconds

Web pages are mostly markup, scripts and boilerplate, and naive tag stripping keeps menus, buttons and cookie notices that repeat on every page of a site. Extraction first removes scripts and styles, then splits the page into blocks and keeps those that look like prose, using cues such as link density, the share of a block's text that is link text, block length and boilerplate phrases. Libraries such as trafilatura do this robustly, and FineWeb found extracting from raw WARC files beat Common Crawl's own text. A language identifier such as fastText then routes each document by language.
