Evaluating LLMs · 02

Benchmarks and their failure modes

Multiple-choice, generative, code and agentic benchmarks: how each is scored, what it really measures, and why benchmarks saturate and get replaced.

What is the problem?Benchmarks are how the field measures progress, but each format has blind spots, and once models approach the ceiling a benchmark stops telling models apart.
Core ideaPick benchmarks whose format matches the capability (recognize vs produce vs act), check how answers are scored, know the chance and expert baselines, and move to harder or fresher sets as a benchmark saturates.
1 · Problem

Four kinds of benchmark

Multiple choice (MMLU, GPQA)

Pick one of the given options. Cheap and unambiguous to score, but measures recognition, and a random guess already scores 1/(number of options).

Short answer (GSM8K)

Produce a final answer (a number) that is compared with the reference. 8.5K grade-school maths word problems; scoring depends on extracting the answer correctly.

Code with tests (HumanEval)

164 hand-written programming problems; the generated function must pass unit tests. Functional correctness instead of text similarity.

Agentic (SWE-bench)

2,294 real GitHub issues: edit a repository so the project's tests pass. Measures multi-step work in a realistic environment; at release the best model, Claude 2, solved 1.96%.

2 · Limitation

How benchmarks fail

Saturation

Once top models score near the ceiling (or near the label-noise limit), differences shrink into the error bars and the benchmark stops ranking models.

Shortcuts

With 4 options, eliminating two weak distractors gives 50% without knowing the answer. MMLU-Pro (MMLU = Massive Multitask Language Understanding) raised options from 4 to 10 and accuracy dropped by 16–33%.

Contamination and label errors

Public test sets leak into training data (deck 05), and some "correct" answers are themselves wrong, which caps the achievable score.

3 · Your turn

Read the baselines

Pick an answer before moving on. Committing to a guess, even a wrong one, makes the real answer stick.

GPQA (Graduate-level Google-Proof Q&A benchmark) reports experts at 65%, skilled non-experts with web access at 34%, and GPT-4 at 39%. What makes GPQA useful as a benchmark?

B. "Google-proof": the large gap between experts (65%) and skilled non-experts with unrestricted web access (34%, near the 25% chance level) means retrieval alone doesn't solve it, so it still separates strong models.
4 · Core idea

Know the floor, the ceiling and the format

Floor

Chance level: 25% for 4 options, 10% for 10. MMLU's original paper: GPT-3 175B improved over random chance "by almost 20 percentage points on average".

Ceiling

Expert accuracy and label noise. If experts score 65% (GPQA) or some labels are wrong, 100% is neither expected nor meaningful.

Format fit

Recognize (multiple choice), produce (short answer, code), or act over many steps (agents). Use the format closest to how the model will be used.

Scoring multiple choice

Two common ways: compare the model's log-probability of each option (or option letter) and take the highest, or let the model generate an answer and parse the letter. They can give different scores for the same model: the first never fails to produce a valid answer, the second also tests instruction following and can lose points to parsing errors. Harnesses differ here, which is one reason published numbers disagree.

At a glance

Each benchmark lives until its scores stop separating models.

5 · How it works

Worked example: how guessing inflates multiple choice

A model truly knows 50% of the answers and guesses uniformly on the rest.

Worked example

  1. 4 options: 0.5 + 0.5 × 1/4 = 62.5%.
  2. 4 options, one distractor eliminated: 0.5 + 0.5 × 1/3 = 66.7%.
  3. 10 options (MMLU-Pro): 0.5 + 0.5 × 1/10 = 55.0%.
  4. Chance-corrected knowledge from a 4-option score s: (s − 0.25) / 0.75; e.g. s = 62.5% → 50%.
More options lower the floor, so scores reflect knowledge more; part of why MMLU-Pro scores are 16–33% lower.
6 · Why it works

Why benchmarks keep being replaced

Progress compresses scores

Near the ceiling, gaps between models fall inside the error bars, so the benchmark no longer ranks them.

Harder versions restore spread

More options (MMLU-Pro), expert-only questions (GPQA) and realistic tasks (SWE-bench) re-open the range.

Fresh sets fight leakage

The longer a test set is public, the more likely it is in training data. New or held-out sets restore trust.

Usage moves on

As models are used as agents and coders, benchmarks shift from recognizing answers to doing work end to end.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"25% on a 4-option benchmark means the model knows a quarter of the material."

25% is what random guessing gets. Knowledge shows up only above the chance floor.

"A model at 90% on a saturated benchmark is clearly better than one at 88%."

Near the ceiling, a 2-point gap may be within the error bars or caused by label noise and prompt format.

"Multiple-choice accuracy shows the model can produce the answer."

It shows the model can recognize the answer among options. Producing it unaided is a harder, different skill.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Subtract chance. (score − 1/k) / (1 − 1/k) for k options.
  • Know the expert ceiling. GPQA: experts 65%, so 100% isn't the target.
  • Match the format to the use. Recognize (MCQ (multiple-choice question)), produce (short answer, code), act (agents).

⚠ Traps

  • MCQ = can produce the answer. It measures recognition among options.
  • Small gaps on saturated sets. Often inside the error bars or label noise.
  • Ignoring the scoring rule. Log-prob vs parsed generation can disagree for the same model.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

MMLU-Pro increased the number of options to…

10, lowering the chance floor to 10%, and accuracy dropped 16–33%.

Why can log-prob scoring and generation scoring disagree on the same multiple-choice benchmark?

Log-prob scoring always yields a valid choice; generation can produce unparseable or differently formatted answers and also depends on instruction following and the parser.

What does SWE-bench measure that HumanEval doesn't?

Working in a real repository on real issues: finding the relevant code, making multi-file edits and passing the project's own tests, rather than writing one standalone function.
9 · Key takeaway

Key takeaway

Choose benchmarks by format (recognize, produce, act), read them against chance and expert baselines, and expect saturation, shortcuts and leakage to retire them.
Say it in 30 seconds

Benchmarks differ in what they measure. Multiple-choice sets like MMLU test recognition and have a guessing floor; short-answer sets like GSM8K test producing an answer; HumanEval checks code with unit tests; SWE-bench asks a model to resolve real GitHub issues, where the best model at release solved under 2 percent. Scores must be read against chance and expert levels: on GPQA experts score 65 percent and skilled non-experts with web search only 34. As models improve, benchmarks saturate, shortcuts appear and test sets leak, so harder versions like MMLU-Pro, with ten options and 16 to 33 percent lower scores, replace them.
