Rerankers

The second stage of retrieval: a slower, more accurate model rereads the query together with each candidate and reorders a short list. Cross-encoders, late interaction (ColBERT) and LLM (large language model) rerankers.

What is the problem?First-stage retrieval (BM25 (Okapi Best Matching 25 ranking function) or a bi-encoder) scores query and document independently, so it is fast but misses fine-grained relevance. The top 20 chunks you hand the LLM often contain near-misses while the best passage sits at rank 60.
Core ideaRetrieve many cheaply, rerank few carefully. Fetch around 100-150 candidates, score each with a model that reads query and document together (a cross-encoder), keep the best 20. Anthropic's tests: top-20 failures fell from 2.9% to 1.9% when reranking was added to contextual hybrid search. Variants trade accuracy for speed: late interaction (ColBERT) and listwise LLM reranking (RankGPT).

1 · Problem

Independent scoring misses relevance

One vector per text

A bi-encoder squeezes a passage into one vector before it has seen the query.

Lexical blind spots

BM25 matches words, not meaning; dense search matches meaning, not exact terms.

Recall vs precision

Wide top-k improves recall but floods the LLM context with noise and cost.

2 · Core idea

Two stages: wide recall, then precision

Why not cross-encode everything

Sentence-BERT's example: finding the most similar pair among 10,000 sentences takes ~65 hours with a BERT (Bidirectional Encoder Representations from Transformers) cross-encoder, ~5 seconds with a bi-encoder.

Cross-encoder

monoBERT feeds [query; passage] to BERT and outputs a relevance score: +27% relative MRR (mean reciprocal rank)@10 on MS MARCO (Microsoft Machine Reading Comprehension) when it was published.

Late interaction

ColBERT keeps one embedding per token, precomputes documents and scores with MaxSim: competitive with BERT rerankers, two orders of magnitude faster.

LLM reranking

RankGPT asks an LLM for a permutation of passages with a sliding window over BM25's top 100; distilled into a 440M model it beats a 3B supervised reranker on BEIR.

7 · Challenges in production

In production

Measure both stages

Track recall@150 for the first stage and nDCG@10 (normalised discounted cumulative gain) after reranking.

Latency budget

An agent may search several times per task; budget the reranker per call.

Distil

Use an LLM reranker offline to label data, then train a small cross-encoder for serving, as RankGPT did.

Structured documents

Format semi-structured records consistently (Cohere recommends YAML (YAML Ain't Markup Language) strings) so the reranker sees the fields.

Further reading

Key papers

The primary sources behind this deck, each with what it contributed. Links go to the paper (arXiv or the conference page).

Sentence-BERT: Sentence Embeddings using Siamese BERT-Networks
Reimers & Gurevych · EMNLP 2019

A bi-encoder producing one embedding per sentence, compared by cosine similarity.

Remember: most similar pair among 10,000 sentences takes ~65 h with a BERT cross-encoder vs ~5 s with SBERT
Passage Re-ranking with BERT
Nogueira & Cho · arXiv 2019

A BERT cross-encoder reads query and passage together and outputs a relevance score; used to rerank BM25 candidates.

Remember: +27% relative MRR@10 over the previous state of the art on MS MARCO
ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction over BERT
Khattab & Zaharia · SIGIR 2020

Late interaction: query and document are encoded separately into token embeddings (documents offline), then scored by summing each query token's maximum similarity (MaxSim).

Remember: competitive with BERT rerankers, two orders of magnitude faster, four orders fewer FLOPs (floating-point operations) per query
Is ChatGPT Good at Search? Investigating Large Language Models as Re-Ranking Agents
Sun et al. · EMNLP 2023

Listwise reranking by an instructed LLM that outputs a permutation, applied with a sliding window over BM25's top 100; the ranking ability distils into small models.

Remember: a distilled 440M model beats a 3B supervised reranker on BEIR
Reciprocal Rank Fusion outperforms Condorcet and individual Rank Learning Methods
Cormack, Clarke & Büttcher · SIGIR 2009

Fuse several rankings by score(d) = Σ 1/(k + rank_r(d)) with k = 60; simple, training-free and better than the individual rankings.

Introducing Contextual Retrieval
Anthropic · Anthropic News 2024

Prepend 50-100 tokens of chunk-specific context (written by an LLM from the whole document) before embedding and BM25 indexing; retrieve top 150, rerank, keep 20. Knowledge bases under 200,000 tokens can go straight into the prompt.

Remember: top-20 retrieval failures 5.7% → 3.7% (−35%), 2.9% with BM25 (−49%), 1.9% with reranking (−67%); $1.02 per million document tokens
Rerank overview
Cohere documentation · docs.cohere.com 2026

A hosted reranker API that orders documents by relevance to a query and returns a relevance score per document; structured documents are best passed as YAML strings.
