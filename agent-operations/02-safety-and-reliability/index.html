Visual Agents · Operations · 02

Safety and reliability

Agents read untrusted content and hold real permissions. Indirect prompt injection, least privilege, sandboxing, human confirmation, and the engineering that keeps long-running agents dependable.

What is the problem?An agent that browses, reads email or calls tools processes text written by strangers. Instructions hidden in that text can hijack it, and its permissions make the damage real: data exfiltration, unwanted purchases, deleted files.
Core ideaAssume tool outputs are untrusted data, not instructions. Contain the blast radius with least privilege, sandboxing and allowlists; require human confirmation for consequential actions; detect attacks with classifiers and monitoring; and engineer reliability with timeouts, idempotent retries, checkpoints and audit logs.

1 · Problem

Untrusted input + real permissions

Indirect prompt injection

Greshake et al.: prompts planted in data the app retrieves can override instructions: data theft, worming, manipulation.

Real side effects

Agents send messages, move money, change files.

Long runs

More steps mean more chances for a failure or an attack to occur.

2 · Core idea

Defence in depth

Least privilege

Each tool gets only the access the task needs, per user.

Isolation

Sandboxed VMs (virtual machines) or containers; network allowlists; no sensitive credentials in reach (Anthropic computer-use guidance).

Human in the loop

Confirm consequential actions; MCP (Model Context Protocol) says hosts SHOULD let a human deny tool invocations.

Detection and testing

Classifiers on tool outputs; red-team with AgentDojo-style suites (97 tasks, 629 security test cases).

7 · Challenges in production

In production

Red-teaming

Test against injection suites before launch and after every change.

Monitoring

Alert on unusual tool sequences, new domains, spikes in actions.

Incident response

Audit logs, kill switches and credential revocation ready before you need them.

User clarity

Show what the agent is doing and why; make approvals informative.
