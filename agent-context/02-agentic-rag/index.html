Agentic retrieval (RAG)

From retrieve-once-then-generate to agents that decide when and what to retrieve, check what they found, refine queries, and cite sources.

What is the problem?Classic RAG (retrieval-augmented generation) retrieves once from the user's question. Multi-hop questions, vague queries and bad retrieval results then lead straight to wrong, confident answers.
Core ideaMake retrieval a tool the agent calls repeatedly: plan queries, retrieve, grade relevance, rewrite or broaden the query, fall back to other sources, and answer with citations. Self-RAG trains the model to decide when to retrieve and critique; CRAG (Corrective Retrieval Augmented Generation) adds an evaluator and corrective web search.

1 · Problem

One retrieval is often not enough

Multi-hop questions

The second query depends on the first answer.

Bad retrieval

Irrelevant chunks are used anyway (CRAG's motivation).

Unneeded retrieval

Retrieving a fixed number of passages regardless of need hurts versatility (Self-RAG's motivation).

2 · Core idea

Retrieval as a tool with feedback

Classic RAG

Lewis et al. (2020): a retriever over an index supplies passages to a generator.

Agentic loop

The agent decides whether to search, what query to send, and whether results suffice.

Self-critique

Self-RAG: reflection tokens to retrieve on demand and judge passages and its own output.

Correction

CRAG: a lightweight evaluator scores retrieval; poor results trigger refinement or web search.

5 · Trade-offs

Trade-offs

Choice Benefit Cost
Classic one-shot RAG one retrieval, low latency fails on multi-hop and bad retrieval
Agentic retrieval loop handles multi-hop, recovers from misses several model and search calls per question
Pre-built index fast, controlled corpus staleness; ingestion pipeline to maintain
Just-in-time fetching always fresh, no index slower; depends on live sources
Small chunks precise matches lose surrounding context; more chunks to read
6 · Failure modes

Failure modes

Failure Symptom Mitigation
Retrieval miss answers from memory or says unknown hybrid search, query rewriting, recall evals
Distracting passages answer swayed by irrelevant text grading and filtering; fewer, better passages
Citation hallucination cites passages that do not support the claim verify claim-passage support
Indirect prompt injection retrieved page instructs the agent treat retrieved text as data; restrict actions (Greshake et al.)
Search loops keeps re-searching similar queries budget; detect near-duplicate queries
7 · Challenges in production

In production

Freshness

Re-index on change; show document dates.

Access control

Retrieval must respect each user's document permissions.

Evaluate two things

Retrieval recall and answer faithfulness, separately.

Latency budgets

Each loop adds round trips; cap iterations for interactive use.

Further reading

Key papers

The primary sources behind this deck, each with what it contributed. Links go to the paper (arXiv or the conference page).

Retrieval-Augmented Generation for Knowledge-Intensive NLP (natural language processing) Tasks
Lewis et al. · NeurIPS 2020

Combines a seq2seq generator with a dense retriever over Wikipedia (non-parametric memory), trained end to end.

Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection
Asai et al. · ICLR 2024

Trains the model to decide when to retrieve and to critique retrieved passages and its own output with reflection tokens.

Corrective Retrieval Augmented Generation
Yan et al. · arXiv 2024

A lightweight evaluator grades retrieved documents and triggers corrective actions (refinement or web search) when retrieval is poor.

Not what you've signed up for: Compromising Real-World LLM-Integrated (LLM = large language model) Applications with Indirect Prompt Injection
Greshake et al. · AISec 2023

Instructions planted in data the application retrieves (web pages, emails, documents) can hijack LLM-integrated apps: data theft, worming, manipulation.
