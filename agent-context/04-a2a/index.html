Agent2Agent protocol (A2A)

An open protocol for agents built by different teams and vendors to discover each other, delegate tasks and stream results, without sharing their internals. Pinned to A2A v1.0.

What is the problem?An agent that needs help from another organisation's agent has no standard way to find it, learn what it can do, hand it a long-running task, follow progress, or receive files back. Wrapping every remote agent as a custom tool repeats that integration for each pair.
Core ideaEach agent publishes an Agent Card (its skills, endpoints, capabilities and security schemes). A client agent sends a Message made of Parts; the remote agent answers with a Message or a Task that moves through a lifecycle and produces Artifacts. Agents stay opaque: they cooperate without sharing memory, tools or plans. MCP (Model Context Protocol) connects an agent to tools and data; A2A connects agents to agents.

1 · Problem

Agents from different builders cannot cooperate

Discovery

No standard place to learn what a remote agent does, where it lives and how to authenticate.

Long-running work

Delegated work may take hours and need more input midway; a single request-response call does not fit.

Opaque partners

Vendors will not expose their prompts, tools or memory; integration must work through a narrow interface.

2 · Core idea

Cards, messages, tasks, artifacts

Agent Card

A JSON (JavaScript Object Notation) document at https://{domain}/.well-known/agent-card.json: name, description, supportedInterfaces (first is preferred), capabilities (streaming, push notifications), skills, securitySchemes.

Message and Part

A turn with a role (user or agent) and Parts; each Part holds exactly one of text, raw bytes, a url or structured data.

Task

The unit of work: id, contextId, status, artifacts and history. A contextId groups related tasks and messages into one conversation.

Artifact

An output of a task, itself made of Parts: a report, a file, structured data.

Google announced A2A on 9 April 2025 with more than 50 partners; the project moved to the Linux Foundation, released v1.0 in March 2026, and by April 2026 had more than 150 supporting organisations.

5 · Trade-offs

Trade-offs

Choice Benefit Cost
A2A between agents one interface for any vendor's agent; long tasks, streaming, push another protocol to operate and secure
Remote agent as an MCP tool simple when the work is a quick function call no task lifecycle, negotiation or partial results
Opaque agents vendors keep their internals; loose coupling harder to debug across the boundary
Streaming (SSE) live progress long-lived connections
Push notifications no open connection for hours-long tasks webhook endpoints to secure and keep reachable
6 · Failure modes

Failure modes

Failure Symptom Mitigation
Spoofed or tampered Agent Card client sends data to an impostor TLS (Transport Layer Security), signed Agent Cards (JWS (JSON Web Signature)) verified by the client, allowlists of trusted agents
Forged webhook calls fake task updates injected agents MUST authenticate webhook calls; clients MUST validate them
Prompt injection across agents remote artifacts instruct the client agent treat artifacts as untrusted data, as with any tool output
Version mismatch v0.3 clients expect the removed kind field pin versions; 1.0 replaced kind with member names
Orphaned tasks work continues after the user gave up CancelTask, timeouts and budgets on delegated work
7 · Challenges in production

In production

Identity and auth

Use the declared security schemes (OAuth 2.0, OpenID Connect, mutual TLS); the extended Agent Card MUST require authentication.

Trace across agents

Propagate trace ids through contextId and metadata so a delegated task appears in one trace.

Budgets for delegation

A remote agent can spend your money: cap steps, time and cost per delegated task.

Platform support

Microsoft (Azure AI (artificial intelligence) Foundry, Copilot Studio) and AWS (Bedrock AgentCore Runtime) support A2A.

Agent2Agent (A2A) Protocol Specification (v1.0)
A2A Project · a2a-protocol.org 2026

Agent Cards at /.well-known/agent-card.json; Messages of Parts (exactly one of text, raw, url or data); Tasks with a lifecycle (SUBMITTED, WORKING, INPUT_REQUIRED, AUTH_REQUIRED, COMPLETED, FAILED, CANCELED, REJECTED) producing Artifacts; JSON-RPC, gRPC and HTTP+JSON bindings; streaming over SSE and push notifications. v1.0.0 released 12 March 2026.

An open protocol for agent-to-agent communication that complements MCP; built on HTTP, SSE and JSON-RPC; secure by default; long-running tasks; modality agnostic.
