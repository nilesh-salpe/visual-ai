RAG, fine-tuning or long context?

Three ways to give a model knowledge it lacks: retrieve it per query, train it into the weights, or put everything in the context window. What each is good at, what the evidence says, what a query costs, and how production systems combine them.

What is the problem?An assistant must answer from a company's documents, which change daily and were never in pretraining. Teams fine-tune "to teach it our data", or paste everything into a huge context window, and get stale facts, hallucinations or a large bill.
Core ideaMatch the tool to what is missing. Missing knowledge (facts that change, need citations or access control): retrieval. Missing behaviour (format, style, tool use, a domain's way of working): fine-tuning. A bounded set of documents that fits and is asked about repeatedly: long context with prompt caching. Production systems combine them: fine-tune for behaviour, retrieve for facts, and route each query to retrieval or long context.

1 · Problem

Three ways to add knowledge

Facts change

Prices, policies and tickets change daily; model weights are a snapshot from the last training run.

Fine-tuning teaches facts poorly

Ovadia et al.: retrieval beat unsupervised fine-tuning for both known and new facts. On new current-events questions, Mistral 7B scored 0.481 base, 0.504 fine-tuned (0.588 with paraphrased data) and 0.875 with retrieval.

Long context is not free

Every query pays for every token in the prompt, and accuracy and recall degrade as contexts grow (context rot). In RULER, only about half of 17 models claiming 32K+ context performed satisfactorily at 32K.

2 · Core idea

Match the tool to what is missing

What the model lacks Use Why
Facts that change, must be cited, or depend on who asks Retrieval (RAG (retrieval-augmented generation)) update the index, not the model; cite sources; filter by permissions
A format, style, tool-use habit or domain behaviour Fine-tuning (SFT (supervised fine-tuning), LoRA (Low-Rank Adaptation)) behaviour generalises from examples; facts are learned slowly and can increase hallucination
A bounded set of documents, asked about repeatedly Long context + prompt caching no retrieval misses; Anthropic suggests knowledge bases under 200,000 tokens can go straight into the prompt
Better use of retrieved documents in one domain Retrieval-aware fine-tuning (RAFT (retrieval-augmented fine-tuning)) train with distractor documents so the model learns to ignore irrelevant chunks and quote the right one

Gekhman et al. add a warning for fine-tuning on facts: examples with knowledge the model lacks are learned much more slowly and, once learned, linearly increase its tendency to hallucinate.

5 · Trade-offs

Trade-offs

Approach Strengths Weaknesses
Retrieval (RAG) fresh facts, citations, permission filtering, scales to any corpus size, cheap per query retrieval misses; chunking loses context; more moving parts
Fine-tuning reliable format and behaviour; shorter prompts; can specialise a small, cheap model facts go stale; new facts learned slowly and can raise hallucination; retraining for every update
Long context no retrieval misses; whole-document reasoning; simple to build cost and latency grow with every token; recall degrades with length and position; bounded by the window (up to 1M tokens on current Claude models)
Long context + caching repeat queries on a stable prefix are cheap and fast cache expires (5 minutes or 1 hour); any change before the cached prefix invalidates it
Hybrid (route per query) retrieval cost for easy queries, long-context quality for hard ones two paths to build, test and monitor
6 · Failure modes

Failure modes

Failure Symptom Mitigation
Fine-tuned on facts confident answers from last quarter's policy retrieve facts at query time; fine-tune for behaviour only
Retrieval miss "I can't find that" although the document exists hybrid search, contextual chunks, reranking; route misses to long context
Lost in the middle facts in the middle of a long prompt are ignored put key material at the start or end; retrieve to shorten the prompt
Distractor chunks the model answers from a similar but wrong document reranking; RAFT-style training with distractors; require quotes
Cache misses long-context bill far above estimates keep the prefix byte-identical; put variable content after the cache breakpoint
Permission leaks a user sees content from documents they cannot open filter retrieval by the user's permissions; never fine-tune on restricted data
7 · Challenges in production

In production

Start with retrieval

It is the default for enterprise knowledge: fresh, citable and permission-aware. See the enterprise RAG case study.

Fine-tune last, for behaviour

When prompts cannot fix format, tone or tool use, fine-tune (often LoRA) on examples of the behaviour, and keep facts in retrieval.

Long context for bounded tasks

One contract, one repository, one long report: put it all in, cache the prefix, and skip the retrieval pipeline.

Measure per path

Track answer quality, retrieval recall, tokens and cost separately for each path, and re-test when the model or the corpus changes.

Further reading

Key papers

The primary sources behind this deck, each with what it contributed. Links go to the paper (arXiv or the conference page).

Fine-Tuning or Retrieval? Comparing Knowledge Injection in LLMs (large language models)
Ovadia, Brief, Mishaeli, Elisha · arXiv (Microsoft) 2023

Retrieval consistently outperformed unsupervised fine-tuning for injecting both existing and new knowledge; training on many paraphrases of a fact helps fine-tuning.

Remember: current events, Mistral 7B: 0.481 base, 0.504 fine-tuned, 0.588 with paraphrases, 0.875 with RAG
Does Fine-Tuning LLMs on New Knowledge Encourage Hallucinations?
Gekhman et al. · EMNLP 2024

Fine-tuning examples with knowledge the model lacks are learned much more slowly than known ones and, once learned, linearly increase hallucination; early stopping mitigates it.

Remember: models acquire new facts through pretraining, mostly not fine-tuning
Retrieval Augmented Generation or Long-Context LLMs? A Comprehensive Study and Hybrid Approach
Li et al. · EMNLP Industry 2024

Long context beats RAG on average when resourced sufficiently, but RAG is far cheaper; Self-Route lets the model declare a query unanswerable from retrieved chunks and only then uses long context.

Remember: identical predictions on over 60% of queries; cost −65% (Gemini-1.5-Pro), −39% (GPT-4o)
RULER: What's the Real Context Size of Your Long-Context Language Models?
Hsieh et al. · COLM 2024

Synthetic long-context benchmark beyond needle-in-a-haystack (multi-key retrieval, multi-hop tracing, aggregation); models degrade sharply as length grows.

Remember: 17 models; only about half of those claiming 32K+ perform satisfactorily at 32K
Lost in the Middle: How Language Models Use Long Contexts
Liu et al. · TACL 2024

Performance is often highest when relevant information is at the beginning or end of the context and degrades when it is in the middle.

RAFT: Adapting Language Model to Domain Specific RAG
Zhang et al. · arXiv 2024

Fine-tune with questions, a golden document and distractor documents (and some examples with no golden document), with chain-of-thought answers that quote the source.

Remember: gains on PubMed, HotpotQA and Gorilla in-domain RAG
Retrieval-Augmented Generation for Knowledge-Intensive NLP (natural language processing) Tasks
Lewis et al. · NeurIPS 2020

Combines a seq2seq generator with a dense retriever over Wikipedia (non-parametric memory), trained end to end.

Introducing Contextual Retrieval
Anthropic · Anthropic News 2024

Prepend 50-100 tokens of chunk-specific context (written by an LLM from the whole document) before embedding and BM25 (Okapi Best Matching 25 ranking function) indexing; retrieve top 150, rerank, keep 20. Knowledge bases under 200,000 tokens can go straight into the prompt.

Remember: top-20 retrieval failures 5.7% → 3.7% (−35%), 2.9% with BM25 (−49%), 1.9% with reranking (−67%); $1.02 per million document tokens
Prompt caching
Anthropic documentation · platform.claude.com 2026

Reuse of cached prompt prefixes: 5-minute cache writes cost 1.25× base input, 1-hour writes 2×, and reads 0.1× on most models (lower on some newer ones).

Context windows (Claude documentation)
Anthropic · Claude platform docs 2026

Context window up to 1M tokens depending on the model; more context is not automatically better, because accuracy and recall degrade as token count grows (context rot).

Remember: up to 1M tokens; 200k on older models
LoRA: Low-Rank Adaptation of Large Language Models
Hu et al. · ICLR 2022

Freezes the pretrained weights and trains a low-rank update BA (B initialized to zero) that can be merged after training.

Remember: 10,000× fewer trainable parameters, 3× less GPU (graphics processing unit) memory (GPT-3 175B)
