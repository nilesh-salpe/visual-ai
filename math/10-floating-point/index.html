Floating-point numbers

How computers store real numbers as sign, exponent and mantissa, what precision and range each LLM (large language model) format gives, and the rounding effects that bite in training.

What is the problem?Models do trillions of arithmetic operations in formats with 32, 16 or even 8 bits. Every number is rounded, small updates can vanish, and large values can overflow.
Core ideaA float is (−1)ˢ × 1.mantissa × 2^(exponent − bias). Exponent bits set the range; mantissa bits set the precision (relative spacing 2⁻ᵐ). FP32 (32-bit floating point) has 8 + 23, BF16 (bfloat16, a 16-bit floating-point format with the exponent range of 32-bit floats) has 8 + 7 (same range, less precision), FP16 (16-bit floating point) has 5 + 10 (more precision, much less range).
1 · Problem

What does a number look like in bits?

Type a value and pick a format. The bits split into sign, exponent and mantissa; the readout shows the value actually stored and the rounding error.

2 · Limitation

Why not exact or fixed-point numbers?

Exact rationals

Unbounded size and far too slow for trillions of operations.

Fixed point

Integers with a fixed scale cannot cover both 10⁻⁸ gradients and 10⁴ activations.

Bits cost bandwidth

Every byte is memory, bandwidth and silicon; fewer bits per number means faster training and inference.

4 · Core idea

Sign, exponent, mantissa

Sign

1 bit: positive or negative.

Exponent

Stored with a bias; picks the power of two, so it sets the range. FP32/BF16: 8 bits. FP16: 5 bits.

Mantissa

Fraction bits after an implicit leading 1; sets relative precision. FP32: 23, FP16: 10, BF16: 7.

value = (−1)ˢ × (1 + mantissa / 2ᵐ) × 2^(exponent − bias)

At a glance

Spacing between neighbours grows with magnitude: relative error stays ≈ 2⁻ᵐ.

5 · How it works

Worked example: storing 0.1 and adding 10⁻⁴ to 1

Round to nearest in each format.

Worked example

  1. 0.1 in FP32 = 0.100000001490…; in BF16 = 0.10009765625; in FP16 = 0.0999755859375.
  2. Spacing just above 1: FP32 2⁻²³ ≈ 1.2 × 10⁻⁷, FP16 2⁻¹⁰ ≈ 9.8 × 10⁻⁴, BF16 2⁻⁷ ≈ 7.8 × 10⁻³.
  3. 1 + 10⁻⁴: FP32 gives 1.0001000; FP16 and BF16 both round back to 1.0: the update vanishes.
  4. Range: FP16 overflows above 65,504; BF16 and FP32 reach ≈ 3.4 × 10³⁸.
This is why training keeps FP32 master weights and accumulators while doing matmuls in 16 or 8 bits (Distributed deck 09).
6 · Why it works

Why low precision still works

Neural nets are noise-tolerant

Gradients are already noisy estimates; rounding error of 2⁻⁸ relative is small by comparison.

Range is what breaks training

BF16 keeps FP32's range, so Kalamkar et al. trained many model types without hyper-parameter changes.

Keep precision where it accumulates

Sums and weight updates stay in FP32, where small contributions would otherwise vanish.

Speed

Halving the bits roughly doubles Tensor Core throughput and halves memory traffic.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"BF16 is more precise than FP16."

BF16 has fewer mantissa bits (7 vs 10), so it is less precise; it has far more range.

"Floating-point addition is associative."

Rounding after each operation makes the order matter, which is why GPU (graphics processing unit) reductions can differ between runs.

"0.1 is stored exactly."

0.1 has no finite binary expansion; every format stores the nearest representable value.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Relative precision ≈ 2⁻ᵐ. m = mantissa bits.
  • BF16 = FP32 with the low 16 bits dropped. Same exponent, trivial conversion.
  • Sum small numbers first / in FP32. Reduces rounding error.

⚠ Traps

  • Comparing floats with ==. Use a tolerance.
  • Assuming addition is associative. (a + b) + c ≠ a + (b + c), so parallel reductions differ run to run.
  • Catastrophic cancellation. Subtracting nearly equal numbers loses most significant digits.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

How many mantissa bits does BF16 have?

7 (plus the implicit leading 1).

Why does adding a small update to a large weight in BF16 often do nothing?

The update is smaller than half the spacing between representable numbers near the weight, so the sum rounds back to the weight.

Which bits decide range and which decide precision?

Exponent bits decide range; mantissa bits decide relative precision.
9 · Key takeaway

Key takeaway

A float is sign × 1.mantissa × 2^exponent: exponent bits give range, mantissa bits give precision; LLMs compute in BF16/FP8 but keep sums and master weights in FP32.
Say it in 30 seconds

Computers store real numbers as a sign, an exponent that picks a power of two, and a mantissa that gives the significant digits. Exponent bits set the range and mantissa bits set the relative precision, about two to the minus number of mantissa bits. FP32 has eight exponent and twenty-three mantissa bits; BF16 keeps the eight exponent bits but only seven mantissa bits, so it has FP32's range with far less precision; FP16 has more precision but overflows at 65,504. Rounding means small updates can vanish and sums depend on order, so training keeps accumulators and master weights in FP32.

Problem: every number is rounded; range and precision are limited.
Core idea: exponent = range, mantissa = precision.
Practice: BF16/FP8 compute, FP32 accumulation.
