Math for LLMs · 02

Matrices and linear layers

What a matrix does to a vector, why every LLM (large language model) layer is mostly matrix multiplication, and how to count its shapes and FLOPs (floating-point operations).

What is the problem?A transformer layer has to turn every token's vector into new vectors: queries, keys, values, MLP (multilayer perceptron) features. Doing that one number at a time would be hopeless.
Core ideaA matrix W (d_in × d_out) maps a vector x to xW: each output is a dot product of x with one column. A linear layer is y = xW + b. Stacking tokens as rows turns a whole sequence into one matmul costing 2·m·k·n FLOPs (floating-point operations).
1 · Problem

What does a matrix do to space?

A 2 × 2 matrix moves every point of the plane. Edit its entries and watch the unit square (and the two basis vectors) transform. The determinant is the area scale.

The matrix [[a, b], [c, d]] sends (1, 0) to (a, c) and (0, 1) to (b, d): its columns are where the basis vectors land.

2 · Limitation

Why not process each number separately?

Features mix

A useful new feature depends on many input coordinates at once; that is exactly a weighted sum, a dot product.

Loops are slow

Element-by-element code wastes hardware; Tensor Cores need dense matrix blocks.

Sequences are batches

Every token gets the same transformation, so stacking tokens as rows turns thousands of vector ops into one matmul.

3 · Your turn

B. Inner dimensions (4,096) match and disappear; the result is (rows of X) × (columns of W). This is the MLP up-projection shape of Llama 2 7B.
4 · Core idea

A linear layer is a matmul plus a bias

Matrix-vector

y = xW: output j is the dot product of x with column j of W.

Matrix-matrix

Stack m inputs as rows of X: Y = XW computes all of them at once.

Bias and composition

y = xW + b. Two linear layers in a row collapse into one, which is why networks put nonlinearities between them.

Y (m × n) = X (m × k) · W (k × n) + b · cost 2·m·k·n FLOPs

At a glance

Inner dimensions must match; the outer ones give the result's shape.

5 · How it works

Worked example: one GPT-3 projection

GPT-3 175B uses d_model = 12,288 and 96 layers. Take one query projection Q = XW_Q for a 2,048-token sequence.

Worked example

  1. Shapes: X is 2,048 × 12,288, W_Q is 12,288 × 12,288, so Q is 2,048 × 12,288; W_Q holds 151M parameters.
  2. FLOPs: 2 × 2,048 × 12,288 × 12,288 ≈ 0.62 TFLOP (trillion floating-point operations) for this one matmul.
  3. Each layer has about 12·d² weights in its matrices (4d² attention, 8d² MLP): 1.81B per layer, × 96 ≈ 174B, nearly all of the 175B.
  4. So a forward pass costs about 2 FLOPs per parameter per token, and training about 6 (forward plus a backward that costs twice as much).
LLM compute is overwhelmingly matrix multiplication; shapes tell you both the parameter count and the cost.
6 · Why it works

Why matrices are the workhorse

Expressive

Any linear map between vector spaces is a matrix; with nonlinearities in between, stacks of them approximate almost any function.

Hardware-friendly

Matmuls reuse each loaded number many times, so they run near peak on GPUs (graphics processing units).

Easy to differentiate

The gradient of XW is another matmul: dW = Xᵀ·dY, dX = dY·Wᵀ.

Easy to count

Shapes give parameters and FLOPs directly, which is how model and training budgets are planned.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"A matrix just scales a vector."

It can rotate, stretch along different directions, shear and project; only diagonal matrices scale coordinates independently.

"Stacking linear layers makes a deeper, more powerful model."

Without nonlinearities, W₁W₂ is just another matrix: the stack is still one linear layer.

"Matmul cost depends only on the parameter count."

It is 2·m·k·n: proportional to parameters × tokens processed.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • (m × k)(k × n) = (m × n), 2mkn FLOPs. One multiply and one add per term.
  • Parameters ≈ 12·L·d². For a standard transformer, ignoring embeddings.
  • Forward ≈ 2N, training ≈ 6N FLOPs per token. N = parameters.

⚠ Traps

  • Mixing up row and column conventions. PyTorch stores nn.Linear weights as (out, in) and computes xWᵀ.
  • Counting a multiply-add as 1 FLOP. Most papers count it as 2.
  • Thinking matrices only scale. They rotate, stretch, shear and project, and can lose information (rank).

Why do networks need nonlinearities between linear layers?

Because the product of matrices is a matrix: without them the whole stack is a single linear map.

Roughly how many parameters does a transformer with L layers and width d have?

About 12·L·d² (plus embeddings).
9 · Key takeaway

Key takeaway

A matrix maps vectors by dot products with its columns; LLM layers are stacks of matmuls whose shapes give parameters (≈12d² per layer) and cost (2mkn FLOPs).
Say it in 30 seconds

Each output of a matrix-vector product is a dot product of the input with one column, so a matrix mixes all input features into each output feature. A linear layer is that plus a bias. Stacking tokens as rows makes a whole sequence one matrix multiplication, which costs two FLOPs per multiply-add: 2·m·k·n. A standard transformer layer has about 12d² weights in its attention and MLP matrices, which is why GPT-3 with d = 12,288 and 96 layers has about 175 billion parameters, and why a forward pass costs about 2 FLOPs per parameter per token.
