Derivatives and the chain rule

How a model finds which way to nudge billions of weights: local derivatives, the chain rule over a computational graph, and why backpropagation costs only about one extra pass.

What is the problem?Training needs ∂loss/∂w for every one of billions of weights, and the loss depends on each weight through a long chain of operations.
Core ideaBreak the computation into simple nodes with known local derivatives. The chain rule says the derivative along a path is the product of local derivatives, summed over paths. Running it from the loss backwards (reverse-mode autodiff, i.e. backprop) yields all gradients in one sweep.
1 · Problem

Which way should each input move?

The graph computes L = (w·x + b − y)² for one data point. Move w and b: the forward values flow right, and the gradients (orange) flow back, each the product of local derivatives.

2 · Limitation

Why not estimate gradients numerically?

One pass per weight

Finite differences nudge each weight separately: 7 billion weights means 7 billion forward passes per step.

Inaccurate

Too large an ε gives approximation error, too small gives floating-point cancellation.

Symbolic is huge

Writing out the derivative formula of a deep network symbolically explodes in size.

4 · Core idea

Local derivatives, multiplied and summed

Local derivative

Each node knows its own derivative: d(sin u)/du = cos u, d(u·v)/du = v, d(u²)/du = 2u.

Chain rule

Along a path, multiply: ∂f/∂x = ∂f/∂c · ∂c/∂a · ∂a/∂x.

Multiple paths

If x feeds several nodes, add the path contributions. Reverse mode accumulates these sums node by node.

∂L/∂x = Σ over paths Π (local derivatives along the path)

At a glance

Reverse mode suits LLMs (large language models): one scalar output, billions of inputs.

5 · How it works

Forward mode vs reverse mode

Forward modeReverse mode (backprop)
Directioninputs → outputs, carrying ∂/∂x for one inputoutput → inputs, carrying ∂L/∂(node)
Cost for all gradientsone pass per inputone pass per output
Best whenfew inputs, many outputsmany inputs, one scalar loss
Memorysmallmust keep forward values (activations)

Why the backward pass costs about 2× the forward

For a linear layer Y = XW, backward computes two matmuls of the same size: dX = dY·Wᵀ and dW = Xᵀ·dY. That is why training FLOPs (floating-point operations) ≈ 3 × forward ≈ 6 per parameter per token.

5 · How it works

Worked example: f(x, y) = (x·y + sin x)² at x = 1, y = 2

Nodes: a = x·y, b = sin x, c = a + b, f = c².

Worked example

  1. Forward: a = 2, b = sin 1 ≈ 0.841, c ≈ 2.841, f ≈ 8.074.
  2. Backward: ∂f/∂c = 2c ≈ 5.683; ∂c/∂a = ∂c/∂b = 1.
  3. x reaches f by two paths: through a (∂a/∂x = y = 2) and through b (∂b/∂x = cos 1 ≈ 0.540). So ∂f/∂x = 2c·(2 + 0.540) ≈ 14.44.
  4. y has one path: ∂f/∂y = 2c·x ≈ 5.68. Notebook 03 checks both against finite differences.
Multiply along each path, add across paths; cache forward values because the backward pass needs them.
6 · Why it works

Why backpropagation scales

One sweep for all weights

Reverse mode gets the gradient of one scalar with respect to every input for a small constant multiple of the forward cost.

Purely local rules

Each operation needs only its own derivative; frameworks compose them automatically (autograd).

Reuses forward work

Cached activations make each backward step a cheap matmul or elementwise product.

The price is memory

Keeping activations is what makes long-sequence training memory-bound (Distributed deck 08).

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Backpropagation is a special learning algorithm for neural nets."

It is just the chain rule applied in reverse order (reverse-mode automatic differentiation); the learning is done by gradient descent.

"Autodiff is numerical differentiation."

It is exact up to floating-point rounding: it applies analytic local derivatives, with no ε.

"Each weight needs its own backward pass."

One backward pass produces gradients for all weights at once.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Gradient has the parameter's shape. Use it to check matrix calculus.
  • Linear layer: dW = Xᵀ·dY, dX = dY·Wᵀ. Both are matmuls.
  • Gradient check with central differences. (f(x+ε) − f(x−ε)) / 2ε, ε ≈ 10⁻⁵.

⚠ Traps

  • Forgetting a path. Reused values (residuals, shared weights) need their gradients summed.
  • Dropping cached activations. Backward needs forward values (or recomputation).
  • Using forward mode for training. It costs one pass per input; reverse mode costs one pass per output.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

For L = (wx − y)² with w = 1, x = 2, y = 3, what is ∂L/∂w?

wx − y = −1, so ∂L/∂w = 2·(−1)·x = −4.

What does the backward pass need from the forward pass?

The intermediate values (activations) at each node, to evaluate local derivatives.

Why is reverse mode used for training instead of forward mode?

There is one scalar loss and billions of parameters: reverse mode costs one pass for all of them; forward mode would need one per parameter.
9 · Key takeaway

Key takeaway

Backprop is the chain rule run backwards: multiply local derivatives along paths, add over paths, and get every gradient for about twice the forward cost.
Say it in 30 seconds

Training needs the derivative of one scalar loss with respect to billions of weights. Break the computation into nodes with simple local derivatives. The chain rule says the derivative along a path is the product of the local derivatives, and when a value feeds several nodes the paths add. Running this from the loss backwards, reverse-mode automatic differentiation, gives every gradient in one sweep at roughly twice the cost of the forward pass, as long as the forward values are kept. Finite differences are only used to check the result.

Core idea: chain rule: multiply along paths, sum over paths.
