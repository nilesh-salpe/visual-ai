Decoder-only, and why it won

Encoder-decoder, encoder-only and decoder-only stacks differ mainly in their attention masks. Why the plain causal decoder became the default for LLMs (large language models).

What is the problem?The 2017 Transformer has an encoder and a decoder with cross-attention. BERT (Bidirectional Encoder Representations from Transformers) kept only the encoder. GPT kept only the decoder. For one general-purpose model, which shape is best?
Core ideaA causal decoder: one stack, one mask (each token sees only the past), trained to predict the next token at every position. Prompts, documents and answers all live in one sequence.
1 · Problem

Three families, one difference: the mask

Every family computes the same attention. What differs is which positions may see which. Each grid shows "row may attend to column" for 8 tokens. In the encoder-decoder, tokens 0–3 are the input and 4–7 the output.

2 · Limitation

What the other shapes cost

Encoder-only can't generate

BERT sees both directions and is trained to fill in masked tokens (15% of them). Great for classification and retrieval, but there's no natural way to write a long answer token by token.

Encoder-decoder needs a split

Every example must be cut into "input" and "target", and the two stacks are joined by cross-attention. Chat turns, documents and code don't come with a natural split.

Fewer training signals per token

Masked-LM objectives compute loss only on the corrupted positions. A causal LM (language model) computes loss on every position of every sequence, so each forward pass yields T training targets.

A multi-turn chat keeps growing. Which architecture can reuse all previous computation (the KV (key-value) cache) as each new message arrives?

C. In a causal decoder a token's keys and values depend only on earlier tokens, so they never change when new tokens arrive. Cache once, append forever. An encoder's bidirectional states change whenever the input grows, so they would have to be recomputed.
4 · Core idea

The causal decoder recipe

One stack

Embedding → N identical blocks (attention + FFN (feed-forward network)) → output head. No encoder and no cross-attention. Fewer moving parts to tune and to parallelize.

One objective

Predict token t+1 from tokens ≤ t, at every position, on any text. No labels, no input/target split, so all of the web is training data.

One sequence for everything

Instructions, documents, few-shot examples, tool calls and answers are all just tokens in context. GPT-2 and GPT-3 showed tasks can be specified in the prompt.

Packing and the document mask

Pretraining packs many documents back to back into one long sequence, so no compute is wasted on padding. With a plain causal mask, a token can attend into the previous, unrelated document. Llama 3: "we use an attention mask that prevents self-attention between different documents within the same sequence". It had limited impact in standard pretraining but mattered for continued pretraining on very long sequences. Notebook 05 shows a packed batch with this mask gives exactly the same outputs as running each document alone.

At a glance

One stack, one mask, one objective; at serving time past K and V never change, so they can be cached.

5 · How it works

Same model, three uses

Pretraining

Full causal mask (plus the document mask when packing) over long sequences. Loss on every token.

Fine-tuning (SFT)

Same causal mask. Prompt and response in one sequence, with the loss usually counted only on response tokens. No architecture change.

Serving

Prefill the prompt with one causal pass (cache K/V), then decode one token at a time, appending to the cache. Exactly the training computation, done incrementally.

What about bidirectional context?

A prefix-LM lets prompt tokens see each other in both directions and keeps the generated part causal. Wang et al. found this non-causal decoder with masked-LM pretraining did best after multitask fine-tuning, while the causal decoder did best for zero-shot use after self-supervised pretraining alone. They also showed models can be adapted between the two. The industry chose the simplest shape that scales and serves well, plus instruction tuning.

Worked example

  1. Causal LM: every position predicts its next token → 2,047 targets.
  2. BERT-style masked LM (15% masked): 307 targets.
  3. Encoder-decoder with a 50/50 split: 1,024 targets, and two stacks.
  4. Packed with a document mask: same target count, no attention across documents.
The causal objective extracts ~6.7× more supervised positions per sequence than 15% masking, from raw text with no labels.
6 · Why it works

Why the causal decoder won

Best zero-shot after pretraining alone

Wang et al. (2022): causal decoder-only models trained autoregressively "exhibit the strongest zero-shot generalization after purely unsupervised pretraining".

Every token is a target

Dense supervision from raw text, with no input/target split, makes it the simplest objective to scale on trillions of tokens.

Serving is incremental

Past K/V never change, so the KV cache, prefix caching, continuous batching and speculative decoding all fit naturally (Inference decks 02–06).

One interface for every task

Prompting turns any task into "continue this text", so one model and one serving stack cover translation, coding, chat and tool use.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Decoder-only models can't "understand" the input because they only look left."

Every prompt token sees all earlier prompt tokens, and the last position sees the whole prompt. Bidirectionality inside the prompt (prefix-LM) can help some setups, but it is not required to model the input well.

"Encoder-decoder models are obsolete."

Wang et al. found non-causal objectives can win after multitask fine-tuning, and encoder-style models remain standard for embeddings and retrieval. Decoder-only is the default for general-purpose generative LLMs.

"A decoder-only Transformer is just the 2017 decoder."

It drops the 2017 decoder's cross-attention sub-layer entirely. Each block is just masked self-attention plus FFN.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Causal mask: j ≤ i. Prefix-LM: bidirectional within the prompt, causal after.
  • Pack + document mask. Full-length rows with no cross-document attention.
  • Same mask everywhere. Pretraining, SFT (supervised fine-tuning) and serving all use the causal mask.

⚠ Traps

  • Packing without a document mask. Tokens attend into unrelated previous documents.
  • "Decoders can't read the input." The last position sees the whole prompt.
  • Calling encoder-decoder obsolete. Wang et al. found non-causal objectives win after multitask fine-tuning; encoders still lead retrieval.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

In a causal mask, query position i may attend to key position j when…

j ≤ i: itself and the past.

Why do packed pretraining sequences need a document mask?

Without it, tokens attend into earlier, unrelated documents in the same packed sequence. The document mask restricts attention to the same document, making a packed batch equivalent to running each document separately.

Give two reasons the causal decoder is convenient at serving time.

Past keys and values never change, so they can be cached and reused (KV cache, prefix caching). And the serving computation is exactly the training computation done incrementally, with no separate encoder pass.
9 · Key takeaway

Key takeaway

A causal decoder is one stack, one mask and one objective: predict the next token at every position. Simple to train at scale, and incremental to serve.
Say it in 30 seconds

Encoder-only, encoder-decoder and decoder-only Transformers mostly differ in their attention mask. The causal decoder lets each token see only the past and trains it to predict the next token at every position, so every token of raw text is a training target and there is no input/target split. At serving time past keys and values never change, so they can be cached, and prompts let one model do any task. Wang et al. found causal decoders give the best zero-shot generalization after plain pretraining, while non-causal variants can win after multitask fine-tuning. When documents are packed together, a document mask stops attention leaking between them.
