Rotary position embeddings (RoPE)

How rotating queries and keys by an angle proportional to position makes attention depend only on the distance between tokens, with no position vector added anywhere.

What is the problem?Attention is order-blind. The 2017 fix adds a position vector to each token embedding, which mixes position into content and lets attention see relative distance only indirectly.
Core ideaSplit q and k into 2-D pairs and rotate pair i by angle m·θᵢ at position m, with θᵢ = 10000−2i/d. The dot product of two rotated vectors depends only on the angle difference, so q·k depends on m − n.
1 · Problem

Attention can't see order by itself

Self-attention scores every pair of tokens with q·k. Shuffle the input tokens and each token gets exactly the same scores, just permuted. "dog bites man" and "man bites dog" would look identical. Position has to be injected somehow.

The 2017 answer: add a vector

x₀ = embedding(token) + PE(position), once, at the input. Every later layer has to untangle "what" from "where" inside the same vector. Recap: Transformer deck 07.

What attention actually needs

Mostly relative information: "the word two to my left", "the subject of this clause". A score that depends on m − n directly would be ideal, and it should keep working when the whole sequence shifts.

2 · Limitation

Limits of added position vectors

Absolute, not relative

With x + PE, the score (x_m + p_m)·W·(x_n + p_n) has content-position cross terms. Relative distance appears only through how the network learns to combine them.

Added once, diluted later

The position signal enters at layer 0 and has to survive every residual update to be useful in layer 40.

Learned tables stop at L

GPT-2-style learned position embeddings have exactly 1,024 rows. Position 1,025 has no vector at all.

Relative position attempts before RoPE

Relative-position schemes (Shaw et al. 2018; T5's bucketed biases) add learned terms that depend on m − n to the attention scores. They work, but they need extra tables or bias terms, and RoFormer argues they are awkward to combine with linear-attention variants. RoPE (rotary position embedding) gets relative behaviour from a fixed rotation with no learned parameters.

3 · Your turn

Rotate both, compare

Rotate query q by angle mθ and key k by angle nθ in the same plane. Their dot product depends on…

C. A dot product depends only on the vectors' lengths and the angle between them. Rotating q by mθ and k by nθ changes that angle by (m − n)θ. Shift both positions by the same amount and nothing changes. RoFormer: "the inner product encodes position information only in the relative form."
4 · Core idea

The RoPE recipe

1. Pair up dimensions

Split a d-dimensional q (or k) into d/2 pairs: (x₀,x₁), (x₂,x₃), … Treat each pair as a point in a 2-D plane, or as a complex number x₂ᵢ + i·x₂ᵢ₊₁.

2. Give each pair a speed

θᵢ = base−2i/d, base = 10,000 (RoFormer, LLaMA) or 500,000 (Llama 3). Pair 0 turns about once every 6 tokens; the last pair takes tens of thousands of tokens per turn.

3. Rotate by position

At position m, rotate pair i by m·θᵢ. Do this to q and k in every attention layer, after the projections. Values are not rotated, and nothing is added to the residual stream.

q′ₘ · k′ₙ = Re[ Σᵢ qᵢ · conj(kᵢ) · ei(m−n)θᵢ ] (pairs written as complex numbers)

5 · How it works

One pair, two tokens: only the gap matters

The left dial shows one pair of the query at position m; the right shows one pair of the key at position n. The score contribution is their dot product. Drag m and n, then use "shift both" to slide the pair along the sequence without changing the gap.

d = 16 here (8 pairs), base 10,000, so θ₀ = 1 rad/token, θ₂ = 0.1, θ₅ ≈ 0.0032. Real heads use d = 128 (64 pairs).

5 · How it works

Many speeds: the frequency spectrum and long-term decay

Each pair rotates at its own speed. Fast pairs separate nearby positions; slow pairs separate far-apart ones. For q = k (all ones) the total score drifts down as the distance grows. RoFormer calls this long-term decay: distant tokens interact more weakly by default.

Wavelengths for d = 128, base 10,000

Tokens per full turn of pair i is 2π/θᵢ: pair 0 ≈ 6, pair 16 ≈ 63, pair 32 ≈ 628, pair 48 ≈ 6,283, pair 63 ≈ 54,410 (computed in notebook 02). Pairs whose wavelength exceeds the training length never complete a turn during training. That fact is the key to long-context extension in deck 07.

5 · How it works

Worked example: rotation speeds for d = 128

Head dimension 128 (64 pairs). Wavelength = tokens per full turn = 2π / θᵢ.

Worked example

  1. Pair 0: θ₀ = 1 rad/token → wavelength 6.3 tokens.
  2. Pair 32: θ = 10000−0.5 = 0.0100 → wavelength 628 tokens.
  3. Pair 63 (base 10,000): wavelength 54,410 tokens; at position 4,096 it has turned only 0.08 of a circle.
  4. With Llama 3's base 500,000, pair 63's wavelength becomes 2,559,196 tokens.
Fast pairs separate nearby tokens, slow pairs far ones. Slow pairs that never complete a turn in training are why long-context extension needs care (deck 07).
6 · Why it works

Why RoPE won

Relative by construction

The score depends on m − n, proven in one line with complex numbers. The model doesn't have to learn to undo absolute positions.

Zero parameters, nothing added to the stream

A fixed rotation, applied inside attention, in every layer. The residual stream carries content only, and every layer gets fresh position information.

Plays well with the KV cache

A key's rotation depends only on its own position, so it is rotated once when written to the cache and never touched again. (Relative-bias schemes recompute per pair.)

Adopted everywhere

GPT-NeoX/GPT-J, PaLM ("better performance on long sequences"), LLaMA, Mistral and most open models since. Its main weakness, behaviour beyond the trained length, has its own family of fixes (deck 07).

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"RoPE adds a position vector to the token embeddings."

Nothing is added. RoPE multiplies (rotates) q and k inside each attention layer. The residual stream never sees a position vector.

"RoPE is applied to the values too."

Only queries and keys are rotated, because only their dot product needs position. Values carry content to the output unchanged.

"With RoPE a model works at any length."

The maths extends to any position, but the model never saw the large angles of slow pairs beyond its training length, so quality collapses without scaling or long-context training (deck 07).
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • θᵢ = base^(−2i/d); wavelength = 2π·base^(2i/d). Pair 0 always turns once every ~6.3 tokens.
  • Rotate keys once. A key's rotation depends only on its own position, so it is cached already rotated.
  • Shift invariance. Adding the same offset to all positions leaves every score unchanged.

⚠ Traps

  • Rotating values. Only q and k are rotated.
  • Mixing pair layouts. Interleaved pairs (paper) vs "rotate half" (Llama code) are permutations; weights trained with one don't work with the other.
  • Assuming RoPE extrapolates. Angles beyond the trained range are new to the model; quality drops past the training length.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

For head dimension d = 128 and base 10,000, what is θ for pair i = 0?

B. θ₀ = 100000 = 1 rad/token, about one full turn every 6.3 tokens. The fastest pair.

Why does shifting every position by the same amount leave all RoPE attention scores unchanged?

Each score depends on the angle between rotated q and k, which is (m − n)θᵢ for each pair. Adding the same shift to m and n leaves m − n unchanged.

Llama 3 raised the RoPE base from 10,000 to 500,000. What does that do to the rotation speeds?

Every θᵢ = base−2i/d gets smaller except pair 0, so pairs rotate more slowly and wavelengths stretch. More pairs stay distinguishable over long distances, which supports longer contexts.
9 · Key takeaway

Key takeaway

RoPE rotates each 2-D slice of q and k by position × frequency, so attention scores depend only on the distance between tokens.
Say it in 30 seconds

Attention is order-blind, so position has to be injected. The 2017 Transformer added a position vector at the input. RoPE instead splits each query and key into 2-D pairs and rotates pair i by the position times a frequency theta-i, which ranges from about one turn every six tokens down to one turn every fifty thousand. A dot product depends only on the angle between the two vectors, so the score depends only on m minus n: relative position for free, with no parameters, nothing added to the residual stream, and keys that are rotated once when cached. The slow pairs are why extending context needs care.

Problem: attention is permutation-invariant; added position vectors are absolute and diluted.
Core idea: rotate q and k pairs by m·θᵢ; q·k depends on m − n.
Spectrum: θᵢ = base^(−2i/d); fast pairs for local order, slow pairs for long range; base 10K → 500K in Llama 3.
