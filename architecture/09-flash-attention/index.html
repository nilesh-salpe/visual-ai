The Modern LLM · 09

FlashAttention internals

How computing exact attention in tiles, with an online softmax, avoids writing the N×N matrix to GPU memory. Plus what FlashAttention-2 and -3 changed.

What is the problem?Standard attention writes the N×N score matrix to HBM, reads it back for the softmax, writes probabilities and reads them again. At long N this memory traffic, not arithmetic, dominates the runtime.
Core ideaLoad blocks of Q, K and V into on-chip SRAM, compute scores, softmax and output for that tile there, and combine tiles with an online softmax (running max and sum, rescaling). The N×N matrix never touches HBM. The result is exact.
1 · Problem

Attention is memory-bound

On an A100 (figures from the FlashAttention paper): HBM holds 40–80 GB at 1.5–2.0 TB/s. On-chip SRAM is 192 KB per streaming multiprocessor across 108 SMs, at around 19 TB/s. SRAM is roughly 10× faster and many orders of magnitude smaller. Standard attention runs as several separate passes, each reading from and writing to HBM. See GPU deck 03 for the hierarchy.

2 · Limitation

Why earlier speed-ups didn't help

Approximate attention cuts FLOPs

Sparse and low-rank methods reduce computation but trade quality, and the FlashAttention abstract notes they "often do not achieve wall-clock speedup".

FLOPs aren't the bottleneck

Softmax, masking and dropout are element-wise over N² entries, so they do little arithmetic per byte moved. Their runtime is set by HBM bandwidth.

Memory grows as N²

Storing S and P for the backward pass needs N² values per head. At N = 65,536 in BF16 that is 8 GiB per head, per layer.

3 · Your turn

What does FlashAttention save?

Pick an answer before moving on. Committing to a guess, even a wrong one, makes the real answer stick.

FlashAttention actually does slightly more FLOPs than standard attention (it recomputes in the backward pass), yet it is several times faster. What does it reduce?

B. It is IO-aware: tiling keeps S and P in SRAM, so HBM traffic drops. GPT-2 medium (N = 1,024), forward + backward on an A100: standard 66.6 GFLOPs, 40.3 GB HBM, 41.7 ms; FlashAttention 75.2 GFLOPs, 4.4 GB, 7.3 ms.
4 · Core idea

Three ingredients

Tiling

Split Q into row blocks and K, V into column blocks sized to fit in SRAM. For each pair of blocks compute S = QKᵀ/√d, then the partial softmax and partial output, without leaving the chip.

Online softmax

Softmax needs a row max and sum over all columns. Keep a running max m and sum ℓ per row; when a new block raises the max, rescale the old sum and the old partial output by em_old − m_new. The result is exact.

Recompute in the backward pass

Don't store P. Save only the per-row softmax statistics (FA2: just the log-sum-exp) and recompute S and P block by block in the backward pass. Extra FLOPs, far less memory traffic, and memory linear in N.

IO complexity (FA1, Theorem 2)

With head dimension d and SRAM size M: standard attention needs Θ(Nd + N²) HBM accesses, while FlashAttention needs Θ(N²d²/M). For typical d (64–128) and M (~100 KB), d² is many times smaller than M. The paper also proves no exact attention algorithm can asymptotically do better for all M.

5 · How it works

Online softmax, step by step

One row of 12 scores, processed in chunks of 4 as if they arrived from three K blocks. Watch the running max m and running sum ℓ. When the max increases, the old sum is multiplied by em_old − m_new.

5 · How it works

Tiling: which blocks are touched

FlashAttention-2 order: for each Q block (outer loop, run in parallel across thread blocks), stream every K/V block through SRAM (inner loop). Step through and compare the elements moved to and from HBM with standard attention. Turn on causal: blocks entirely above the diagonal are skipped.

N = 8 blocks of 128 rows, d = 64. Forward pass, element counts: standard ≈ 4Nd + 4N², tiled ≈ 2Nd + (N/B_r)·2Nd (the same traffic model as notebook 08).

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"FlashAttention is an approximation of attention."

It is exact: the same outputs up to floating-point rounding (notebook 08: max error ~1e-15). Only the order of operations changes.

"FlashAttention makes attention O(N)."

Compute is still O(N²). What becomes O(N) is the extra memory: no N×N matrix is stored. HBM traffic drops by a large factor but is still quadratic in N.

"It is faster because it does fewer FLOPs."

It does more FLOPs (75.2 vs 66.6 GFLOPs in Fig. 2) because of recomputation. It is faster because it moves about 9× fewer bytes.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

In the online softmax, when a new block has a larger maximum, what happens to the running sum ℓ?

Rescaled by e^(m_old − m_new), and so is the partial output.

What does FlashAttention store for the backward pass instead of P?

Only per-row softmax statistics (in FA2, just the log-sum-exp L = m + log ℓ). S and P are recomputed block by block in SRAM during the backward pass.

Name two changes in FlashAttention-2 compared with FA1.

Parallelize over the sequence (outer loop over Q blocks, not K/V); fewer non-matmul FLOPs (rescale the output once at the end); better work split across warps; store only the log-sum-exp.
9 · Key takeaway

Key takeaway

FlashAttention computes exact attention tile by tile in SRAM with an online softmax, so the N×N matrix never touches HBM: more FLOPs, far fewer bytes, much faster.
Say it in 30 seconds

Standard attention writes the N by N score matrix to GPU high-bandwidth memory, reads it back for the softmax, writes the probabilities and reads them again, and at long sequences that traffic, not arithmetic, sets the runtime. FlashAttention loads blocks of Q, K and V into on-chip SRAM and computes scores, softmax and output there. It combines blocks with an online softmax that keeps a running max and sum per row and rescales when the max grows. The backward pass recomputes scores from saved statistics instead of storing them. It is exact, uses memory linear in N, and on GPT-2 cut HBM traffic from 40 to 4.4 GB. FlashAttention-2 reordered the loops for parallelism; FlashAttention-3 uses Hopper's asynchrony and FP8.

Problem: N×N intermediates make attention memory-bound and O(N²) in memory.
Core idea: tiling + online softmax + recompute: exact, linear memory, ~9× less HBM traffic.
Versions: FA2: loop order and parallelism (50–73% of peak); FA3: Hopper async + FP8 (740 TFLOPs/s).
