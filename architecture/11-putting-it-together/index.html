2 · Limitation

Where people get stuck

Mixing up what is cached

K and V (after RoPE) are cached, Q isn't. With GQA only the K/V heads are cached. With MLA (multi-head latent attention) it's the latent plus the RoPE key.

Counting parameters wrongly

Forgetting that GQA shrinks Wk and Wv, that SwiGLU has three matrices, or that untied embeddings count twice.

Confusing kernel and architecture

FlashAttention doesn't change the model; it computes the same function faster. RoPE scaling and sliding windows do change what the model computes.

5 · How it works

Follow one token through the stack

1. Embed

Token id → row of the embedding table (d numbers). No position vector is added.

2. Attention sub-layer

RMSNorm → q, k, v projections (fewer K/V heads) → RoPE on q and k → append k, v to the KV cache → attention over the cache with FlashAttention → Wo → add to the stream.

3. FFN sub-layer

RMSNorm → SwiGLU (or route to top-k experts) → add to the stream.

4. Repeat L times

The residual stream accumulates every layer's contribution; nothing renormalizes it along the way.

5. Output

Final RMSNorm → output head (vocab logits) → sample the next token, which becomes the next input.

6. Long inputs

Positions beyond the trained range need RoPE scaling or long-context training; a sliding window caps the cache.

5 · How it works

Worked example: sizing Llama 3 70B from its config

Vocabulary 128,256; d = 8,192; 80 layers; 64 query heads, 8 KV heads (head dim 128); FFN 28,672; untied embeddings.

Worked example

  1. Parameters: 70.55B (same formula as notebook 10).
  2. Weights: BF16 141 GB; FP8 (8-bit floating point) 71 GB → at least 2 × 80 GB GPUs (graphics processing units) in BF16.
  3. KV per token: 2 × 80 × 8 × 128 × 2 = 320 KiB; 32 sequences at 8K = 80 GiB.
  4. Forward FLOPs per token ≈ 2 × parameters = 141 GFLOP (billion floating-point operations).
Weights pick the minimum GPU count; KV per token decides how many concurrent long-context users fit; FLOPs per token set prefill speed.
6 · Why it works

Why the pieces fit together

They solve different problems

Stability (pre-norm), cost per op (RMSNorm), position (RoPE), FFN quality (SwiGLU), serving memory (GQA/MLA), memory traffic (FlashAttention), parameters per FLOP (MoE). Each fix is local, so none conflicts with the others.

The few interactions are known

RoPE plus MLA needs decoupled RoPE. RoPE plus long context needs scaling. MoE plus GQA is fine (Mixtral). Pre-norm needs a final norm.

Inference shaped the design

The KV cache explains GQA, MLA, sliding windows and why decoder-only won. Active parameters explain MoE. Memory traffic explains FlashAttention.

What comes next

Training these models at scale (data, scaling laws, parallelism) and aligning them (post-training) are the next topics in this guide.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Parameter count tells you serving cost."

Serving cost also depends on the KV cache (set by K/V heads, layers and context length) and, for MoE, on active rather than total parameters.

"Two models with the same parameters have the same architecture."

Llama 2 7B and Llama 3 8B are similar in size but differ in K/V heads (32 vs 8), FFN width (11,008 vs 14,336), vocabulary (32K vs 128K) and RoPE base (10K vs 500K).

"FlashAttention is part of the model architecture."

It is a kernel. Swapping it for standard attention gives the same outputs, only slower and using more memory.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • FLOPs/token ≈ 2N. Plus the attention term for long contexts.
  • Memory = weights + KV + activations. KV usually decides concurrency.
  • Check rope_theta and rope_scaling. They tell you the trained and supported context.

⚠ Traps

  • Parameter count = serving cost. KV per token and active (MoE) parameters matter as much.
  • Same size, same architecture. Llama 2 7B vs Llama 3 8B differ in KV heads, FFN width, vocabulary and RoPE base.
  • Treating FlashAttention as architecture. It is a kernel; outputs are the same.

9 · Key takeaway

Key takeaway

A modern LLM layer is RMSNorm → GQA attention with RoPE → residual → RMSNorm → SwiGLU (or MoE) → residual, computed with FlashAttention, and its size and cache follow directly from the config.
Say it in 30 seconds

Every modern open LLM is the same template. A token embedding with no position vector; then L identical blocks, each a pre-norm RMSNorm, grouped-query attention with RoPE on queries and keys computed by a FlashAttention kernel, a residual add, another RMSNorm, a SwiGLU feed-forward or a set of routed experts, and another residual add; then a final RMSNorm and the output head. Parameters, KV cache per token and FLOPs follow directly from the config: Llama 3 8B has 8.03 billion parameters, 70% of them in FFNs, and a 128 KiB KV cache per token. Each design choice maps to a specific scaling problem.

Template: embed → L × [RMSNorm, GQA+RoPE, +, RMSNorm, SwiGLU/MoE, +] → RMSNorm → head.
Sizes: Llama 3 8B: 8.03B params, ~70% FFN, 128 KiB KV per token.
Reading configs: num_key_value_heads, rope_theta, intermediate_size, hidden_act, sliding_window, experts.

LLaMA: Open and Efficient Foundation Language Models
Touvron et al. · arXiv 2023

The recipe most open models followed: pre-normalization with RMSNorm, SwiGLU with a ⅔·4d hidden size, and rotary embeddings.

Llama 2: Open Foundation and Fine-Tuned Chat Models

Adds grouped-query attention for the 34B and 70B models and documents the chat post-training: SFT (supervised fine-tuning), two reward models and iterative RLHF (reinforcement learning from human feedback) with rejection sampling and PPO (Proximal Policy Optimization).

Remember: 27,540 SFT annotations; over 1M human comparisons
The Llama 3 Herd of Models
Llama Team, AI (artificial intelligence) @ Meta · arXiv 2024

Dense Transformer with GQA (8 KV heads), RoPE base 500,000, a 128K vocabulary and a document mask; staged long-context pretraining to 128K; post-training with SFT, rejection sampling and DPO (Direct Preference Optimization) in six rounds.

Remember: 128K context after six stages over ~800B tokens
Mistral 7B
Jiang et al. · arXiv 2023

A 7B model with GQA and sliding-window attention (W = 4,096) plus a rolling-buffer KV cache.
