Long context II: sliding window and ALiBi

Two other ways to handle long sequences: limit how far each layer looks (sliding-window attention with a rolling KV (key-value) cache), or bias scores by distance (ALiBi (Attention with Linear Biases)).

What is the problem?Full attention costs O(T²) compute and its KV cache grows with every token. At long T, both memory and time explode, even when most useful context is nearby.
Core ideaSliding window: each token attends only to the last W tokens, and stacked layers relay information further back, so the cache can be a fixed-size ring buffer. ALiBi: no position embeddings; subtract a head-specific slope × distance from every score.
1 · Problem

Full attention gets expensive fast

Score computations per layer and KV-cache entries per layer, as the sequence grows. Full causal attention computes about T²/2 scores and caches T entries. A sliding window of W = 4,096 computes at most T·W and caches at most W.

2 · Limitation

Why not just cut the context?

Truncating loses information

Dropping everything older than W tokens at the input means the model can't use it at all.

Sparse patterns are fiddly

Hand-designed sparse attention (strided, global tokens) needs custom kernels and careful choices for every pattern.

Position extrapolation still matters

Even with cheaper attention, the position encoding must behave sensibly at lengths beyond training (deck 07, and ALiBi below).

4 · Core idea

Two ideas

Sliding-window attention (SWA)

Token i attends to positions i−W+1 … i only. Information from further back reaches i indirectly: token i−W saw it in the previous layer. The KV cache needs only the last W entries, stored in a rolling buffer at slot i mod W. Mistral 7B: W = 4,096, 2× faster at 16K with its kernel changes, 8× less cache at 32K.

ALiBi

Don't add position embeddings at all. Add a linear penalty −m·(i−j) to each query-key score, with a different slope m per head (a geometric sequence, 1/2 … 1/256 for 8 heads). Trained at 1,024 tokens, a 1.3B model extrapolates to 2,048 and matches a sinusoidal model trained at 2,048, while training 11% faster and using 11% less memory.

Not every Mistral-family model uses the window

Mixtral's paper notes it "supports a fully dense context length of 32k tokens", meaning full attention, unlike Mistral 7B's sliding window. Windowing is a per-model design choice; a model card or config (sliding_window) tells you which.

At a glance

Bounded attention per layer; depth relays information further back; memory capped at W per layer.

5 · How it works

Stacked windows: the receptive field grows with depth

Each row is a layer, each column a position (newest on the right). Highlighted cells are positions that can influence the last token's output through the stack. One layer sees W positions; each extra layer reaches W−1 further.

5 · How it works

The rolling-buffer KV cache

A cache of W = 4 slots. Token t's key and value are written to slot t mod 4, overwriting the entry from t−4, which the window no longer needs. Press "next token".

5 · How it works

ALiBi: a distance penalty per head

The bias added to each attention score for one head (rows: query position i, columns: key position j, causal). Darker means a bigger penalty. Heads with a steep slope focus locally; heads with a gentle slope can look far back.

Slopes for 8 heads: the geometric sequence 1/2¹, 1/2², …, 1/2⁸. For n heads it starts at 2^(−8/n) with the same ratio (Press et al.).

5 · How it works

Worked example: Mistral 7B at 32K tokens

32 layers, 8 KV heads of 128, BF16 (bfloat16, a 16-bit floating-point format with the exponent range of 32-bit floats), window W = 4,096.

Worked example

  1. KV per token: 2 × 32 × 8 × 128 × 2 = 128 KiB.
  2. Full cache at 32,768 tokens: 4 GiB; rolling buffer (4,096 slots): 0.5 GiB, 8× less.
  3. Theoretical span: 32 × (4,096 − 1) + 1 = 131,041 tokens (paper: ~131K).
  4. Token 10,000 is written to slot 10,000 mod 4,096 = 1,808, overwriting token 5,904.
Constant memory per sequence and attention cost O(T·W), at the price of indirect long-range access.
6 · Why it works

Why they work, and their limits

Most attention is local

Many heads mostly look nearby. A window keeps that cheap and lets depth carry longer-range information.

Memory becomes constant

With a rolling buffer, KV memory per sequence is capped at W entries per layer: 8× smaller at 32K for Mistral 7B, and it never grows during generation.

ALiBi has no unseen positions

A penalty proportional to distance is defined for any distance, and longer distances just get a larger penalty, which is why it extrapolates.

Limits

Information older than W must survive several relays, so exact long-range retrieval is harder than with full attention. ALiBi's built-in bias towards recent tokens can also limit how much distant text is used.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"A sliding-window model can't use anything older than W tokens."

It can, indirectly: information moves up to W further back per layer, so the theoretical span is about L × W. It is lossy, though.

"ALiBi is a kind of position embedding."

Nothing is added to the embeddings. ALiBi adds a fixed, distance-dependent bias to the attention scores.

"Every Mistral model uses sliding-window attention."

Mistral 7B does (W = 4,096). Mixtral uses fully dense attention over 32K. Check the config.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Span ≈ layers × W. Exactly L·(W−1)+1 with an inclusive window of W keys.
  • ALiBi slopes: 2^(−8i/n). For 8 heads: 1/2 … 1/256.
  • Check sliding_window in the config. Mixtral, unlike Mistral 7B, is dense over 32K.

⚠ Traps

  • Assuming nothing beyond W is visible. Information hops W per layer, lossily.
  • Calling ALiBi a position embedding. It is a bias on attention scores.
  • Off-by-one windows. Codebases differ on whether the window includes the current token.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

In Mistral's rolling buffer with W = 4,096, where is token 10,000's key stored?

Slot i mod W = 1,808, overwriting token 5,904's entry.

What does ALiBi add to the score between query i and key j?

−m·(i − j), a negative bias growing linearly with distance, with a fixed slope m per head (e.g. 1/2 … 1/256 for 8 heads). No position embeddings at all.

Why does sliding-window attention make the KV cache constant-size?

A token never attends further back than W positions, so older keys and values are never needed again and can be overwritten in a ring buffer of W slots.
9 · Key takeaway

Key takeaway

Sliding windows cap attention cost and KV memory and rely on depth to reach further; ALiBi replaces position embeddings with a per-head distance penalty that extrapolates.
Say it in 30 seconds

Full attention costs order T squared and its cache grows with every token. Sliding-window attention lets each token attend only to the last W tokens. Information older than that still flows indirectly through the stack, so Mistral 7B, with W of 4,096 over 32 layers, has a theoretical span of about 131K. Because no token looks back further than W, the KV cache can be a ring buffer indexed by position mod W: 8 times less memory at 32K. ALiBi removes position embeddings and subtracts a head-specific slope times the distance from each attention score, which let a model trained at 1,024 tokens work at 2,048.

Problem: O(T²) scores and an ever-growing KV cache.
SWA (sliding-window attention): attend to the last W; span ≈ L·W; rolling buffer at i mod W.
ALiBi: score − m·distance, slopes 1/2…1/256; train short, test long.
