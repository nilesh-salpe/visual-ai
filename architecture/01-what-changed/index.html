The Modern LLM · 01

What changed since 2017

The 2017 Transformer and a 2024 Llama block side by side: seven changes, what problem each one solved, and where each is explained in this guide.

What is the problem?The 2017 Transformer was built for translation on 8 GPUs. Scaling it to hundreds of billions of parameters, long contexts and millions of users exposed problems in training stability, position handling, FFN quality, inference memory and attention speed.
Core ideaModern LLMs keep the 2017 skeleton (attention + FFN + residuals) and swap specific parts: pre-norm RMSNorm, RoPE, SwiGLU, GQA/MLA, a decoder-only stack, long-context tricks and FlashAttention, with MoE for the largest models.

2 · Limitation

What broke when the 2017 design was scaled up

Training stability

Post-norm (a LayerNorm after each residual add) gives large gradients near the output at initialization. It needs a carefully tuned learning-rate warm-up, and deeper stacks make this worse (Xiong et al., 2020).

Position handling

Sinusoidal or learned vectors are added to the token embedding, so position is mixed into the content. Attention sees relative distance only indirectly, and learned positions don't exist beyond the trained length.

Inference memory

Every head keeps its own keys and values. During generation that KV cache, not compute, limits batch size and context (Inference deck 02).

FFN quality per parameter

The ReLU FFN holds about two thirds of a layer's weights. A gated variant (SwiGLU) gets lower perplexity at the same parameter count (Shazeer, 2020).

Attention is memory-bound

A plain implementation writes the N×N score matrix to GPU memory and reads it back. At long N that traffic, not FLOPs, sets the runtime (Dao et al., 2022).

Two stacks for one job

An encoder-decoder needs separate inputs, targets and cross-attention. For "continue this text" a single causal stack is simpler, and it learns from every token.

3 · Your turn

Which change is mostly about serving cost?

Pick an answer before moving on. Committing to a guess, even a wrong one, makes the real answer stick.

Which of these changes mainly reduces memory at inference time, rather than improving training quality?

C. GQA lets several query heads share one key/value head, so the KV cache shrinks by the sharing factor (8× for Llama 3 with 64 query heads per 8 KV heads in 70B). PaLM reported MQA as roughly neutral for quality and training speed but a significant saving at decoding time. The others mainly help training speed, stability or quality.

Also new, but not in every model

  • Long context: RoPE scaling (PI, NTK-aware, YaRN), larger RoPE base, sliding-window attention. Decks 07 and 08.
  • Mixture of Experts: replace the FFN with many expert FFNs and a router. Mixtral and DeepSeek-V2. Deck 10.
  • No biases in linear layers and norms (PaLM: "this results in increased training stability for large models"). Llama's config also has attention_bias: false.

    6 · Why it works
    
Why these changes stuck

    

    

      
They are cheap to adopt
Each swap changes one sub-component and keeps the residual stream and the attention + FFN layout. They compose: you can take all of them at once, as LLaMA did.

      
They target scale problems
Pre-norm and RMSNorm address stability and speed at depth. GQA and MLA address serving memory. FlashAttention and RoPE scaling address long sequences. These problems only appeared at scale.

      
They were tested in public
Shazeer's GLU ablation, Xiong's norm analysis, RoFormer and the GQA uptraining study each report controlled comparisons, and open model families then confirmed the combination.

      
Inference shaped training
Several changes (MQA/GQA/MLA, sliding windows, MoE's active parameters) exist mainly because a model is served billions of times after it is trained once.

    

  






  

    7 · Misconceptions
    
Common misconceptions

    

    
Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

    

      
"Modern LLMs use a completely different architecture from the 2017 Transformer."

      
      
The skeleton is the same: token embeddings, a stack of attention + FFN layers with residual connections, and a softmax output. The changes are targeted swaps inside that skeleton.

    

    

      
"Each change was invented by the model that made it famous."

      
      
Mostly not. LLaMA credits pre-normalization to GPT-3, SwiGLU to PaLM (and Shazeer 2020), and rotary embeddings to GPT-Neo (and Su et al. 2021). Its contribution was the combination and the open release.

    

    

      
"These changes are mostly about accuracy."

      
      
Many are about cost: RMSNorm (speed), GQA/MLA (KV memory), FlashAttention (memory traffic), MoE (FLOPs per token). Quality had to stay roughly the same; the cost went down.

    

  






  

    8 · Check yourself
    
Check yourself

    

    
Answer from memory. If you can't, revisit the slide named in the answer.

    

      
In a pre-norm block, where is the normalization applied?

      

      
      
      
      
      

      
B. x + F(Norm(x)). The residual path itself is never normalized, so a final norm is added before the output head.

    

    

      
Llama 3 8B has num_attention_heads 32 and num_key_value_heads 8. What does that mean, and what does it buy?

      
      
It uses GQA: groups of 4 query heads share one key/value head. The KV cache is 4× smaller than with full multi-head attention, which means more concurrent sequences or longer contexts per GPU.

    

    

      
Name the parts of a Llama block that differ from the 2017 block, and one reason for each.

      
      
Pre-norm (stable without warm-up), RMSNorm (cheaper), RoPE (relative positions; no added vector), SwiGLU (better quality per parameter), GQA (smaller KV cache), decoder-only (one stack, every token trains). FlashAttention is the kernel used to compute the same attention faster.

    

  






  

    9 · Key takeaway
    
Key takeaway

    

    
A modern LLM is the 2017 Transformer with seven targeted swaps: pre-norm, RMSNorm, RoPE, SwiGLU, shared or compressed K/V heads, a decoder-only stack and an IO-aware attention kernel.

    
Say it in 30 seconds
The skeleton hasn't changed: attention plus FFN layers with residual connections. What changed are the parts that broke at scale. Normalization moved inside the residual branch and became RMSNorm, for stability and speed. Positions became rotations of q and k (RoPE), so attention depends on relative distance. The FFN became a gated SwiGLU. Query heads now share key/value heads (GQA) to shrink the KV cache. Everything runs as a single causal decoder, computed with FlashAttention. Long-context tricks and Mixture-of-Experts sit on top for the models that need them.

    
Problem: the 2017 block had stability, position, memory and speed problems at scale.
Core idea: keep the skeleton; swap norm, position, FFN, K/V heads, stack type and kernel.
Read configs: every field in a config.json maps to one of these decisions.
