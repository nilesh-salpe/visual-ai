LangGraph in production

What a checkpointer adds: per-thread memory, human-in-the-loop with interrupt and resume, recovery from failures without redoing finished steps, history and time travel, plus retries, durability modes and streaming.

What is the problem?Production agents run for minutes or hours, wait for people, call flaky services, crash halfway and must remember each user's conversation. A process-local loop loses all of that on the first restart.
Core ideaCompile the graph with a checkpointer: state is saved after every super-step under a thread_id. That one mechanism gives memory (continue a thread), human-in-the-loop (interrupt() pauses, Command(resume=...) continues), fault tolerance (re-invoke with no input to resume from the last checkpoint) and history (inspect, replay or fork earlier states). Add retry policies per node and choose a durability mode.

1 · Problem

Agents outlive processes

Long waits

An approval can take hours; holding a process open for it is fragile.

Crashes mid-task

Restarting from scratch repeats expensive or non-repeatable steps.

Many conversations

Each user and thread needs its own state, isolated and resumable.

2 · Core idea

Checkpoint every step

Threads

config={"configurable": {"thread_id": ...}} selects whose state to load and save.

Interrupts

interrupt(payload) pauses the run and surfaces the payload under interrupt; Command(resume=value) continues, and value becomes interrupt()'s return value.

Resume after failure

Finished steps stay checkpointed; invoking the same thread with None continues from the failed step.

History

get_state and get_state_history list every checkpoint, for debugging, replay and forking.

Checkpointers hold thread-scoped state; a separate store holds data shared across threads, such as user preferences and long-term facts.

7 · Challenges in production

In production

Idempotent nodes

Assume any node can run more than once: after resume, retry or replay.

Serializable state

Keep state and interrupt payloads JSON-serialisable (JSON = JavaScript Object Notation); checkpointers may not store arbitrary objects.

Workers anywhere

Because state lives in the checkpointer, any worker can resume any thread: scale workers independently.

Observe pauses

Track how long runs wait on humans and how many are stuck; alert on stale interrupts.
