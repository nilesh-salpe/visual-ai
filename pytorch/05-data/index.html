Data pipelines for LLMs

Getting tokens to the GPU (graphics processing unit): Dataset and DataLoader, fixed windows for pretraining, padding with attention masks and −100 labels for fine-tuning, and sequence packing.

What is the problem?Pretraining consumes a token stream; fine-tuning uses variable-length examples. Batches must be rectangular, padding must not leak into the loss, and the GPU must never wait for data.
Core ideaA Dataset returns one example; a DataLoader batches (with collate_fn), shuffles and prefetches with worker processes. Pretraining cuts the token stream into fixed windows. Fine-tuning pads and marks ignored labels with −100 (cross-entropy's default ignore_index). Packing concatenates examples to avoid padding waste.
1 · Problem

How much is padding?

A batch of variable-length sequences. Grey cells are padding the GPU still computes on. Change the batch size, or switch to packing.

2 · Limitation

Why data loading is tricky

Rectangular batches

GPUs want fixed shapes; real text has every length.

Loss leakage

Padding or prompt tokens that count in the loss distort training.

Starving the GPU

Tokenising in the training process makes the GPU wait.

4 · Core idea

Dataset, collate, DataLoader

Dataset

len and getitem: one example, e.g. a window of T + 1 tokens split into inputs and targets.

collate_fn

Turns a list of examples into tensors: pad, build attention masks and labels, or pack.

DataLoader

batch_size, shuffle, num_workers, pin_memory, prefetch: keeps the GPU fed.

At a glance

Labels = inputs shifted by one; −100 where no loss should be taken.

5 · How it works

Worked example: padding vs packing

Notebook 05: 64 examples with lengths drawn uniformly between 20 and 400 tokens.

Worked example

  1. Padded batches of 8 (each padded to its longest example): 44% of computed tokens are padding.
  2. Batches of 32: 48% padding; bigger batches make it worse because the longest example dominates.
  3. Packing the same examples into full rows of fixed length: padding falls to at most the tail of the last row.
  4. Packed documents need a document mask (or per-document position ids) so tokens do not attend across document boundaries.
Padding can waste nearly half the compute on varied lengths; packing recovers it.
6 · Why it works

Why this design works

Separation of concerns

Datasets know examples; collate knows batching; the loader knows parallelism.

Exact loss

The −100 convention makes masking a label choice, with no special loss code.

Throughput

Worker processes and pinned memory overlap data preparation and copies with GPU compute.

Packing

Fills every position with real tokens; standard for pretraining and common for SFT (supervised fine-tuning).

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"The attention mask removes padding from the loss."

It only stops attention to padding; the loss needs labels of −100 at those positions.

"Bigger batches reduce padding waste."

With padding to the longest example, bigger batches usually waste more (44% → 48% in notebook 05).

"Packing lets documents see each other harmlessly."

Without a document mask, tokens attend across unrelated documents.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • labels = −100 on padding and prompt. F.cross_entropy ignores them by default.
  • pin_memory=True + non_blocking. Overlaps host-to-GPU copies.
  • num_workers > 0. Tokenisation and collation run in parallel processes.

⚠ Traps

  • Padding with a real token id and no mask. The model attends to padding.
  • Training on prompt tokens in SFT. Usually you mask the prompt to −100.
  • Overlapping windows by accident. Inflates epochs and leaks validation data.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

Pretraining window of T inputs needs how many tokens from the stream?

T + 1: inputs are the first T, targets the last T.

What do pin_memory and non_blocking=True do?

Allocate page-locked host memory so host-to-GPU copies can run asynchronously, overlapping with compute.

How do you keep packed documents independent?

Use a block-diagonal causal mask (or per-document position ids / varlen attention) so attention stays within each document.
9 · Key takeaway

Key takeaway

A Dataset returns examples, a collate function pads or packs them with −100 labels where no loss applies, and a DataLoader with workers keeps the GPU fed.
Say it in 30 seconds

PyTorch splits data loading into a Dataset that returns one example, a collate function that turns a list of examples into tensors, and a DataLoader that batches, shuffles and prefetches with worker processes. Pretraining cuts a long token stream into windows of T plus one tokens, inputs and shifted targets. Fine-tuning pads examples to a rectangle, builds an attention mask, and sets labels to minus one hundred wherever no loss should count, because that is cross-entropy's default ignore index. Padding can waste nearly half the compute, so packing concatenates examples into full rows with a document mask.

Problem: variable lengths, exact loss, fed GPUs.
Core idea: Dataset → collate → DataLoader; −100 labels.
Efficiency: pack instead of pad; workers + pinned memory.
