Putting it together: a tiny GPT

Every piece of this topic in one small, runnable model: embeddings, pre-norm blocks with SDPA (scaled dot-product attention), a tied head, AdamW with weight-decay groups, warmup + cosine, clipping, and sampling, nanoGPT style.

What is the problem?Each previous deck showed one piece. To trust them, you need to see them work together: a model that trains, whose loss falls, and that generates text.
Core ideaA GPT = token + position embeddings → L pre-norm blocks → final norm → head tied to the embedding. Train with the standard loop (AdamW, decay groups, warmup + cosine, clipping). Generate by repeatedly sampling from the last position's logits. Initialise embeddings with std 0.02.

4 · Core idea

The whole model

Embeddings

wte (V × C) + wpe (T_max × C), initialised with std 0.02.

Blocks

L pre-norm blocks: RMSNorm (root-mean-square normalization) → SDPA attention → residual; RMSNorm → MLP (multilayer perceptron) → residual.

Head

Final RMSNorm, then logits = h @ wteᵀ (tied weights).

5 · How it works

Generation loop

model.eval()
idx = encode("the ")
with torch.no_grad():
    for _ in range(80):
        logits, _ = model(idx[:, -T_max:])              # crop to the context window
        probs = F.softmax(logits[0, -1] / 0.8, dim=-1)   # temperature 0.8
        idx = torch.cat([idx, torch.multinomial(probs, 1)[None]], dim=1)
print(decode(idx[0]))

Without a KV (key-value) cache this recomputes the whole prefix every step; serving systems cache keys and values (Inference deck 02).

5 · How it works

Worked example: notebook 09 on a laptop CPU

A 2-layer, 64-wide character GPT (vocabulary 28) on a short repetitive text; 300 steps of AdamW (lr 3×10⁻³, β₂ 0.95), batch 16 × 32 characters.

Worked example

  1. With nn.Embedding's default std-1 initialisation and a tied head, the first loss was 46.5: logits are huge. With GPT-2's std 0.02 it starts at 3.36 ≈ ln 28 = 3.33, as an untrained model should.
  2. Training loss falls from 3.36 to 0.09; validation loss 0.08 nats per character on this repetitive text.
  3. Sampling at temperature 0.8 from "the " produces "the quick brown fox jumps over th lazy lazy love lazy dog. dog…": locally right, globally confused, as expected from a tiny model.
  4. The same code scaled up (12 layers, C = 768, GPUs, FSDP (Fully Sharded Data Parallel), torch.compile) is essentially nanoGPT's GPT-2 (124M).
Initialisation scale matters immediately; once it is right, the standard loop trains a working language model in seconds.
6 · Why it works

Why it works

One objective

Next-token cross-entropy over every position trains the whole stack.

Stable recipe

Pre-norm, small init, AdamW with decay groups, warmup and clipping.

Tied embeddings

Fewer parameters and a shared notion of token similarity in and out.

Scales unchanged

More layers, data and GPUs (FSDP, compile) without changing the logic.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"A good tiny model proves the architecture."

It proves the plumbing; architecture decisions need scaling experiments.

"Low training loss on repetitive text means it learned language."

It memorised a tiny corpus; validation on varied text is the real test.

"Sampling needs special training."

Generation reuses the trained next-token distribution; decoding choices are made at inference.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Check loss at step 0. It should be ≈ ln V.
  • Overfit one batch first. Loss → 0 proves the plumbing works.
  • model.eval() + torch.no_grad() to sample. Faster and dropout-free.

⚠ Traps

  • Default std-1 embeddings with a tied head. Initial loss ≫ ln V.
  • Forgetting to crop context. Inputs longer than the position table crash or misbehave.
  • Evaluating in train mode. Dropout makes validation loss noisy and pessimistic.
8 · Check yourself

Check yourself

Answer from memory. If you can't, revisit the slide named in the answer.

Parameters of a tied-head GPT with L = 12, C = 768, V = 50,304 (ignore positions, norms)?

12 × 12 × 768² + 50,304 × 768 ≈ 84.9M + 38.6M ≈ 124M.

Why initialise embeddings with std 0.02 when the head is tied?

With std 1, logits = h·Eᵀ are huge at initialisation, giving a loss far above ln V and unstable early training.

What is the first check you run on a new training script?

The step-0 loss ≈ ln V, then overfit a single batch to near-zero loss.
9 · Key takeaway

Key takeaway

A GPT is embeddings, pre-norm SDPA blocks and a tied head trained with the standard AdamW loop; check the step-0 loss (≈ ln V), then scale the same code up.
Say it in 30 seconds

This deck assembles the topic into a working model. Token and position embeddings, initialised with a small standard deviation, feed a stack of pre-norm blocks using scaled dot product attention, then a final norm and an output head that reuses the token embedding. The standard loop trains it: AdamW with weight decay only on matrices, warmup and cosine decay, gradient clipping. In notebook nine the default embedding initialisation gave a first loss of 46 instead of about three, a classic bug; with the fix the loss falls to under 0.1 and the model generates text. The same code at GPT-2 size has 124 million parameters.
