Performance: compile, SDPA and memory

Making PyTorch fast: torch.compile (TorchDynamo + AOTAutograd + TorchInductor), graph breaks, fused attention with scaled_dot_product_attention, and reading GPU (graphics processing unit) memory usage.

What is the problem?Eager PyTorch launches one kernel per operation and writes every intermediate to memory. Attention materialises a T × T matrix. Both waste time and memory at LLM (large language model) scale.
Core ideatorch.compile captures your Python into graphs (TorchDynamo), adds the backward (AOTAutograd) and generates fused kernels (TorchInductor: Triton on GPUs, C++ on CPUs (central processing units)). Graph breaks split graphs and cost speed. SDPA (scaled dot-product attention) uses fused attention kernels that never store the score matrix. Memory is read with torch.cuda.max_memory_allocated() and the profiler.
1 · Problem

The quadratic memory term

Memory of one attention layer's score matrix (B · H · T · T) versus q, k, v (3 · B · H · T · D), BF16 (bfloat16, a 16-bit floating-point format with the exponent range of 32-bit floats). Fused attention keeps only the latter.

2 · Limitation

Where eager PyTorch loses time

Kernel launches

Each elementwise op is its own kernel with launch overhead.

Memory round trips

Every intermediate is written to HBM (high-bandwidth memory) and read back.

Materialised attention

Scores and probabilities of size T × T per head.

4 · Core idea

Three tools

torch.compile

Dynamo captures graphs with guards; Inductor fuses ops and generates Triton/C++ kernels.

SDPA

F.scaled_dot_product_attention → FlashAttention / efficient / cuDNN kernels: exact attention, linear memory.

Memory tools

5 · How it works

Compile modes

modeWhat it does (PyTorch 2.14.1 docstring)
"default"good balance between performance and overhead
"reduce-overhead"reduces Python overhead with CUDA (Compute Unified Device Architecture, NVIDIA's programming platform for its graphics processors) graphs; useful for small batches; more memory
"max-autotune"Triton or template matmuls and convolutions; CUDA graphs on by default on GPU
"max-autotune-no-cudagraphs"like max-autotune without CUDA graphs

Graph breaks in practice

Notebook 07: a function with a data-dependent if and a print becomes several graphs; the clean version is one graph. torch._dynamo.explain reports graph_count, graph_break_count and reasons. Use fullgraph=True to turn breaks into errors.

5 · How it works

Worked example: attention memory

One layer, 32 heads, head dimension 128, BF16 (2 bytes). Notebook 07 computes the sizes.

Worked example

  1. T = 1,024: the score matrix (B·H·T·T) is 0.06 GiB versus 0.023 GiB for q, k and v together.
  2. T = 8,192: scores 4 GiB versus 0.19 GiB for q, k, v: 21× larger, per layer, before softmax copies.
  3. T = 131,072: scores would be 1,024 GiB; q, k, v are 3 GiB. Only fused attention that never materialises the matrix makes this feasible.
  4. The PyTorch 2 paper reports torch.compile speedups of 2.27× (inference) and 1.41× (training), geometric mean over 180+ models on an A100.
Kernel fusion saves memory traffic; fused attention removes the quadratic memory term.
6 · Why it works

Why these help

Fusion

Elementwise chains become one kernel: one read, one write.

Tiling

FlashAttention computes softmax blockwise in on-chip memory (Architecture deck 09).

Guards keep it correct

Compiled code is reused only when shapes, dtypes and globals match; otherwise recompile.

Measurable

Profiler traces and memory stats turn guesses into numbers.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"torch.compile changes results."

It preserves semantics up to floating-point reordering (notebook 07: max difference below 10⁻⁴).

"Compiling always speeds things up."

Small CPU workloads may see nothing (notebook 07); gains are largest on GPUs with fusable ops.

"FlashAttention is approximate."

It computes exact attention with an online softmax.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • mode="reduce-overhead". Uses CUDA graphs; good for small batches and decode.
  • torch._dynamo.explain(fn)(x). Lists graph breaks and their reasons.
  • torch.cuda.max_memory_allocated(). Peak memory; reset with reset_peak_memory_stats().

⚠ Traps

  • Data-dependent Python branches. if x.sum() > 0 breaks the graph.
  • Benchmarking the first call. It includes compilation; warm up first.
  • Recompilation on changing shapes. Mark dynamic dims or pad to buckets.

9 · Key takeaway

Key takeaway

torch.compile captures and fuses your model (Dynamo + AOTAutograd + Inductor), SDPA removes attention's quadratic memory, and memory stats and the profiler tell you what to fix.
Say it in 30 seconds

Eager PyTorch launches a kernel per operation and writes every intermediate to memory. torch compile captures your Python into graphs with TorchDynamo, builds the backward with AOTAutograd, and generates fused Triton or C++ kernels with TorchInductor; the PyTorch 2 paper measured 2.27 times faster inference and 1.41 times faster training on average. Data-dependent branches cause graph breaks, which explain can find. For attention, scaled dot product attention uses fused kernels that never store the T by T score matrix, which at 8,192 tokens is 4 gibibytes per layer. Memory statistics and the profiler show the rest.
