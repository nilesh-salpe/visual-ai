PyTorch for LLMs: key papers

Every paper cited on the decks' Key papers slides, in the order the guide introduces them. Each entry links to the paper and to the decks that use it.

PyTorch: An Imperative Style, High-Performance Deep Learning Library
Paszke et al. · NeurIPS 2019 · cited in Tensors, strides and views, Autograd, nn.Module and a transformer block, The training loop, Data pipelines for LLMs, Putting it together: a tiny GPT

PyTorch's design: eager, Pythonic execution ("code as a model") with efficient C++/CUDA kernels, a caching allocator and reverse-mode autograd.

Tensor Views
PyTorch documentation · docs.pytorch.org 2026 · cited in Tensors, strides and views

Which operations return views that share storage with their base (view, transpose, narrow, expand, …) and when a copy is made.

Autograd mechanics
PyTorch documentation · docs.pytorch.org 2026 · cited in Autograd

How autograd records the graph, saved tensors, no_grad and inference mode, in-place correctness checks and gradient accumulation.

(Beta) Implementing High-Performance Transformers with Scaled Dot Product Attention
PyTorch documentation · docs.pytorch.org 2026 · cited in nn.Module and a transformer block, Performance: compile, SDPA, memory

F.scaled_dot_product_attention and its fused backends (FlashAttention, memory-efficient, cuDNN, math), selectable with sdpa_kernel.

nanoGPT
Karpathy · GitHub 2022 · cited in nn.Module and a transformer block, The training loop, Putting it together: a tiny GPT

A minimal, readable GPT training codebase in PyTorch (model.py + train.py) using SDPA, AdamW with weight-decay groups, cosine schedule, DDP (distributed data parallel) and torch.compile.

FlashAttention-2: Faster Attention with Better Parallelism and Work Partitioning
Dao · ICLR 2024 · cited in nn.Module and a transformer block

Fewer non-matmul FLOPs (floating-point operations), parallelism across the sequence (outer loop over query blocks) and better work split across warps.

Remember: ~2× FA1 (FlashAttention-1); 50–73% of peak on A100
Decoupled Weight Decay Regularization (AdamW)
Loshchilov & Hutter · ICLR 2019 · cited in The training loop

L2 regularization and weight decay differ for adaptive optimizers; applying decay directly to the weights (AdamW) decouples it from the learning rate and improves generalization.

torch.utils.data
PyTorch documentation · docs.pytorch.org 2026 · cited in Data pipelines for LLMs

Dataset, Sampler and DataLoader: batching, collate_fn, worker processes, pinned memory and prefetching.

Automatic Mixed Precision package (torch.amp)
PyTorch documentation · docs.pytorch.org 2026 · cited in Mixed precision in PyTorch

torch.autocast op lists (which ops run in lower precision and which stay in FP32) and GradScaler for FP16 loss scaling.

Remember: GradScaler: init scale 65,536, ×2 growth, ×0.5 backoff, every 2,000 steps
Mixed Precision Training
Micikevicius et al. · ICLR 2018 · cited in Mixed precision in PyTorch

Half-precision weights, activations and gradients with an FP32 master copy of the weights and loss scaling to avoid gradient underflow.

Remember: nearly 2× less memory
A Study of BFLOAT16 for Deep Learning Training
Kalamkar et al. · arXiv 2019 · cited in Mixed precision in PyTorch

BF16 keeps FP32's 8-bit exponent (same range) with a 7-bit mantissa, and trains image, speech, language and recommendation models without hyper-parameter changes.

PyTorch 2: Faster Machine Learning Through Dynamic Python Bytecode Transformation and Graph Compilation
Ansel et al. · ASPLOS 2024 · cited in Performance: compile, SDPA, memory

torch.compile: TorchDynamo captures graphs from Python bytecode with guards and graph breaks; TorchInductor generates Triton (GPU) and C++ (CPU) code.

Remember: 2.27× inference, 1.41× training geomean speedup on A100 (180+ models)
torch.compiler
PyTorch documentation · docs.pytorch.org 2026 · cited in Performance: compile, SDPA, memory

Overview of torch.compile: TorchDynamo graph capture, AOTAutograd, the Inductor backend, compile modes and troubleshooting graph breaks.

CUDA semantics
PyTorch documentation · docs.pytorch.org 2026 · cited in Performance: compile, SDPA, memory

Devices and streams, asynchronous execution, the caching allocator, memory statistics (memory_allocated, max_memory_allocated) and CUDA graphs.

FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness (IO = input/output, memory reads and writes)
Dao et al. · NeurIPS 2022 · cited in Performance: compile, SDPA, memory

Tiles attention so scores never leave on-chip SRAM (static random-access memory, fast on-chip memory), using an online softmax and recomputation in the backward pass. Exact, with memory linear in sequence length.

Remember: GPT-2 medium: 40.3 → 4.4 GB of memory traffic, 41.7 → 7.3 ms
PyTorch Distributed: Experiences on Accelerating Data Parallel Training
Li et al. · VLDB 2020 · cited in Distributed training in PyTorch

PyTorch's DistributedDataParallel design: gradient bucketing, overlapping all-reduce with the backward pass, and skipping synchronization during gradient accumulation.

Remember: near-linear scaling on 256 GPUs
torchrun (Elastic Launch)
PyTorch documentation · docs.pytorch.org 2026 · cited in Distributed training in PyTorch

Launches one process per device and sets RANK, LOCAL_RANK, WORLD_SIZE, MASTER_ADDR and MASTER_PORT; supports multi-node and elastic restarts.

Getting Started with Fully Sharded Data Parallel (FSDP2)
PyTorch documentation · docs.pytorch.org 2026 · cited in Distributed training in PyTorch

fully_shard applied to each transformer block and then the root; parameters become DTensors sharded on dim 0; all-gather before use, reduce-scatter after backward.

PyTorch FSDP: Experiences on Scaling Fully Sharded Data Parallel
Zhao et al. · VLDB 2023 · cited in Distributed training in PyTorch

PyTorch's ZeRO-3-style fully sharded data parallelism, with flattened parameter units, prefetching and hybrid sharding.

Remember: comparable to DDP speed while supporting much larger models
Language Models are Unsupervised Multitask Learners (GPT-2)
Radford et al. · OpenAI 2019 · cited in Putting it together: a tiny GPT

Decoder-only language model that moved layer normalization to the input of each sub-block (pre-norm) and added a final norm.

Remember: context 1,024 tokens, vocabulary 50,257
