PyTorch for LLMs · 01

Tensors, strides and views

What a PyTorch tensor really is (storage, shape, strides, dtype, device), why reshaping attention heads is free, when it is not, and broadcasting and einsum for attention math.

What is the problem?LLM (large language model) code constantly reshapes activations: splitting heads, transposing for attention, broadcasting masks. Done wrong it silently copies gigabytes, or fails with "view size is not compatible".
Core ideaA tensor is a view onto flat storage described by shape and strides (elements to skip per dimension). view, transpose, slicing and expand only change that metadata. After a transpose the tensor is non-contiguous, so view fails and you need reshape or .contiguous().

2 · Limitation

Why this matters for LLM code

Hidden copies

A stray .contiguous() on a (B, H, T, T) tensor copies gigabytes.

Confusing errors

"view size is not compatible" appears exactly where heads are merged after a transpose.

Aliasing

Modifying a view in place modifies the original tensor, including weights.

4 · Core idea

Storage, shape and strides

Storage

A flat 1-D buffer on a device (CPU (central processing unit), CUDA (Compute Unified Device Architecture, NVIDIA's programming platform for its graphics processors)) with one dtype.

Shape + strides

Element [i₀, i₁, …] is at offset + Σ iₖ·stride[k]. Contiguous: strides decrease right to left.

Views

view, transpose/permute, slicing, expand, unsqueeze: new metadata over the same storage.

At a glance

element [i, j] lives at offset + i·stride[0] + j·stride[1]

5 · How it works

Worked example: splitting attention heads

Activations x of shape (B, T, C) = (2, 5, 12), split into H = 3 heads of D = 4. Notebook 01 runs every line.

Worked example

  1. Contiguous strides for (2, 5, 12) are (60, 12, 1): one step in the last dimension moves 1 element, one token moves 12.
  2. x.view(2, 5, 3, 4) is free (strides (60, 12, 4, 1)); .transpose(1, 2) gives shape (2, 3, 5, 4) with strides (60, 4, 12, 1), still free but now non-contiguous.
  3. Merging back with .view(2, 5, 12) on the transposed tensor fails: "view size is not compatible with input tensor's size and stride". .transpose(1, 2).contiguous().view(…) or .reshape(…) copies once and works.
  4. expand gives stride 0 along broadcast dimensions: a (4,) bias expanded to (3, 4) has strides (0, 1) and uses no extra memory.
Shape changes are metadata until a non-contiguous layout forces a copy; know which operations copy.
6 · Why it works

Why strided tensors are a good design

Free reshapes

Most layout changes cost nothing, so code can be written in the most readable shape.

Broadcasting without memory

Stride-0 dimensions let a bias or mask act on a whole batch.

Kernels choose layouts

Fused kernels accept strided inputs; copies happen only where a kernel needs contiguity.

Same API on every device

The metadata model is identical on CPU and GPU (graphics processing unit).

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"reshape and view are the same."

view never copies and fails if strides do not allow it; reshape returns a view when possible and copies otherwise.

"Transpose moves data."

It swaps two strides; the data moves only if you later call contiguous() or an op that needs contiguity.

"Broadcasting allocates the expanded tensor."

Expanded dimensions have stride 0; memory is only used when a result is computed.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • stride[i] = product of later dims. For contiguous tensors.
  • Broadcasting aligns from the right. Size-1 or missing dims stretch.
  • einsum names the math. "bhid,bhjd->bhij" is QKᵀ per head.

⚠ Traps

  • view after transpose. Fails; use reshape or contiguous().
  • Editing a view edits the original. Views share storage (notebook 01 shows x[0,0] change).
  • Silent broadcasting bugs. (B, 1) + (B,) gives (B, B), not (B,).

9 · Key takeaway

Key takeaway

A tensor is storage plus shape and strides: view, transpose, slicing and expand are free metadata changes, and a copy happens only when a non-contiguous layout must become contiguous.
Say it in 30 seconds

A PyTorch tensor is a view onto a flat block of memory, described by its shape and strides, the number of elements to skip per dimension. Operations like view, transpose, slicing and expand only create new metadata over the same storage, which is why splitting attention heads costs nothing. A transpose leaves the tensor non-contiguous, so view can no longer merge dimensions; reshape or contiguous makes one copy. Broadcasting uses stride zero so a bias or mask applies to a whole batch without extra memory, and einsum writes attention math directly.

Problem: reshaping without hidden copies or errors.
Core idea: storage + shape + strides; views share memory.
Rule: transpose → non-contiguous → reshape/contiguous to merge.
