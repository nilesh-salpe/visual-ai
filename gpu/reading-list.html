GPU for GenAI: key papers

Every paper cited on the decks' Key papers slides, in the order the guide introduces them. Each entry links to the paper and to the decks that use it.

NVIDIA H100 Tensor Core GPU Architecture (whitepaper)
NVIDIA · whitepaper 2022 · cited in What a GPU is

The reference for Hopper: SM layout, fourth-generation Tensor Cores, FP8, TMA, thread-block clusters and the memory system.

Remember: 132 SMs (H100 SXM5), 989 TFLOP (trillion floating-point operations)/s dense BF16
Benchmarking and Dissecting the Nvidia Hopper GPU Architecture
Luo et al. · arXiv 2024 · cited in What a GPU is

Microbenchmarks of Hopper's memory hierarchy, FP8 tensor cores and distributed shared memory.

Scaling Laws for Neural Language Models
Kaplan et al. · arXiv 2020 · cited in Why GPUs for AI

Loss falls as a power law in parameters, data and compute; also gives the ≈ 6·N·D training-compute rule of thumb.

Remember: trends spanning more than seven orders of magnitude
PaLM: Scaling Language Modeling with Pathways
Chowdhery et al. · JMLR 2023 · cited in Why GPUs for AI

A 540B dense model trained on TPU (tensor processing unit) v4 Pods; introduces model FLOPs utilization (MFU) as the efficiency metric and uses SwiGLU (Swish-gated linear unit), RoPE (rotary position embedding) and multi-query attention.

The Llama 3 Herd of Models
Llama Team, AI (artificial intelligence) @ Meta · arXiv 2024 · cited in Why GPUs for AI, Inside a GPU server, Cluster topology, GPU failures

Dense Transformer with GQA (8 KV heads), RoPE base 500,000, a 128K vocabulary and a document mask; staged long-context pretraining to 128K; post-training with SFT (supervised fine-tuning), rejection sampling and DPO (Direct Preference Optimization) in six rounds.

Remember: 128K context after six stages over ~800B tokens
Computing's Energy Problem (and what we can do about it)
Horowitz · ISSCC 2014 · cited in Memory hierarchy

Energy per operation vs per memory access: moving data costs far more than computing on it.

FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness
Dao et al. · NeurIPS 2022 · cited in Memory hierarchy

Tiles attention so scores never leave on-chip SRAM, using an online softmax and recomputation in the backward pass. Exact, with memory linear in sequence length.

Remember: GPT-2 medium: 40.3 → 4.4 GB of memory traffic, 41.7 → 7.3 ms
ZeRO: Memory Optimizations Toward Training Trillion Parameter Models
Rajbhandari et al. · SC 2020 · cited in Memory hierarchy

Partitions optimizer states, gradients and parameters across data-parallel workers instead of replicating them.

Remember: 100B+ parameters on 400 GPUs at 15 PFLOP (quadrillion floating-point operations)/s; 8× larger models than prior state of the art
Efficient Memory Management for Large Language Model Serving with PagedAttention
Kwon et al. · SOSP 2023 · cited in Memory hierarchy

Stores the KV cache in fixed-size blocks mapped by a block table, like virtual memory pages, giving near-zero fragmentation and sharing with copy-on-write. The basis of vLLM.

Remember: 2–4× throughput vs FasterTransformer and Orca at the same latency
NVIDIA GB200 NVL72
NVIDIA · product page 2024 · cited in Inside a GPU server

A rack-scale NVLink domain: 72 Blackwell GPUs connected all-to-all by NVLink switches.

Remember: 130 TB/s aggregate NVLink bandwidth
Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM
Narayanan et al. · SC 2021 · cited in Cluster topology

Combines tensor, pipeline and data parallelism (PTD-P) with an interleaved pipeline schedule, placing tensor parallelism inside nodes.

Remember: 1T parameters at 502 PFLOP (quadrillion floating-point operations)/s on 3,072 GPUs, 52% of peak
NVIDIA Collective Communications Library (NCCL) documentation
NVIDIA · docs 2024 · cited in Cluster topology

The library that implements all-reduce, all-gather, reduce-scatter, broadcast and all-to-all over NVLink and the network, choosing ring or tree algorithms.

MegaScale: Scaling Large Language Model Training to More Than 10,000 GPUs
Jiang et al. · NSDI 2024 · cited in GPU failures

Production training system at ByteDance: algorithm-system co-design plus diagnosis tools for stragglers and failures at 10,000+ GPU scale.

Remember: 55.2% MFU (model floating-point-operation utilization, the share of peak compute spent on the model's math) on 12,288 GPUs (175B model), 1.34× Megatron-LM
Silent Data Corruptions at Scale
Dixit et al. · arXiv 2021 · cited in GPU failures

Meta's account of silent data corruption: defective silicon that returns wrong results without raising errors, how one case was debugged, and mitigations.

Cores that don't count
Hochschild et al. · HotOS 2021 · cited in GPU failures

Google's report that a few "mercurial" CPU cores in a large fleet silently compute wrong answers.

Splitwise: Efficient Generative LLM (large language model) Inference Using Phase Splitting
Patel et al. · ISCA 2024 · cited in Heterogeneous GPUs

Characterizes prompt computation as compute-intensive and token generation as memory-intensive, and splits them onto separate machines, possibly of different GPU types.

Remember: 1.4× throughput at 20% lower cost, or 2.35× throughput at the same cost and power
DistServe: Disaggregating Prefill and Decoding for Goodput-optimized Large Language Model Serving
Zhong et al. · OSDI 2024 · cited in Heterogeneous GPUs

Defines serving quality as goodput, the request rate served within both TTFT and TPOT targets, and runs prefill and decode on separate GPUs so they stop interfering.

Remember: 7.4× more requests or 12.6× tighter SLO than colocated systems
Mooncake: A KVCache-centric Disaggregated Architecture for LLM Serving
Qin et al. · arXiv 2024 · cited in Heterogeneous GPUs

Kimi's serving platform: separate prefill and decode clusters with a disaggregated KV cache pool built from CPU (central processing unit), DRAM (dynamic random-access memory) and SSD (solid-state drive) resources.

Remember: 75% more requests on real workloads
NVIDIA Multi-Instance GPU User Guide
NVIDIA · docs 2024 · cited in Sharing GPUs

How to partition a supported GPU into hardware-isolated instances with dedicated SMs, L2 slices and memory.

Remember: up to 7 instances per H100
Orca: A Distributed Serving System for Transformer-Based Generative Models
Yu et al. · OSDI 2022 · cited in Sharing GPUs

Iteration-level scheduling (requests join and leave the batch after every decode step) plus selective batching (batch the matmuls, run attention per request).

Remember: 36.9× throughput over FasterTransformer at the same latency (GPT-3 175B)
S-LoRA: Serving Thousands of Concurrent LoRA Adapters
Sheng et al. · MLSys 2024 · cited in Sharing GPUs

Keeps adapters in host memory, pages them into a unified GPU memory pool and batches requests for different adapters together.

Remember: up to 4× throughput vs Hugging Face PEFT (parameter-efficient fine-tuning) and naive vLLM LoRA
Punica: Multi-Tenant LoRA Serving
Chen et al. · MLSys 2024 · cited in Sharing GPUs

A CUDA (Compute Unified Device Architecture, NVIDIA's programming platform for its graphics processors) kernel (SGMV) that batches requests for many different LoRA adapters through one shared base model.

Remember: 12× throughput, +2 ms latency per token
