The memory hierarchy:
where performance is decided

Most GPU performance work is about not moving bytes. This deck goes level by level from registers out to NVMe, then covers the techniques that keep data close to the compute: tiling, fusion, FlashAttention and paged KV caches.

02 · The levels

Fetching a number from DRAM costs ~170× more energy than multiplying it

The gap shows up in energy as well as time. A chip that ships every operand to and from DRAM would spend most of its power budget moving data.

Energy per operation, 45 nm process (log scale). Newer nodes shrink every number, but the ratio between arithmetic and off-chip access has stayed huge.

This is the physics behind every optimization in this deck: reuse data that is already on-chip and avoid round trips to HBM.
M. Horowitz, "Computing's Energy Problem (and what we can do about it)", ISSCC 2014.
03 · Keep data close

Tiling: load a block into shared memory once, then use it T times

A naive matmul reads A[i,k] and B[k,j] from memory for every multiply-add. A tiled kernel loads a T×K strip of A and a K×T strip of B into SRAM, computes a whole T×T output tile from them, and so cuts memory traffic by a factor of T.

loaded into SMs
FLOPs per byte loaded

Model: square output tiles, BF16 values. Real GEMMs also order their tiles so that neighbouring blocks reuse each other's strips in L2, which cuts HBM traffic further.

Tile size is limited by SRAM capacity (228 KB of shared memory per SM) and registers. That limit is why kernel writers obsess over tile shapes, and why Hopper added TMA to copy tiles asynchronously.
04 · Keep data close

Kernel fusion: one trip to HBM instead of five

After a GEMM, a typical MLP block runs bias-add → GELU → dropout → residual-add. Run as separate kernels, each one reads the whole tensor from HBM and writes it back. A fused kernel keeps the values in registers.

That is what torch.compile (Inductor + Triton), XLA, and hand-written fused kernels do. Fusion doesn't reduce the FLOPs at all; the speedup comes from fewer bytes moved and fewer kernel launches.
05 · Keep data close

FlashAttention never writes the N×N attention matrix to HBM

Standard attention writes S = QKᵀ (N×N) to HBM, reads it back for softmax, then writes and reads it again for the weighted sum. FlashAttention streams K/V tiles through SRAM and uses an online softmax (a running max and running sum), so the full matrix never exists in memory.

Memory for scores (per head)

HBM traffic for attention (per head)

Model: head dim 128, BF16, 128-row tiles. The standard version runs scale, mask, softmax and dropout as separate kernels.

Score memory drops from O(N²) to O(N), and HBM traffic drops several-fold. The FLOPs are the same or slightly higher (there is recomputation in the backward pass), yet it runs 2–4× faster. That is the clearest example of attention being limited by IO rather than compute.
Dao et al., "FlashAttention" (2022); FlashAttention-2 (2023); FlashAttention-3 (2024, Hopper: async TMA + FP8).
06 · Capacity

Training memory: 16 bytes per parameter before activations

Mixed-precision Adam stores BF16 weights (2 B) + BF16 gradients (2 B) + FP32 master weights, momentum and variance (12 B). ZeRO and FSDP shard these across data-parallel ranks.

weights (BF16)gradients (BF16)optimizer state (FP32 ×3)80 GB H100 limit

Not included: activations, which scale with batch × sequence × layers and are often the largest item. They are reduced with activation checkpointing, sequence/context parallelism, or offloading.

A 70B model needs about 1.1 TB just for weights and optimizer state. That is why training is always sharded, and why FSDP and ZeRO-3 add an all-gather of the weights before every layer.
Rajbhandari et al., "ZeRO: Memory Optimizations Toward Training Trillion Parameter Models" (2020).
07 · Capacity

In inference, the KV cache uses up HBM capacity

KV bytes = 2 × layers × kv_heads × head_dim × bytes × tokens × batch. It grows linearly with context and with the number of concurrent users.

GQA (8× fewer KV heads than query heads), FP8 KV and MLA all exist to shrink this number. Every byte saved means more concurrent users, and decode reads less memory per step.
08 · Capacity

PagedAttention: virtual memory for the KV cache

Early servers reserved one contiguous KV buffer per request, sized for max length. Most requests finish early, so most of that space was never used. vLLM allocates fixed-size blocks on demand, the way an OS allocates pages.

The vLLM paper measured 60–80% KV memory waste in earlier systems, compared with under 4% using paging. Paging also enables prefix sharing: requests with a common system prompt point to the same blocks.
Kwon et al., "Efficient Memory Management for Large Language Model Serving with PagedAttention", SOSP 2023.
09 · Beyond the GPU

Off-GPU memory is huge but sits behind a narrow pipe

Offloading weights, optimizer state or KV cache to CPU RAM or NVMe buys capacity, but every byte has to come back through PCIe. Drag to see how long it takes to move a given amount of data at each level.

Per-GPU, one direction: HBM3 3.35 TB/s · NVLink 4 450 GB/s · PCIe Gen5 x16 ~64 GB/s · 400 Gb/s NIC 50 GB/s · local NVMe ~7 GB/s per drive.

Offloading works when the transfer can be overlapped with compute: ZeRO-Offload optimizer steps, prefetching the next layer's weights, or a tiered KV cache for idle chat sessions. It fails when a transfer sits on the critical path of every token.
10 · Test yourself

Questions to test your understanding

Explain why FlashAttention is faster when it does the same FLOPs.
Standard attention is IO-bound: it writes the N×N score matrix to HBM and reads it back several times (for scale, mask, softmax and the matmul with V). FlashAttention tiles Q, K and V into SRAM, computes softmax incrementally (online softmax with a running max and sum), and writes only the N×d output. HBM traffic drops and memory goes from O(N²) to O(N). In the backward pass it recomputes the scores instead of storing them, which is extra FLOPs, and it is still faster.
How much KV cache does a 70B model need for 32 users at 8K context?
2 × 80 layers × 8 KV heads × 128 × 2 bytes = 320 KB per token. × 8,192 × 32 ≈ 86 GB, on top of 140 GB of weights. You need at least 4 × 80 GB GPUs, or FP8 KV to halve it. Without GQA (64 KV heads) it would be 8× larger, about 690 GB.
How much memory does it take to train a 7B model with Adam, and how do you fit it?
16 B/param × 7B = 112 GB of states, plus activations. That doesn't fit on one 80 GB GPU. Options: ZeRO-2 or 3 / FSDP across 8 GPUs (≈14 GB/GPU of states), activation checkpointing, 8-bit optimizers, or CPU offload of optimizer state. Explain each trade-off: more communication, recompute cost, PCIe bandwidth.
What is kernel fusion, and when doesn't it help?
Fusion merges several ops into one kernel so that intermediate values stay in registers or SRAM, which saves HBM round trips and launches. It helps memory-bound chains (elementwise ops, norms, softmax). It helps little for big compute-bound GEMMs, beyond fusing their epilogue. It can hurt if the fused kernel needs too many registers, which lowers occupancy.
Why is shared memory faster than L1 or L2 if it's the same SRAM?
On Hopper, L1 and shared memory are the same 256 KB physical SRAM per SM, split by configuration. Shared memory is managed by the programmer, so you place exactly the tile you will reuse there, with no misses or evictions. L2 (50 MB) is shared across all SMs, farther away and slower. Distributed shared memory on H100 also lets SMs in a cluster read each other's shared memory.
11 · Take it with you

Four things to remember

The levels are registers → SMEM/L1 → L2 → HBM → NVLink peers → host DRAM → NVMe. Each step down is bigger and slower; HBM is about 3 TB/s and PCIe about 64 GB/s.
Most optimizations are about reuse: tiling (GEMM), fusion (elementwise chains) and IO-aware algorithms (FlashAttention).
Training memory is 16 B/param plus activations, so it is sharded with ZeRO/FSDP. Inference memory is weights + KV cache, managed with paging, GQA and FP8.
Offloading only pays off when the transfer overlaps with compute. If it's on the critical path, the PCIe link becomes the limit.
