GPU for GenAI · 04

Inside a GPU server:
8 GPUs, 4 switches, 1 box

The 8-GPU HGX/DGX node is the basic unit of AI (artificial intelligence) infrastructure. This deck shows what is inside it, how data moves between its parts, and which link is the bottleneck for each kind of traffic.

Press → or Space to begin.

01 · The box

An HGX H100 node, opened up

Hover or tap any component. Two separate networks run through this box: NVLink connects the GPUs (graphics processing units) to each other through NVSwitch, and PCIe (PCI (Peripheral Component Interconnect) Express, the standard expansion bus) connects the GPUs to the CPUs (central processing units), NICs (network interface cards) and storage.

DGX H100: 8× H100 SXM (640 GB HBM3 (third-generation high-bandwidth memory) in total), 4× NVSwitch, 8× ConnectX-7 400 Gb/s compute NICs, 2× Xeon CPUs, 2 TB DDR5 (fifth-generation double-data-rate memory), about 30 TB of NVMe (Non-Volatile Memory Express, the fast interface for flash storage), up to about 10.2 kW.
NVIDIA DGX H100 user guide and datasheet. PCIe switch arrangement simplified; it varies by OEM (HGX boards go into Dell, Supermicro, HPE and other servers).

Inside the node a GPU gets about 450 GB/s per direction; to another node it gets about 50 GB/s. That 9× gap determines how every parallelism strategy is mapped onto the hardware: tensor parallelism stays on NVLink, and only data and pipeline parallelism cross the network.

All-reduce time ≈ 2·(n−1)/n × size ÷ per-GPU bandwidth, ignoring latency. Default: 7 GB, the BF16 (bfloat16, a 16-bit floating-point format with the exponent range of 32-bit floats) gradients of a 3.5B model. In-node bandwidth uses 450 GB/s; the NVLink SHARP (Scalable Hierarchical Aggregation and Reduction Protocol, in-network reduction on NVIDIA switches) in-switch reduction on NVSwitch can do better.

Per GPU and per direction: HBM (high-bandwidth memory) 3,350 · NVLink 450 · PCIe Gen5 64 · NIC 50 · NVMe ~7 GB/s. Memorize these five numbers.

Worked example

  1. HBM: 1 GB ÷ 3,350 GB/s = 0.3 ms.
  2. NVLink: 1 GB ÷ 450 GB/s = 2.2 ms.
  3. PCIe Gen5: 1 GB ÷ 64 GB/s = 15.6 ms.
  4. NIC (400 Gb/s): 1 GB ÷ 50 GB/s = 20.0 ms.
  5. NVMe: 1 GB ÷ 7 GB/s = 142.9 ms.
  6. Implication: keep tensor-parallel traffic on NVLink, data-parallel gradients on the network, and checkpoints off the critical path.
The same gigabyte takes 0.3 ms in HBM and 143 ms from NVMe: placement decides speed.
04 · Affinity

nvidia-smi topo -m: which GPUs, NICs and CPUs are close to each other

A node has two CPU sockets (two NUMA (non-uniform memory access) domains). If a dataloader on socket 1 feeds GPU 0, or GPU 0 sends through a NIC on the other socket, traffic crosses the inter-socket link (UPI (Intel's Ultra Path Interconnect between CPU sockets)) and loses bandwidth. NCCL (NVIDIA Collective Communications Library) reads this topology and picks the NIC for each GPU, ideally PIX. When jobs are slow, check the pinning: numactl and CPU affinity for dataloaders, and NCCL_IB_HCA or NCCL_TOPO_FILE when auto-detection gets it wrong (common in VMs (virtual machines)).

05 · Power

Power is the real limit: a cluster's capacity is set by megawatts

systems per rack
GPUs per rack
racks for the cluster
facility power

Typical air-cooled data-center racks were designed for about 10–20 kW. A single DGX H100 nearly fills one. Blackwell rack-scale systems need direct liquid cooling. PUE (power usage effectiveness) = facility power ÷ IT (information technology) power.

"Why don't you just add more GPUs?" Because of power, cooling and floor space. A 16K-GPU H100 cluster draws about 25 MW, which is roughly the consumption of a small town.
06 · Scale-up

The NVLink domain grows from 8 GPUs to 72

GB200 NVL72 puts 72 Blackwell GPUs and 36 Grace CPUs in one rack, all connected through NVLink switch trays. Every GPU can reach every other GPU at 1.8 TB/s, so the whole rack works like one big GPU for tensor and expert parallelism.

A bigger scale-up domain means tensor parallelism and MoE (Mixture of Experts) all-to-all traffic can span more GPUs without touching the slower network. Frontier labs care about this because MoE inference is limited by all-to-all bandwidth.
NVIDIA GB200 NVL72 product page: 72 GPUs, 130 TB/s aggregate NVLink, ~13.5 TB HBM3e. HGX H100: 900 GB/s per GPU over NVLink 4.
07 · In practice

A node is slow. What do you check?

1 · Clocks and throttling

nvidia-smi -q -d PERFORMANCE,CLOCK,POWER,TEMPERATURE: look for thermal or power-cap throttling, or clocks locked low. One hot GPU slows the whole job.

2 · Errors

dmesg | grep -i xid, ECC (error-correcting code) counters and row remapping (nvidia-smi -q -d ECC,ROW_REMAPPER), NVLink error counters.

3 · Topology and links

nvidia-smi topo -m, nvidia-smi nvlink -s (are all links up?), lspci -vv for the negotiated PCIe width and speed (x16 Gen5, not x8 Gen3).

4 · Microbenchmarks

dcgmi diag -r 3, nccl-tests all_reduce_perf (compare busbw with a known-good node), and a GEMM (general matrix multiplication) burn-in to check sustained TFLOPS (trillion floating-point operations per second).

Labs run these as preflight checks before admitting a node into a training job, and keep a quarantine pool for nodes that fail. Deck 06 covers this in detail.
Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Memorize the ladder. HBM 3,350 · NVLink 450 · PCIe 64 · NIC 50 · NVMe 7 GB/s.
  • Check affinity. nvidia-smi topo -m shows which NIC and CPU socket sit closest to each GPU.
  • Power sets capacity. A DGX H100 draws ~10.2 kW; racks are sized in kilowatts, not GPUs.

⚠ Traps

  • Cross-socket traffic. A GPU using a NIC on the other CPU socket pays extra hops.
  • PCIe as GPU-to-GPU path. Without NVLink, tensor parallelism is much slower.
  • Ignoring thermals. Hot GPUs throttle clocks and become stragglers.
08 · Test yourself

Questions to test your understanding

Walk me through what's in an 8×H100 server and how the GPUs talk.
There are 8 SXM GPUs on an HGX baseboard. Each has 18 NVLink 4 links that go to 4 NVSwitch chips, so any GPU can reach any other at 900 GB/s bidirectional, all-to-all, without blocking. Separately, PCIe Gen5 switches connect GPUs to one 400G NIC per GPU (ConnectX-7, used with GPUDirect RDMA), to NVMe, and to the 2 CPU sockets. The CPUs handle orchestration and data loading but sit off the hot path.
What does GPUDirect RDMA do and why does it matter?
It lets the NIC read and write GPU memory directly over PCIe, with no staging copy in host DRAM (dynamic random-access memory) and no CPU involvement. Without it, every inter-node message is copied GPU → host → NIC, which doubles the PCIe traffic, adds latency and uses CPU memory bandwidth. NCCL depends on it for inter-node collectives. GPUDirect Storage does the same for NVMe and parallel file systems.
Why is there one NIC per GPU?
So that each GPU gets its own 400 Gb/s (50 GB/s) path to the network behind a nearby PCIe switch (PIX affinity), which avoids PCIe and UPI contention. It also matches the rail-optimized network design: GPU i in every node connects to the same leaf switch (rail i). See deck 05.
Can you train with PCIe H100 cards instead of SXM? What changes?
PCIe H100s have a lower TDP (about 350 W vs 700 W), fewer SMs (streaming multiprocessors) and lower HBM bandwidth, and only an optional NVLink bridge between pairs rather than NVSwitch all-to-all. Tensor parallelism across 8 GPUs would then go over PCIe (~64 GB/s), which is far too slow. They suit inference of models that fit on 1–2 GPUs, but not large-scale training.
What's the practical limit on how many H100s you can put in a data hall?
Power and cooling, not floor space. Each DGX H100 draws about 10 kW, so a 16K-GPU cluster is about 20 MW of IT load and about 25 MW of facility load at PUE 1.2. Many existing data centers can't deliver 40+ kW per rack, which is why new AI builds are designed around power and use liquid cooling for Blackwell-class racks.
09 · Take it with you

Four things to remember

There are two fabrics in the box: NVLink/NVSwitch (GPU↔GPU, 900 GB/s bidirectional) and PCIe (GPU↔NIC, NVMe and CPU, ~64 GB/s per direction).
One 400G NIC per GPU, with GPUDirect RDMA, gives about 50 GB/s per GPU off the node, roughly 9× less than NVLink.
Topology and NUMA affinity matter. Check them with nvidia-smi topo -m; wrong pinning quietly costs bandwidth.
Power is the binding constraint. NVL72-style racks make the scale-up domain bigger at about 120 kW per rack.
