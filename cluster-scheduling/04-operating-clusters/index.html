Operating a training cluster

Keeping thousands of GPUs (graphics processing units) productive: health checks and draining, automatic requeue and restart from checkpoint, preemption with grace periods, and how labs choose between Slurm and Kubernetes.

What is the problem?At thousands of GPUs, hardware failures arrive every few hours (see the GPU failures deck). Without automation each failure means a person finds the bad node, removes it, and restarts the job by hand while the rest of the cluster sits idle.
Core ideaClose the loop automatically: detect bad nodes (health checks, failed jobs), drain them so no new work lands there, requeue the affected job, restart it from the latest checkpoint on healthy nodes, and repair or reboot the node before returning it. Preemption uses the same path with a grace period to checkpoint. Choose the scheduler by workload mix: Slurm for large batch training, Kubernetes with Kueue when training shares a platform with services.

1 · Problem

Failures are routine at scale

Frequent interruptions

Llama 3 405B pretraining saw 466 job interruptions in 54 days, 419 unexpected (GPU failures deck).

One node stops everything

A synchronous job runs at the speed of its slowest or broken rank.

Manual recovery is slow

Finding, draining and restarting by hand turns minutes of failure into hours of idle GPUs.

2 · Core idea

Detect, drain, requeue, restart

Detect

Periodic health checks (Slurm HealthCheckProgram every HealthCheckInterval seconds), job-level watchdogs, and GPU error counters.

Drain

DRAIN prevents additional jobs from running on a node while running work finishes; Slurm also drains nodes that report fewer GPUs than configured.

Requeue and restart

Slurm requeues batch jobs when JobRequeue=1 (the default) or --requeue; JobSet recreates the whole set; the job resumes from its latest checkpoint.

Grace for preemption

Slurm sends SIGTERM at once and SIGKILL after GraceTime: enough time to save a checkpoint if the job traps the signal.

4 · Low-level design

Preemption without losing work

import signal, sys

def on_sigterm(signum, frame):        # preemption or shutdown: grace period has started
    save_checkpoint(step)              # must finish before GraceTime runs out
    sys.exit(0)                        # the scheduler requeues the job (--requeue)

signal.signal(signal.SIGTERM, on_sigterm)
5 · Trade-offs

Slurm or Kubernetes?

Question Slurm Kubernetes + Kueue
All-at-once allocation built in (a job gets all its nodes together) Kueue admission + waitForPodsReady
Backfill built-in plugin with time limits BestEffortFIFO lets fitting jobs pass; no reservation-based backfill like Slurm's
Topology tree, block, ring, torus3d plugins Kueue topology-aware scheduling (beta), JobSet exclusive placement
Services and inference not its strength native (deployments, autoscaling)
Containers supported (OCI (Open Container Initiative) containers, plugins) native
Typical fit large batch pretraining on fixed clusters mixed training + inference platforms, cloud elasticity
6 · Failure modes

Failure modes

Failure Symptom Mitigation
Flapping node jobs keep landing on a node that fails again drain on first failure; burn-in tests before returning it
Checkpoints too rare each failure loses hours pick the interval from MTBF (mean time between failures) and save cost (Young/Daly, GPU failures deck)
Signal not handled preemption kills the job without saving trap SIGTERM; set GraceTime long enough to checkpoint
Silent data corruption loss spikes with no crash numerical checks; isolate and test suspect GPUs
Restart storms many jobs restart at once and overload storage stagger restarts; scale checkpoint storage
7 · Challenges in production

In production

Goodput

Measure the share of GPU time spent on useful training steps, not just allocated GPUs.

Spare capacity

Keep hot-spare nodes so restarts do not wait for repairs.

Burn-in

Stress-test new and repaired nodes before they join the pool.

Automate the loop

Detection, drain, requeue and repair should not need a human for routine failures.

slurm.conf and scontrol reference
SchedMD · slurm.schedmd.com 2026

HealthCheckProgram runs as root on all compute nodes every HealthCheckInterval seconds (0 disables it); JobRequeue=1 (default) lets batch jobs be requeued; the DRAIN state prevents additional jobs from running on a node.

Preemption
SchedMD · slurm.schedmd.com 2026

PreemptType none / partition_prio / qos; PreemptMode CANCEL, REQUEUE (only with --requeue or JobRequeue=1), SUSPEND (with GANG), GANG (time-slicing jobs in a partition), OFF; GraceTime sends SIGCONT and SIGTERM at once and SIGKILL at the new end time.

Setup All-or-nothing with ready Pods (waitForPodsReady)
Kubernetes SIG (special interest group) Scheduling · kueue.sigs.k8s.io 2026

Kueue watches an admitted workload until all its pods are ready; if not within the timeout (default 30 minutes) it is evicted and requeued with exponential backoff (60 s up to 3,600 s), which breaks partial-allocation deadlocks between distributed jobs.

JobSet overview
Kubernetes SIG Apps · jobset.sigs.k8s.io 2026

A group of Kubernetes Jobs managed as a unit: separate templates per replicated job, the whole set recreated on failure per its failure policy, exclusive placement per topology domain, and a headless service for pod discovery.
