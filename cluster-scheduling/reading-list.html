Cluster scheduling: key papers

Every paper cited on the decks' Key papers slides, in the order the guide introduces them. Each entry links to the paper and to the decks that use it.

Scheduling Configuration Guide (Slurm 26.05)
SchedMD · slurm.schedmd.com 2026 · cited in Scheduling a GPU cluster, Slurm for GPU clusters

The main scheduler tests jobs in strict priority order per partition (sched_interval 60 s); backfill starts lower-priority jobs that do not delay higher-priority ones and needs realistic time limits (bf_interval 30 s, bf_window 1,440 min, bf_max_job_test 100, bf_resolution 60 s).

Multifactor Priority Plugin
SchedMD · slurm.schedmd.com 2026 · cited in Scheduling a GPU cluster, Slurm for GPU clusters

Priority = weighted sum of factors in [0, 1] (age, association, fair-share, job size, partition, QOS, site, TRES (trackable resources)) minus nice; every weight defaults to 0; PriorityDecayHalfLife defaults to 7 days; Fair Tree is the default fair-share algorithm since 19.05.

Kueue overview
Kubernetes SIG (special interest group) Scheduling · kueue.sigs.k8s.io 2026 · cited in Scheduling a GPU cluster, Kubernetes for GPU workloads

Kubernetes-native job queueing: decides when a job waits, is admitted or is preempted; quotas and fair sharing, resource flavors, admission checks, all-or-nothing scheduling with a timeout, topology-aware scheduling; integrates with Jobs, JobSet, Ray and Kubeflow Trainer.

Setup All-or-nothing with ready Pods (waitForPodsReady)
Kubernetes SIG Scheduling · kueue.sigs.k8s.io 2026 · cited in Scheduling a GPU cluster, Kubernetes for GPU workloads, Operating a training cluster

Kueue watches an admitted workload until all its pods are ready; if not within the timeout (default 30 minutes) it is evicted and requeued with exponential backoff (60 s up to 3,600 s), which breaks partial-allocation deadlocks between distributed jobs.

Slurm Workload Manager overview
SchedMD · slurm.schedmd.com 2026 · cited in Slurm for GPU clusters

Three functions (allocate access to resources, launch and monitor work, arbitrate contention via a queue); slurmctld central manager with optional backup, slurmd on each node, optional slurmdbd accounting; nodes, partitions, jobs and job steps.

Generic Resource (GRES) Scheduling
SchedMD · slurm.schedmd.com 2026 · cited in Slurm for GPU clusters

GPUs as GRES (gres.conf, AutoDetect=nvml); --gres=gpu:N per node, --gpus per job, --gpus-per-node/-task; CUDA_VISIBLE_DEVICES set per step; MIG (Multi-Instance GPU, hardware partitioning of one GPU) instances as GPUs (pre-partitioned); gres/shard sharing without isolation; nodes with fewer resources than configured are drained.

Classic Fairshare Algorithm
SchedMD · slurm.schedmd.com 2026 · cited in Slurm for GPU clusters

F = 2^(−U/S) (refined with effective usage UE through the account tree), with usage decayed by PriorityDecayHalfLife; still available with PriorityFlags=NO_FAIR_TREE.

Topology Guide
SchedMD · slurm.schedmd.com 2026 · cited in Slurm for GPU clusters

topology/tree (lowest switch that fits, best-fit leaf switches; --switches=count@time), topology/block (fixed-size blocks to reduce fragmentation; --segment), topology/ring (26.05) and topology/torus3d.

Preemption
SchedMD · slurm.schedmd.com 2026 · cited in Slurm for GPU clusters, Operating a training cluster

PreemptType none / partition_prio / qos; PreemptMode CANCEL, REQUEUE (only with --requeue or JobRequeue=1), SUSPEND (with GANG), GANG (time-slicing jobs in a partition), OFF; GraceTime sends SIGCONT and SIGTERM at once and SIGKILL at the new end time.

NVIDIA acquires open-source workload management provider SchedMD
NVIDIA · NVIDIA Blog 2025 · cited in Slurm for GPU clusters

NVIDIA acquired SchedMD, Slurm's main developer, on 15 December 2025 and said it will keep Slurm open-source and vendor-neutral; Slurm runs on more than half of the top 10 and top 100 TOP500 systems.

Schedule GPUs (Kubernetes)
Kubernetes documentation · kubernetes.io 2026 · cited in Kubernetes for GPU workloads

Vendor device plugins expose resources such as nvidia.com/gpu; GPUs are specified in limits (requests default to and must equal limits); node labels, selectors and Node Feature Discovery target GPU types.

Dynamic Resource Allocation (Kubernetes)
Kubernetes documentation · kubernetes.io 2026 · cited in Kubernetes for GPU workloads

Stable since v1.35 (first in v1.30): DeviceClasses, ResourceClaims and ResourceSlices; devices can be shared through a claim and filtered with CEL expressions, unlike device plugins with per-container requests.

Cluster Queue (Kueue)
Kubernetes SIG Scheduling · kueue.sigs.k8s.io 2026 · cited in Kubernetes for GPU workloads

Cluster-scoped quotas per ResourceFlavor (nominalQuota, borrowingLimit, lendingLimit); cohorts share unused quota; StrictFIFO or BestEffortFIFO (default); preemption withinClusterQueue and reclaimWithinCohort default to Never.

Topology Aware Scheduling (Kueue)
Kubernetes SIG Scheduling · kueue.sigs.k8s.io 2026 · cited in Kubernetes for GPU workloads

Beta and on by default since Kueue 0.14: a Topology object over node labels (block, rack, node); podset-required-topology keeps all pods in one domain, podset-preferred-topology tries and moves up a level.

JobSet overview
Kubernetes SIG Apps · jobset.sigs.k8s.io 2026 · cited in Kubernetes for GPU workloads, Operating a training cluster

A group of Kubernetes Jobs managed as a unit: separate templates per replicated job, the whole set recreated on failure per its failure policy, exclusive placement per topology domain, and a headless service for pod discovery.

slurm.conf and scontrol reference
SchedMD · slurm.schedmd.com 2026 · cited in Operating a training cluster

HealthCheckProgram runs as root on all compute nodes every HealthCheckInterval seconds (0 disables it); JobRequeue=1 (default) lets batch jobs be requeued; the DRAIN state prevents additional jobs from running on a node.

The Llama 3 Herd of Models
Llama Team, AI (artificial intelligence) @ Meta · arXiv 2024 · cited in Operating a training cluster

Dense Transformer with GQA (8 KV (key-value) heads), RoPE (rotary position embedding) base 500,000, a 128K vocabulary and a document mask; staged long-context pretraining to 128K; post-training with SFT (supervised fine-tuning), rejection sampling and DPO (Direct Preference Optimization) in six rounds.
