Speculative decoding

Draft several tokens with a small model, verify them all in one pass of the large model, and keep exactly the large model's output distribution (Leviathan et al., ICML 2023; Chen et al., 2023).

What is the problem?Decode produces one token per full read of the model's weights. The GPU waits on memory while its compute sits mostly idle, and tokens can't be generated in parallel because each depends on the last.
Core ideaA cheap draft model proposes γ tokens; the target model scores all of them in one forward pass; a modified rejection rule accepts a prefix of them, so the output distribution is unchanged.
1 · Problem

Decode is slow for a reason that has nothing to do with compute

At batch 1, every decode step reads all the weights, about 140 GB for a 70B model in BF16, to produce one token. Scoring several tokens in the same pass costs almost the same, because the memory read is the bottleneck, not the math (GPU deck 02).

If we knew which tokens to score, we could check several of them for about the price of one step.
2 · Limitation

The obvious shortcuts break something

Just use a small model

Fast, but the quality is the small model's, not the large one's.

Generate in parallel

Impossible directly: token t+1 depends on token t (autoregression).

Bigger batches

Help throughput across users, but don't make one user's stream faster.

3 · Your turn

Faster, without changing the output

How can a large model generate faster without changing what it would output?

B. Verification of γ drafted positions happens in one target forward pass. With the modified rejection rule, the accepted tokens are distributed exactly as if the target had sampled them itself.
4 · Core idea

Draft, verify, accept or reject

1. Draft

The draft model q samples γ tokens autoregressively. It's cheap because it's small (often about two orders of magnitude smaller, per Leviathan et al.).

2. Verify

The target model p scores all γ positions plus one extra in a single forward pass.

3. Accept or reject

Accept draft x with probability min(1, p(x)/q(x)). On the first rejection, sample a replacement from norm(max(0, p − q)) and stop.

4. Bonus token

If all γ are accepted, sample one more token from p for free. Each pass yields 1 to γ+1 tokens.

5 · How it works

How many tokens per target pass, and how much faster?

If each draft token is accepted with probability α, the expected tokens per target pass is (1 − αγ+1) / (1 − α) (Leviathan et al., eq. 1). With draft cost c relative to the target, the wall-clock improvement is that divided by (γc + 1) (Theorem 3.8).

6 · Why it works

Why it works

Exactness

The rejection rule makes the output distribution identical to the target's. Leviathan et al. report identical outputs, and Chen et al. preserve it "within hardware numerics". Build-it notebook 09 checks this by Monte Carlo.

Spare compute

Decode is memory-bound, so verifying γ+1 positions costs about one step. Accepted drafts are close to free tokens.

Measured

2–3× on T5-XXL (Leviathan et al.); 2–2.5× on Chinchilla 70B (Chen et al.).

Limit

Even with a free draft (c ≈ 0), the speedup is bounded by 1/(1 − α), so the acceptance rate matters most.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Speculative decoding trades quality for speed."

The output distribution is exactly the target model's. Only latency changes.

"It only works with greedy decoding."

The modified rejection sampling works for sampling too, which is the setting both papers address.

"A longer draft (bigger γ) is always faster."

Each extra draft token costs c and is less likely to be accepted. The best γ depends on α and c.

What is the maximum possible speedup as γ → ∞ with a free draft model (c = 0)?

1 / (1 − α), e.g. 5× for α = 0.8. Throughput per target pass is capped by the acceptance rate.

On rejecting draft x at position i, what is the replacement token sampled from?

The residual distribution norm(max(0, p − q)), which corrects for what the draft over-proposed.
9 · Key takeaway

Key takeaway

Speculative decoding drafts γ tokens with a cheap model and verifies them in one target pass. A modified rejection rule keeps the output exactly the target's, and speedup ≈ (1 − α^(γ+1)) / ((1 − α)(γc + 1)).
Say it in 30 seconds

Decode is memory-bound: each step reads all the weights to make one token, so scoring several tokens costs about the same as scoring one. Speculative decoding lets a small draft model propose γ tokens, then the target model scores them all in one pass and accepts each with probability min(1, p/q), resampling from max(0, p − q) on the first rejection. The output distribution is exactly the target's. Expected tokens per pass is (1 − α^(γ+1))/(1 − α), and the papers reported 2–3× speedups.
