Activation memory and recomputation

Where activation memory comes from in a transformer, and how full, selective and √n checkpointing trade a little extra compute for a lot of memory.

What is the problem?Backward needs every intermediate activation of the forward pass; for long sequences and big batches those activations exceed the weights many times over.
Core ideaStore only some activations (checkpoints) and recompute the rest during backward. Checkpointing every √n layers needs about 2√n stored activations for one extra forward pass; selective recomputation drops just the cheap-to-recompute attention scores.
1 · Problem

Activations, not weights, fill the GPU

Memory for one GPT-3-scale layer's activations vs its weights as the sequence grows (micro-batch 1, BF16 (bfloat16, a 16-bit floating-point format with the exponent range of 32-bit floats)).

2 · Limitation

Why you can't just drop activations

Backward needs them

Each layer's gradient uses its inputs and intermediate values from the forward pass.

Offloading is slow

Copying activations to CPU (central processing unit) memory goes over PCIe (Peripheral Component Interconnect Express, the standard expansion bus), about 50× slower than HBM (high-bandwidth memory).

Smaller batches hurt

Shrinking the micro-batch reduces GPU (graphics processing unit) efficiency and, with pipelines, increases bubbles.

4 · Core idea

Three recomputation strategies

Full

Store only each transformer layer's input; recompute the whole layer in backward. Minimum memory, ~30% more time.

√n checkpointing

Store a checkpoint every √n layers: O(√n) memory for one extra forward (Chen et al.: 48 GB → 7 GB for 1,000 layers at +30%).

Selective

Recompute only the attention-score operations (large activations, few FLOPs (floating-point operations)). Korthikanti et al.: MFU (model floating-point-operation utilization, the share of peak compute spent on the model's math) 54.2% vs 42.1% with full recompute.

At a glance

Best k ≈ √L; cost ≈ one extra forward pass.

5 · How it works

Memory vs compute for a deep stack

A stack of L layers. Choose the checkpoint spacing k: stored activations L/k + k, recompute cost about one extra forward whenever k > 1.

5 · How it works

Worked example: activations for a GPT-3-scale model

96 layers, h = 12,288, 96 heads, sequence 2,048, micro-batch 1; per-layer activations s·b·h·(34 + 5as/h) bytes (Korthikanti et al.).

Worked example

  1. Per layer: 2.67 GiB; all 96 layers: 256 GiB, more than three 80 GB GPUs.
  2. Full recomputation (store only each layer's input, 2·s·b·h bytes): 4.5 GiB, at the cost of recomputing every layer.
  3. Selective (drop only the 5as/h attention part): 76 GiB, recomputing only cheap attention-score ops.
  4. With TP (tensor parallelism) = 8 and sequence parallelism on top: 9.6 GiB per GPU.
Selective recomputation plus sequence parallelism removes most activation memory for a few percent of compute.
6 · Why it works

Why recomputation is a good trade

GPUs have spare FLOPs

Memory, not compute, usually limits batch and sequence size; spending some FLOPs to save memory pays off.

Exact

Recomputed activations are identical (with the same dropout RNG (random number generator)), so gradients are unchanged.

Selective is nearly free

Attention scores are memory-heavy but compute-light, so recomputing just them costs little.

Composes with everything

Works with TP, SP (sequence parallelism), PP (pipeline parallelism) and FSDP (Fully Sharded Data Parallel); pipelines also store only stage-boundary activations with recompute.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Recomputation changes the gradients."

It reproduces the same values (with the same RNG state), so gradients are identical.

"Checkpointing doubles the training time."

It adds about one extra forward pass, roughly a third more compute for full recompute; selective recompute adds much less.

"FlashAttention makes recomputation unnecessary."

FlashAttention avoids storing the N×N score matrix; other activations (MLP (multilayer perceptron), LayerNorm) remain.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Activations ∝ sequence × batch × layers. Weights don't grow with them.
  • k ≈ √L. Memory ≈ 2√L stored activations.
  • Recompute what is cheap. Attention scores: big memory, few FLOPs.

⚠ Traps

  • Full recompute everywhere. ~30% slower; selective often suffices.
  • Forgetting the backward peak. A segment's activations are rebuilt during its backward.
  • Mixing checkpointing with RNG. Dropout masks must be reproduced exactly during recompute.

What does selective recomputation recompute and why?

Only the attention-score operations: they create large activations (the 5as/h term) but have few FLOPs, so recomputing them is cheap.

Why must dropout be handled carefully with recomputation?

The recomputed forward must use the same random mask; frameworks save and restore the RNG state.
9 · Key takeaway

Key takeaway

Activation memory scales with sequence, batch and depth; checkpointing (√n), full or selective recomputation trade a little compute for most of that memory.
Say it in 30 seconds
