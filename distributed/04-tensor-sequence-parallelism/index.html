Distributed Training · 04

Tensor and sequence parallelism

Split every weight matrix across the GPUs (graphics processing units) of a node (Megatron), and shard the activations that tensor parallelism alone would duplicate (sequence parallelism).

What is the problem?Some layers are too big for one GPU, and even sharded weights must be gathered whole to compute. Splitting the matrices themselves needs communication inside every layer.
Core ideaTensor parallelism: split the first matrix of each block by columns and the second by rows, so each GPU computes its share and one all-reduce per block combines them. Sequence parallelism: split the LayerNorm and dropout regions along the sequence, turning each all-reduce into a reduce-scatter + all-gather.
1 · Problem

Split the matrix, not the batch

One MLP (multilayer perceptron) block across t GPUs. Pick t: each GPU holds 1/t of each weight matrix and computes 1/t of the hidden units; partial outputs are summed with an all-reduce.

2 · Limitation

What data parallelism can't do

Layer too big

FSDP (Fully Sharded Data Parallel) still materializes each full layer on every GPU when it computes; giant layers and their activations may not fit.

Per-GPU work is fixed

DP (data parallelism) shortens the step only by splitting the batch, which grows the global batch.

Activations dominate

At long sequence lengths, activations per layer exceed the weights.

3 · Your turn

Where is the communication?

Pick an answer before moving on. Committing to a guess, even a wrong one, makes the real answer stick.

In a Megatron MLP (A split by columns, B split by rows), when do GPUs need to communicate in the forward pass?

B. Column-splitting A gives each GPU complete hidden units, so tanh/GELU (Gaussian Error Linear Unit) is local. Row-splitting B gives partial sums of the output, combined with one all-reduce. The backward pass needs one more, for the input gradient.
4 · Core idea

Megatron tensor parallelism, plus sequence parallelism

Attention

Split by heads: each GPU computes its heads (column-split Q, K, V), then the output projection is row-split and all-reduced.

MLP

First matrix column-split, second row-split: one all-reduce forward, one backward.

Sequence parallelism

The regions between blocks (LayerNorm, dropout) are split along the sequence; each all-reduce becomes a reduce-scatter + all-gather of the same total volume.

Selective recompute

Recompute only the attention-score part (large memory, few FLOPs (floating-point operations)) in backward instead of whole layers.

At a glance

One all-reduce per block forward, one backward; with sequence parallelism, reduce-scatter + all-gather instead.

5 · How it works

Activation memory per layer vs strategy

GPT-3-scale layer (h = 12,288, 96 heads, micro-batch 1). Move the sequence length and tensor-parallel degree.

Formula from Korthikanti et al.: s·b·h·(34 + 5as/h) bytes per layer without parallelism. Tensor parallelism alone divides only the parts inside the attention and MLP blocks (the paper's 10 + 24/t + 5as/(ht) form); with sequence parallelism everything divides by t.

5 · How it works

Worked example: activation memory per layer (GPT-3 175B)

Korthikanti et al.: activations per layer = s·b·h·(34 + 5as/h) bytes, with s = 2,048, b = 1, h = 12,288, a = 96 heads.

Worked example

  1. 5as/h = 5 × 96 × 2,048 / 12,288 = 80 (the attention-score term).
  2. Per layer, no parallelism: 2,048 × 12,288 × (34 + 80) bytes = 2.67 GiB; × 96 layers = 256 GiB.
  3. Tensor + sequence parallelism over t = 8: ÷ 8 → 0.33 GiB per layer.
  4. Plus selective recomputation (drop the 5as/h part, recompute it): 34·sbh/8 = 0.10 GiB per layer.
The paper reports 5× less activation memory and MFU (model floating-point-operation utilization, the share of peak compute spent on the model's math) rising from 42.1% (full recompute) to 54.2% on a 530B model.
6 · Why it works

Why it works, and its limits

Exact

Splitting matrices and summing partials gives identical results; notebook 03 checks forward and backward against the unsplit layer.

Cuts per-GPU work and memory

Each GPU reads and computes 1/t of every layer, and with sequence parallelism stores 1/t of the activations.

Communication every layer

Four collectives per layer per step (two forward, two backward); only NVLink makes them cheap.

Bounded by the node

TP (tensor parallelism) scales to the NVLink domain (8 GPUs on HGX, up to 72 on NVL72); beyond that use PP (pipeline parallelism), CP (context parallelism) and DP.

7 · Misconceptions

Common misconceptions

Each statement below is a mental model people often get wrong. Decide why it is wrong, then reveal.

"Tensor parallelism is just model sharding like FSDP."

FSDP gathers whole layers and each GPU computes all of a layer on its own data; TP keeps layers split and each GPU computes part of every layer on the same data.

"Sequence parallelism adds communication."

It replaces each all-reduce with a reduce-scatter + all-gather of the same total volume, while sharding activations.

"Bigger t is always better."

Communication grows and per-GPU matmuls shrink; past the NVLink domain it slows down.
7 · Tricks and traps

Tricks and traps

Rules of thumb that make this topic quick to reason about, and the mistakes people most often make with it.

✓ Tricks

  • Column then row. The nonlinearity stays local; one all-reduce per block.
  • Two all-reduces per layer forward. One after attention, one after the MLP; two more in backward.
  • TP ≤ GPUs per NVLink domain. Usually TP = 8 on HGX servers.

⚠ Traps

  • TP across nodes. Per-layer all-reduces over the network dominate step time.
  • TP > KV (key-value) heads. K/V heads get replicated (GQA (grouped-query attention) models).
  • Forgetting replicated activations. Plain TP keeps LayerNorm/dropout inputs on every GPU; sequence parallelism shards them.

Check yourself

How many all-reduces does one transformer layer need in the forward pass with Megatron TP?

2: one after attention, one after the MLP.

What does sequence parallelism shard that plain TP replicates?

Activations in the LayerNorm and dropout regions between the attention and MLP blocks, split along the sequence dimension.

What does selective recomputation recompute?

Only the attention-score operations (QKᵀ, softmax, dropout, attention over V): large activations, few FLOPs.
9 · Key takeaway

Key takeaway

Tensor parallelism splits every matrix inside a node with one all-reduce per block; sequence parallelism and selective recompute shard and shrink the activations.
Say it in 30 seconds

When a layer or its activations are too big, split the matrices themselves. Megatron splits the first matrix of each block by columns and the second by rows, so each GPU computes its share of the hidden units and an all-reduce sums the partial outputs, once per block in the forward pass and once in backward. That communication happens in every layer, so tensor parallelism stays inside the fast NVLink domain. Sequence parallelism also shards the activations between blocks along the sequence, and selective recomputation drops only the cheap but huge attention-score activations, cutting activation memory about five times.

Problem: layers and activations too big; FSDP still computes whole layers.
Core idea: column-then-row splits, one all-reduce per block; sequence-parallel activations.
Placement: inside the NVLink domain (TP ≈ 8).
